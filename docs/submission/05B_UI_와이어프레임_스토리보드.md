## 1. 화면 목록 — 고객과 운영은 **다른 앱**이다

```
:8080  고객 앱     app/static/insurance.html + insurance.js
:8081  운영 앱     app/static/admin.html     + admin.js
```

★한 프로세스로 합치지 않았다. `app/main.py` 가 role 에 따라 라우터를 다르게 싣는다 —
**고객 앱에는 `/api/admin/*` 이 아예 없고 `/static/admin.html` 도 404 다.**
무인증 노출·DoS 표면을 줄이려고 일부러 갈라 놓은 것이다.

| 화면 | 포트 | 담는 것 |
|---|---|---|
| 보험정보 입력 | 8080 | 보험사 · 가입일 · 질병기호 · 동의 |
| 보장 확인 상세 | 8080 | 판정 · 근거 조항 · 적용 약관 · 코호트 |
| AI 보험 상담 | 8080 | 용어 설명(약관 원문 인용) · 근거 밖이면 기권 |
| 실제 청구 결과 제보 | 8080 | 외부 사례 수집(★판정 근거 아님 — 통계 전용) |
| 운영 대시보드 | 8081 | release · 인덱스 · 검수 큐 · 지식갭 |

## 3. 와이어프레임 — ★되묻기와 기권

이 화면이 **이 프로젝트의 핵심 설계**다. 나머지는 이걸 위해 있다.

```
┌─ 전문가 확인 필요 ───────────────────────────────────────┐
│                                                          │
│  일반 실손 · 노후실손 · 유병력자실손 중                    │
│  어느 상품인지 알려주세요. 상품에 따라 자기부담금이 다릅니다.│
│                                                          │
│  ★ 근거 조항을 대지 못해 판정하지 않았습니다.              │
│    오류가 아닙니다 — 추측으로 "보장됩니다"라고               │
│    말하지 않기 위한 정상 동작입니다.        (HTTP 200)     │
│                                                          │
│  후보 약관 — 어느 것인지 특정하지 못했습니다               │
│  ★고르지 않으면 판정하지 않습니다                          │
│    아무거나 골라 답하면 다른 약관의 조항을 근거로 대게 됩니다.│
│                                                          │
│   ○ 무배당 삼성화재 다이렉트 실손의료비보험(1904.3)        │
│       20190401 · 3세대                                    │
│   ○ (착한실손)무배당 삼성화재 노후실손의료비보험(1904.8)   │
│       20190401                                            │
│   ○ 무배당 삼성화재 유병력자 실손의료비보험(1904.3)        │
│       20190401                                            │
│                                                          │
│  규칙엔진 rules-2026.08.02 · 추적 e6f2628906d44308        │
└──────────────────────────────────────────────────────────┘
```

**설계 의도**

- **기권은 오류가 아니다.** HTTP **200** 으로 나간다. 화면이 그 문장을 직접 적는다.
- 후보를 **감추지 않는다.** 못 고른 이유를 함께 적는다.
- **추적 ID 를 화면에 노출한다.** "왜 그때 그렇게 답했나"를 나중에 재현할 수 있어야 한다.

## 5. ★화면 상태표 — 어떤 상태에서 무엇이 보이나

`Verdict` 4단 × `abstained` 는 코드가 정본이다
(`app/core/domain/insurance.py:60` · `app/core/domain/precheck_result.py:44`).

| `verdict` | `abstained` | 대표 `reason_code` | 화면 | HTTP |
|---|:---:|---|---|:---:|
| `likely_covered` | false | `covered_by_clause` | 보장 근거 조항 + 조건 | 200 |
| `unlikely` | false | `excluded_by_clause` | 면책 조항 + ★"확정 아님" 문구 | 200 |
| `needs_documents` | false | `exception_applies` | 조건부 + **무엇을 더 확인해야 하나** | 200 |
| `needs_expert` | **true** | `ambiguous_product` | ★**후보 제시 · 되묻기**(§3) | 200 |
| `needs_expert` | **true** | `documents_not_confirmed` | "보유는 하지만 아직 확정 전" | 200 |
| `needs_expert` | **true** | `no_evidence` | "근거를 못 찾음 ≠ 보장됨" | 200 |
| `needs_expert` | **true** | `citation_unverified` | 근거를 댔지만 우리 것이 아님 | 200 |
| `needs_expert` | **true** | `ambiguous_citation` | 어느 조항인지 특정 불가 | 200 |
| — | — | `insurer_not_supported` | "보유하고 있지 않습니다" | 200 |
| (장애) | — | — | `ConfigError`·`InfraError`·`LLMOutputError` | **5xx** |

★**`documents_not_confirmed` 와 `insurer_not_supported` 를 반드시 가른다.**
1,367건을 갖고 있는데 "없습니다"라고 답하면 사실을 잘못 전하는 것이고,
사용자가 할 일도 다르다 — 전자는 기다리면 되고 후자는 다른 곳을 찾아야 한다.

★**기권(200)과 장애(5xx)를 화면에서 다르게 그린다.** 기권을 오류 화면으로 그리면
사용자는 "고장났다"로 읽고 다시 시도한다.

## 6. 에이전트 트랙 — 같은 판정을 JSON 으로

사람 화면과 **같은 유스케이스**가 REST/MCP 로도 나간다. 화면만 있는 기능은 없다.

```jsonc
// POST /v1/prechecks
{ "insurer": "삼성화재", "enrolled_on": "20190501",
  "kcd_codes": ["K02.1"], "product_name": null,
  "client_ref": "agent-a1" }
```

```jsonc
// 200 — ★기권도 200 이다
{ "schema_version": "...",
  "verdict": "needs_expert",
  "abstained": true,                      // ← 화면 §3 이 그리는 상태
  "reason_code": "ambiguous_product",
  "message": "일반 실손·노후실손·유병력자실손 중 …",
  "applied_policy": null,
  "candidates": [                          // ← 되묻기용 후보
    { "insurer": "삼성화재",
      "product_name": "무배당 삼성화재 다이렉트 실손의료비보험(1904.3)",
      "sale_start": "20190401", "generation": 3,
      "generation_label": "3세대 (착한실손)",
      "date_confidence": "exact", "parse_status": "ok" }
  ],
  "per_code": [], "citations": [],
  "rule_engine_version": "rules-2026.08.02",
  "extractor": "pymupdf/1.28.0",
  "trace_id": "e6f2628906d44308",         // ← 화면 하단과 같은 값
  "warnings": [] }
```

**필드가 화면의 어느 자리에 대응하나**

| JSON | 화면 |
|---|---|
| `abstained: true` | "★근거 조항을 대지 못해 판정하지 않았습니다" 배너 |
| `candidates[]` | 후보 라디오 목록 |
| `applied_policy` | 「어느 약관으로 봤나」 블록 |
| `citations[].clause_id` · `page_from/to` | 근거 카드의 `{sha12}/{부}/{조}` · `p56–68` |
| `citations[].tier` | ★`POLICY_CLAUSE` 만 판정 근거. `EXTERNAL_REPORT`·`STATISTICS` 는 참고용 |
| `warnings[]` | 판정에 못 쓴 근거 — **조용히 버리지 않는다** |
| `trace_id` | 화면 하단 "추적 e6f2…" |

★`ExternalCaseSubmission`(제보)은 **판정 근거가 아니다.** `verification: "unverified"` 가 기본이고
검증 없이 통계에 들어가지 않는다. 약관 조항과 **같은 인덱스에 넣지 않는다.**

| 4 | `04_판정_근거조항.png` | 판정 + 근거 5건 | 조 번호·부·쪽·문서 SHA 가 실제로 붙는다. 확정률 경고가 판정 위에 있다 |
| 5 | `05_용어설명.png` | 용어 설명(본인부담금) | 약관 원문에서 정의를 찾아 인용. ★"뜻만 설명하고 보장은 판정하지 않는다" 경고 포함 |
| 6 | `06_운영화면.png` | 관리자 로그인 게이트 | 고객/운영 물리 분리. 관리자 승격은 **CLI 전용 · UI 버튼 없음** |

> 캡처에서 **약관 인용 본문만 가렸다**(저작물). `［약관 원문 272자］` 로 대체했고
> **조항 ID·약관명·페이지는 그대로 뒀다** — 인용이 동작한다는 증거는 거기에 있다.

### ★이 스토리보드가 증명하지 **못하는** 것

발표에서 이 네 줄을 빼지 않는다.

1. **관리자 대시보드 안쪽은 못 찍었다.** 로그인이 필요한데 자격증명을 대신 입력하지 않았다.
   컷6 이 증명하는 것은 **「잠겨 있다」까지**이고, 대시보드가 데이터를 옳게 그리는지는 미확인이다.
2. **코호트 통계는 빈 값이다.** 동작 불량이 아니라 **제보 콜드스타트**(최소 표본 30 미달)다.
   화면이 「사례 없음」이라고 정직하게 적는다.
3. **한 흐름(삼성화재·K02.1)뿐이다.** 같은 점검에서 `M51.2`(현대해상)·`J20.9`(흥국화재)는
   **근거를 못 찾아 기권**했다(`no_evidence`) — 면책에 없다는 뜻이지 보장된다는 뜻이 아니다.
4. **확정 850건은 기계 대조까지다.** 사람 최종 승인은 **0건**.
   엄격 모드(`config/precheck_mode.json` → `human_signoff`)로 바꾸면 판정 가능 약관은 **0건**이 된다.

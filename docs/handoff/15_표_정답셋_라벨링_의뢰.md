## 0. 왜 이게 지금 필요한가

표 추출이 **"생성 완료 · 품질 검증 미완료"** 에 멈춰 있다.
멈춘 이유가 기술이 아니라 **잴 자가 없어서**다.

```
조항에 실린 표      916개 (레코드 12,561)   ← 「선」 경로만
보류 (미검증)      162,170개              ← 「2열짝짓기」 전량
정답셋              표 3개 · 레코드 22개    ← data/eval/table_gold.json
판별 게이트 근거     참 4건 · 거짓 3건       ← ★이게 문제다
```

지금 과탐 판별기는 **참 4 · 거짓 3** 으로 맞춘 임계값 하나(`T1 통로무결성 0.052`)에 걸려 있다.
이 표본으로 정직하게 말할 수 있는 건 *"명백한 오탐을 거른다"* 까지다.

★**보류 162,170개가 판정에 못 들어가고 있다.** 그중 진짜 표가 얼마나 되는지 아무도 모른다.
보장한도·자기부담금이 그 안에 있다.

## 1. 무엇을 부탁하나 — 둘

| | 무엇 | 목표 | 왜 |
|---|---|---|---|
| **A** | **알려진 참/거짓 집합 확장** | 각 **20~30건** | 판별기를 맞출 재료. ★**싸고 즉시 쓰인다** |
| **B** | **층화 정답셋 라벨링** | 층당 3표 = **~72건** | 품질을 *숫자로* 말하기 위한 것 |

**A 를 먼저 해 주면 좋겠다.** B 없이도 판별기 개선이 바로 돌아간다.

---

## 2. A · 알려진 참/거짓 집합 (먼저)

### 지금 손에 있는 것

```
참(4)   용어정의표 DB 02aaee47b190 p53 · 자기부담금 표 …
거짓(3) '6.' | '응급환자의 이송 등…'            ← 6·7·8행에 같은 값 반복
        '보험금 ④ 회사는' | '늦어지는 경우…'
        '실손의료비보험은 에 한정합니다)를'
        | '보험회사가 피보험자의 질병 또는 손해(의료비 회사가 보상하는 상품입니다.'
                                              ← ★한 문장을 두 열로 쪼개며 어절이 뒤섞였다
```

### 부탁

**각 20~30건까지** 채워 주면 된다. 판별기가 배울 대상이라 **극단적인 예**가 값어치가 크다.

- **참**으로 넣을 것 — 진짜 격자 표. 특히 **질병분류표 · 장해분류표 · 자기부담금표 · 용어정의표**
- **거짓**으로 넣을 것 — **본문 두 단 조판**이 표로 잡힌 것. 위 3건이 전형이다
- ★**애매하면 넣지 말고 `unsure`** 로 빼 주세요. 애매한 것으로 임계값을 맞추면 둘 다 망가진다

### 형식

`data/eval/table_gold.json` 과 같은 자리에 `table_true_false.json` 으로 주시면 됩니다.

```jsonc
{"true": [{"sha12":"02aaee47b190","page":53,"why":"용어정의표 · 격자 뚜렷"}],
 "false":[{"sha12":"…","page":34,"why":"본문 2단. 한 문장이 두 열로 쪼개짐"}]}
```

`why` 한 줄이 중요합니다 — 나중에 임계값이 흔들릴 때 **왜 그렇게 정했는지**가 근거가 됩니다.

## 3. B · 층화 정답셋 라벨링

### 후보는 이미 뽑힌다

```bash
python -m scripts.eval.build_table_labelset --per-stratum 3
```

```
층화 기준   (보험사 12) × (복원 방식 2: 선 · 2열짝짓기)
출력        data/eval/table_labelset_candidates.jsonl
뽑기        시드 고정 — 재실행해도 같은 표가 나온다(라벨이 무효가 되지 않는다)
```

> ★**조판 세대는 층에 안 넣었다.** 넣으면 층당 표본이 1개도 안 남는다.
> 도구 주석에 그렇게 적혀 있으니, *"층화했다"* 를 조판까지 덮은 것으로 읽지 말아 주세요.

### 찍는 방법 — **백지에서 타이핑하지 않는다**

각 줄에 추출 결과가 들어 있습니다. 셋 중 하나만 찍어 주세요.

| `label` | 뜻 |
|---|---|
| `table` | 진짜 표다 |
| `prose` | 본문인데 표로 잡혔다 (과탐) |
| `unsure` | 모르겠다 ← ★**억지로 고르지 마세요** |

- 셀 **값**이 틀린 경우에만 `fix` 에 고쳐 주세요. 값이 맞으면 비워 두면 됩니다
- `note` 는 선택입니다

### ★기대 결과를 미리 적어 둡니다

지금 정답셋 도달률이 **1.000** 인데, **이건 흥국화재 한 조판만 맞춘 값**입니다.

> **1.000 이 떨어지는 것이 정상입니다. 안 떨어지면 표본을 의심해야 합니다.**

떨어졌다고 나빠진 게 아닙니다 — **처음으로 제대로 재는 것**입니다.

## 4. 이 라벨이 어디에 쓰이나

```
A 참/거짓  →  T1~T5 신호 임계값 재조정 (scripts/extract/table_signals.py)
              → 보류 162,170개 중 진짜 표를 살린다
B 층화     →  층별 precision/recall 표
              → 층 하나라도 0.9 미만이면 그 층은 "미검증"으로 판정에서 뺀다
```

두 번째가 중요합니다. **전체 평균이 좋아도 특정 보험사에서 무너지면 그 보험사 가입자가 손해를 봅니다.**
그래서 평균이 아니라 **층별 최악**을 봅니다.

---

## 5. 규모와 한계 — 정직하게

- 층당 3표는 **적습니다.** rule of three 로 층별 *"오류율 63% 미만"* 까지밖에 못 말합니다
- 그래도 하는 이유 — ★**층이 무너지는 곳은 3표로도 드러납니다.** 비율 추정이 아니라
  **붕괴 탐지**가 목적입니다
- A(참/거짓)는 통계가 아니라 **판별기 재료**라 20~30건이면 충분합니다

## 7. 부탁드리는 순서

```
1. A 참/거짓 20~30건        ← 먼저. 이것만으로 판별기가 돈다
2. B 후보 생성 + 라벨링      ← python -m scripts.eval.build_table_labelset --per-stratum 3
3. 결과 주시면 임계값 재조정 → 보류 해제 여부 판단
```

막히거나 형식이 애매하면 말씀해 주세요. **`unsure` 가 많은 것은 실패가 아닙니다** —
그게 많다는 사실 자체가 "지금 추출이 애매한 것을 많이 만든다"는 측정값입니다.

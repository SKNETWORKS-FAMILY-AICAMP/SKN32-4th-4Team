담당 **최연우** · 버전 v2 · 2026-08-24

## 0. 당신이 만드는 것

판정 결과를 **오해 없이** 보여 주는 화면.

이 프로젝트에서 화면은 장식이 아니다. **`needs_expert` 를 "보장 안 됨"으로 읽히게 만들면
그 자체가 사고**다.

---

## 1. 화면 상태표 — 이대로 만든다

| `verdict` | 표시 | 색 | 문구 |
|---|---|---|---|
| `unlikely` | **면책 가능성** | 빨강 | "면책 조항에 해당할 가능성이 있습니다. 아래 근거를 확인하세요" |
| `needs_documents` | **조건부 확인 필요** | 주황 | "조건에 따라 보장될 수 있습니다. 아래 조건을 확인하세요" |
| `likely_covered` | **보장 가능** | 초록 | "보장 조항에 해당할 가능성이 있습니다. 실제 지급은 보험사가 결정합니다" |
| `needs_expert` | **확인 불가** | 회색 | "약관에서 근거를 찾지 못했습니다. 보장 여부를 판단할 수 없습니다" |

★**라벨과 문구의 확신도를 맞춘다.** enum 이 `likely_`·`unlikely` 로 **가능성**을 말하는데
문구가 "해당합니다"로 **단정**하면 사용자는 확정으로 읽는다.
이 서비스는 지급을 결정하지 않는다 — 보험사가 한다.

### ★절대 하면 안 되는 것

- `needs_expert` 를 **"보장 안 됨"으로 표시** — 전혀 다른 뜻이다
- `needs_documents` 를 **"보장"으로 표시** — 조건이 있다
- 면책 목록에 없다는 것을 **"보장됩니다"로 표시**
- ★**어느 값도 "지급된다 / 지급되지 않는다"로 단정 표시** — 우리는 사전검토이지 지급 결정이 아니다

## 2. 되묻기 화면

`reason_code` 가 이 셋이면 **후보를 보여 주고 고르게 한다.**

| `reason_code` | 화면 |
|---|---|
| `ambiguous_product_line` | "일반 실손 / 노후실손 / 유병력자실손 중 무엇인가요?" — `candidates` 를 카드로 |
| `ambiguous_product` | "상품을 골라 주세요" — `candidates` 목록 |
| `insurer_not_supported` | "아직 이 보험사 약관을 보유하고 있지 않습니다" + 지원 목록 링크 |
| `no_version_at_date` | "그 시점 약관을 못 찾았습니다" + 보유 기간 표시 |

## 3. 근거 사슬 화면 — **이 프로젝트의 핵심 화면**

판정 옆에 **왜 그렇게 판단했는지**가 반드시 붙는다.

```
[면책]  F32 (우울증)
  └ 적용 약관: DB손해보험 · 3세대(착한실손) · 2020-01-01 판매
  └ 근거: 보통약관 4.1 (보상하지 않는 사항) · 33~38쪽
      "…정신 및 행동장애(F04∼F99). 다만, F04∼F09, F20∼F29 …는 보상합니다"
  └ [원문 보기]
```

### 필수 요소

- **적용 약관**(보험사·세대·판매시점) — 무엇으로 판단했는지
- **조항 번호와 쪽수** — 사용자가 원문을 찾아갈 수 있게
- **인용문** — 실제 그 문장

## 4. 경고 표시

`warnings` 배열이 비어 있지 않으면 **반드시 보여 준다.**

```
⚠ 판매시점을 월까지만 확인했습니다. 경계 시점이면 세대가 다를 수 있습니다.
```

조용히 숨기면 안 된다.

## 4-2. ★참고 조항 — `related_clauses` (2026-08-25 추가)

`PrecheckResult` 에 필드 둘이 늘었다. **근거와 같은 목록에 그리면 안 된다.**

| 필드 | 무엇 |
|---|---|
| `citations` | 질병기호가 **실제로 적힌** 조항. 판정을 만든 근거. `tier="policy_clause"` |
| `related_clauses` | 의미검색이 「읽어 볼 만하다」고 고른 조항. **판정 근거가 아니다.** `tier="retrieved_clause"` |
| `related_search` | `""`=안 함 · `"ok"` · `"failed: ..."` |

### 왜 나눠 놨나

`citations` 는 정규식 범위 대조로 나온다 — 결정적이고 재현된다.
`related_clauses` 는 벡터 거리로 나온다 — **비슷하다는 것은 근거가 아니다.**
한 목록에 그리면 화면이 둘을 같은 무게로 보여 주고, 백엔드에서 나눈 것이
화면에서 도로 합쳐진다. 사용자에게는 **화면이 곧 계약이다.**

### 그리는 법 (`app/static/insurance.js` 에 구현돼 있다 — 참고)

- 제목을 다르게 — 「참고 조항 — 판정 근거가 아닙니다」
- 「비슷하다는 것은 근거가 아니므로 위 판정에는 쓰이지 않았습니다」를 **매번** 붙인다
- 테두리를 **실선(근거) / 점선(참고)** 으로 가른다
  ★색이 아니라 **선 모양**으로 가른다 — 색만 바꾸면 흑백 출력·색각이상에서 구분이 사라진다

### `related_search` 세 상태를 화면에서도 가른다

| 값 | 화면 |
|---|---|
| `""` (스위치 꺼짐) | 아무것도 안 그린다 |
| `"ok"` · 0건 | 아무것도 안 그린다 — **없는 참고를 지어내지 않는다** |
| `"failed: ..."` | 「참고 조항을 보여 드리지 못했습니다(검색 오류)」 + 「판정은 영향받지 않았습니다」 |

★실패를 조용한 빈 화면으로 만들면 사용자는 「관련 조항이 없구나」라고 읽는다. **다른 말이다.**

## 5. 참고 사례 (나중에)

외부 에이전트가 준 사례는 **판정 근거와 다른 구역**에 둔다.

```
─────────── 판정 근거 (약관) ───────────
  보통약관 4.1 …

─────────── 참고 사례 (검증 전) ─────────
  ⚠ 아래는 다른 이용자의 보고이며 약관 근거가 아닙니다
```

**같은 목록에 섞지 않는다.**

---

## 6. 확인 방법

백엔드·테스트 통과만으로 "완료"라 하지 않는다. **매 단계 실제로 열어서 본다.**

```bash
python -m scripts.run_customer_server
# http://127.0.0.1:8080/ 에서 실제 판정 요청 → 상태·근거·경고 확인
# 마이페이지는 http://127.0.0.1:8080/static/mypage.html

python -m scripts.run_admin_server
# http://127.0.0.1:8081/ 에서 운영 화면 확인
```

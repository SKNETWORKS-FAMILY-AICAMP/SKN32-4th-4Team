## 0. 당신이 만드는 것

근거 묶음을 받아 **판정하고, 사람이 읽을 설명을 쓴다.**
그리고 그 설명이 **근거를 벗어나지 않았는지 검사**한다.

## 2. 지켜야 할 경계

| 하면 안 되는 것 | 왜 |
|---|---|
| **`not_mentioned` 를 `likely_covered` 로 올리기** | 면책 목록에 없다 ≠ 보장된다. 보장은 '보상하는 사항' 조항이 정한다 |
| 근거에 없는 조항 인용 | `citation_guard` 가 걸러 내지만, 애초에 만들지 않는다 |
| 근거를 넘어선 추론 | 조항에 "우울증"이 없는데 "정신과 질환이니 비슷하게…"는 금지 |
| 기권을 부끄러워하기 | **`needs_expert` 는 정상 결과다.** 억지로 판정하면 사람이 손해를 본다 |
| 자유 텍스트만 반환 | 구조화 출력이어야 검증할 수 있다 |
| **`citation_eligible == false` 조항을 근거로 쓰기** | 조 경계가 모순인 조항이다. 아래 참조 |
| **부록 내용을 조 이름으로 인용하기** | 질병분류표를 `제27조(준용규정)` 이라 부르면 **출처가 틀린다** |

### `citation_eligible` — 두 번째 관문

`parse_status` 는 **문서**가 파싱됐나를 묻고, `citation_eligible` 은 **조항**을 인용해도 되나를 묻는다.
축이 다르다. AI 1 이 걸러 주지만 판정에서도 확인한다 — 근거는 두 번 검사해도 손해가 없다.

실측(s6 전량): `parse_status == "ok"` 조항 196,361개 중 인용 가능 **188,834(96.17%)**,
그중 「보상하지 않는 사항」 조항 **2,541 / 3,185**.

### 부록은 조가 아니라 **부록으로** 인용한다

`별표`·`붙임`·`장해분류표`·`특정질병 분류표` 는 `annexes[]` 에 따로 있다 —
KCD 코드 대조는 대부분 **여기서** 나온다.

- 좋은 인용: `[별표1] 특정질병 분류표` · `장해분류표`  ← `annex["label"]`
- 나쁜 인용: `제27조(준용규정)` ← 부록을 삼킨 조 이름. 내용은 맞아도 **출처가 틀렸다**

`owner_clause_ordinal` 은 항상 `None` 이다. "이 별표는 제9조 것" 이라고 **추정하지 않는다**(§0).

## 3. ★인용 검증 — 이미 만들어져 있다

```python
from app.core.domain.citation_guard import EvidenceClause, verify

r = verify(
    cited_clauses=llm_output.cited_clauses,   # LLM 이 인용했다고 한 것
    evidence=[EvidenceClause(qualified_no=c.qualified_no, text=c.text)
              for c in bundle.clauses],
    answer_text=llm_output.reason,
    quotes=llm_output.quotes,
)
if not r.ok:
    # ★답을 버리고 기권한다. 재시도는 1회까지.
    return abstain(ReasonCode.CITATION_UNVERIFIED, r.reason)
```

| 검사 | 위반 시 |
|---|---|
| 인용 조항이 근거에 실재하는가 | **폐기** |
| 본문에서 `제N조` 를 말했는데 선언 안 했는가 | 경고 |
| 인용문이 조항 원문의 실제 일부인가 | 경고 |

**프롬프트로 "추측하지 마라"라고 적는 것만으로는 부족하다.**
그건 지켜지길 바라는 것이고, 이 검사는 강제된다.

## 4. LLM 출력 형식 (강제)

```json
{
  "verdict": "likely_covered | unlikely | needs_documents | needs_expert",
  "abstained": true,
  "cited_clauses": ["보통약관/제9조", "특별약관/제3조"],
  "quotes": { "보통약관/제9조": "실제 원문에서 따온 문장" },
  "reason": "사람이 읽을 설명"
}
```

`cited_clauses` 가 비어 있으면 `likely_covered`/`unlikely` 를 낼 수 없다.

★**기권 여부는 `verdict` 가 아니라 별도 필드 `abstained: bool` 로 나간다.**
`verdict` 만 보고 판단하지 않는다.

## 5. 모델 평가 지표 — 이걸로 모델을 고른다

| 지표 | 방향 |
|---|---|
| **인용 정합률** — 인용한 조항 중 근거에 실재하는 비율 | 높을수록 |
| **근거 초과율** — 근거에 없는 내용을 답에 넣은 비율 | 낮을수록 |
| **적절한 기권율** — 근거 부족 시 `needs_expert` 를 낸 비율 | 높을수록 |
| **과잉 기권율** — 근거 충분한데 `needs_expert` 를 낸 비율 | 낮을수록 |
| **스키마 준수율** — 구조화 출력을 형식대로 낸 비율 | 높을수록 |

> "지시를 잘 따르는 모델인가"보다 **"구조화 출력을 안정적으로 내는가"** 가 중요하다.
> 그게 코드로 검증 가능한 형태이기 때문이다.

## 6. 이미 있는 것

```python
from app.core.domain import kcd_ranges as kcd
from app.core.usecases import precheck

kcd.scan_clause(text)      # 조항에서 코드 범위 + 면책/예외/불명
kcd.judge(code, mentions)  # excluded / exception / not_mentioned / invalid_code
precheck.run(req)          # 규칙 기반 전체 흐름(참고 구현)
```

`precheck.run()` 이 이미 규칙 판정을 한다. **당신이 채울 곳은 셋이다.**

1. **자기부담금 계산** — 세대별로 다르다. 조항의 표에서 뽑아야 한다
2. **한도·대기기간** — `needs_documents` 의 조건을 구체화
3. **설명문 + 인용 검증** — LLM 을 붙이는 곳

## 7. 골든 세트 (당신이 만든다)

20~30건. 각 건에 **기대 verdict 와 기대 인용 조항**을 적는다.

```yaml
- id: golden-001
  request: {insurer: DB손해보험, enrolled_on: "20200301", kcd_codes: [F32],
            product_name: "프로미라이프 실손의료비"}
  expect:
    verdict: needs_documents
    reason_code: exception_applies
    must_cite: ["보통약관/4.1"]
```

**반드시 넣을 실패 케이스:**
- 근거 없음 → `needs_expert` (`abstained=true`)
- 잘못된 조항 번호 인용 → 폐기
- 다른 버전 혼입 → 검출
- 면책 예외 누락 → 검출
- 표본 부족 → 통계 안 냄

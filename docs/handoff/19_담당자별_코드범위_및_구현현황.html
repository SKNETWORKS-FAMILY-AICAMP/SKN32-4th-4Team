비전공자용 60초 요약

이 프로젝트는 보험 약관을 대신 “추측”하는 챗봇이 아니다. 원문을 정리하고, 질문과 관련된 근거를 찾고, 정해진 규칙으로 판단한 뒤, 그 결과와 출처를 화면에 보여 주는 여러 단계의 협업 시스템이다. 어느 단계든 근거가 부족하면 자신 있게 답하는 대신 멈추거나 전문가 확인을 요청하는 것이 안전 원칙이다.

1. 데이터 수집·전처리 담당 합의 필요

비유: 책을 깨끗이 펴고 쪽수와 목차를 붙이는 사서

보험사 PDF를 모아 중복을 가리고, 글·표·쪽 위치를 찾을 수 있는 자료로 바꾼다. 사용자는 출처가 불분명한 복사본이 아니라 확인된 원문을 바탕으로 답을 받게 된다.

2. AI 검색 서유현

비유: 질문을 듣고 관련 약관 책장을 찾아오는 사서

많은 약관 중 질문과 관련된 조항 후보를 찾아 원문 위치와 함께 넘긴다. “보장된다”는 결론을 내리지는 않는다. 사용자는 어떤 조항을 근거로 삼았는지 확인할 수 있다.

3. AI 판정·설명 송채영

비유: 찾아온 서류를 규정표와 대조하는 심사 담당자

검색된 근거와 가입 조건을 정해진 규칙에 맞춰 비교하고 이유를 설명한다. 근거가 부족하면 “확인 필요”라고 답한다. 사용자는 근거 없는 확답으로 인한 오해를 줄일 수 있다.

4. 에이전트 정재희

비유: 담당 부서에 일을 순서대로 전달하는 교통정리 담당자

필요한 정보와 도구를 정해진 순서로 호출하고 실패하면 제한된 횟수만 다시 시도한다. 판정 결과를 마음대로 바꾸지는 않는다. 다른 AI도 프로그램 간 통로(API)를 통해 안전하게 요청할 수 있게 한다.

5. 백엔드 김지혜

비유: 신분을 확인하고 기록을 보관하는 안전금고와 접수창구

로그인·권한을 확인하고, 요청과 결과를 안전하게 저장하며, 화면과 외부 프로그램에 필요한 정보를 전달한다. 누가 무엇을 했는지 기록해 문제가 생기면 원인을 추적할 수 있다.

6. 프론트엔드 최연우

비유: 복잡한 심사 결과를 읽기 쉽게 보여 주는 안내판

사용자가 보험 정보를 입력하고 결과·근거·경고를 이해하도록 화면에 표시한다. 화면에서 판정을 새로 만들거나 불리한 경고를 숨기지 않는다. 사용자는 결과와 이유를 함께 볼 수 있다.

한 문장으로 정리: 데이터는 믿을 만한 재료를 만들고, 검색은 근거를 찾고, 판정은 규칙을 적용하고, 에이전트는 순서를 조정하고, 백엔드는 안전하게 보관·전달하며, 프론트엔드는 이를 정확히 보여 준다.

쉬운 용어사전

아래 영어는 개발팀의 작업표에 자주 나오지만, 뜻은 어렵지 않다.

fail-closed — 모르면 안전하게 멈추기
필요한 근거나 설정이 없을 때 임의로 통과시키지 않고 요청을 중단하는 방식이다. 고장 난 출입증으로 문이 열리지 않는 것과 같다.
readiness — 영업 시작 전 점검
서버가 켜졌다는 사실만 보지 않고, 승인 데이터·저장소·필수 설정까지 실제 응답 준비가 됐는지 확인하는 점검표다.
manifest — 데이터 포장 명세서
어떤 원본과 설정으로 어떤 결과를 만들었는지 목록과 전자 지문(hash)으로 남긴 영수증이다. 누군가 파일을 바꾸면 차이를 찾을 수 있다.
rerank — 검색 결과 다시 줄 세우기
처음 찾은 여러 조항을 질문과 더 가까운 순서로 한 번 더 정렬하는 단계다. 사서가 후보 책을 가져온 뒤 가장 관련 있는 책을 위에 놓는 것과 같다.
DSN — 데이터베이스 접속 주소 묶음
서버 주소·포트·데이터베이스 이름·접속 계정 등을 한데 적은 연결 정보다. 비밀번호가 포함될 수 있어 문서나 화면에 그대로 공개하면 안 된다.
serving — 지금 실제 답변에 쓰는 버전
시험용 후보가 아니라, 승인되어 현재 사용자 응답에 연결된 데이터나 모델을 뜻한다.
P·R·F1 — 검색 품질을 보는 세 숫자
P(정밀도)는 “찾아온 것 중 정답 비율”, R(재현율)은 “찾아야 할 정답을 놓치지 않은 비율”이다. F1은 두 값을 함께 균형 있게 보는 점수다.
mutation test — 일부러 고장 내 보는 안전시험
시험용 코드에 알려진 결함을 일부러 넣고 검사가 그 결함을 잡는지 확인한다. 검사가 단순히 초록불만 켜는 장식이 아닌지 검증하는 방법이다.

6. 저장소 안에서 대신 끝낼 수 없는 일

사람 판단 대기

  • 문서 종류별로 골고루 뽑은 D5 표본과 조항 시작·끝 위치의 정밀도(P)·재현율(R)·균형점수(F1) 정답표
  • 법률자료 114건·근거 240개의 자동 대조 이후, 법률 전문가의 최종 승인
  • 확정 문서 잔여 모호·불일치 건의 최종 선택
  • 자기부담금·장해지급률 후보의 원문 승인
  • 전체 품질검사(QA)·운영 버전 승인·데이터의 실명 책임자 지정

운영 비밀·인프라 대기

  • 보험/관리자 데이터베이스 접속 주소 묶음(INSURANCE_PG_DSN 등)
  • 운영 서버 원격 접속(SSH)·계정/권한·복제본과 원본의 차이 0 확인
  • 문제 발생 시 이전 버전으로 되돌리는 연습과 백업 복원 증거
  • 원격 에이전트의 인터넷 주소(DNS)·통신 암호화(TLS)·방화벽(WAF)·접속키 전달
  • 고성능 그래픽 장치(GPU)를 확보한 뒤, 학습에 쓰지 않은 시험셋과 “기존보다 나쁘지 않음” 평가 실행

남은 품질·승인 입력

  • D4는 S7 결과가 나오기 전에 품질 기준을 미리 등록하지 못한 절차상 결함이다. 이미 끝난 결과에 소급하지 않고 다음 세대부터 먼저 등록한다.
  • D5 문서 종류별 사람 표본·부록을 놓치지 않는 비율·조항 시작/끝 위치의 P·R·F1 확인
  • Qwen3-Embedding-4B 경량화(4bit) 모델의 현행 검색 순위 재측정과, 문서 표현이 증거보다 강하지 않은지 사람 검수
  • 실제 운영 DB 접속 정보로 엄격한 공개 전 검사, 원본/복제본 차이 0, 이전 버전 복귀 연습
  • 전처리·전체 품질검사·얼굴/음성 모델의 실명 책임자 합의

7. 인계받은 사람이 먼저 돌릴 검증

아래 명령은 개발자가 담당 범위가 깨지지 않았는지 자동으로 다시 확인할 때 쓴다. 실제 DB 접속 정보·GPU 장비·사람 정답표가 없으면 일부 검사가 “건너뜀(skip)” 또는 “중단”으로 끝나는 것이 정상이다. 실행하지 못한 검사를 성공했다고 보고하면 안 된다.

# 전처리 포장 명세서와 전·후 단계(S5↔S6)가 서로 맞는지 확인

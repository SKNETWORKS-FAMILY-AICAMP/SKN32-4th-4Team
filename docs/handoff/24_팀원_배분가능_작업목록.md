### ★★그리고 **기본 CI 가 segfault 로 끝난다** — 재현 확인

PG 를 띄우고 돌려도 **54~60% 구간에서 `exit 139`(SIGSEGV)** 로 죽는다. **2회 연속 재현**했다.

```
Windows fatal exception: access violation
  psycopg_pool/pool.py:611 worker → :627 _connect → psycopg/connection.py:109 connect
```

**죽는 스레드는 `transformers/core_model_loading.py:1185 _materialize_copy`** — 3회 모두 같다.
즉 **기본 CI 안에서 진짜 모델 가중치를 물질화하는 경로가 돈다**(`ml` 마커를 뺐는데도).

★★**원인을 한 번 틀렸다.** 처음엔 「psycopg 풀」이라고 썼는데 덤프의 **첫 스레드**를 읽은 것이었고,

## 9. ✅ 확인해서 **닫은 것** — 넘길 필요 없음

| 무엇 | 결과 |
|---|---|
| 본문 없는 발생이 인용 가능으로 표시돼 있나 | ★**아니다. 0건** — 게이트 결함 아님 |

```sql
-- 2026-08-25 실측
SELECT count(*) FROM policy_clause_occurrence o
LEFT JOIN policy_clause_content c ON c.content_hash = o.content_hash
WHERE o.index_generation='s6' AND c.content_hash IS NULL AND o.citation_eligible;
-- 0
```

`s6` 에서 `content` 행이 없는 발생은 **15,890건**(고유 해시 8,206 · `clause` 8,707 · `annex` 7,183)이고,
**전부 `citation_eligible = false`** 다. 인용 경로로는 새지 않는다.

다만 **부모 조항 복원이 안 되므로 검색에도 안 걸린다.** "적재됐다"와 "검색된다"는 다른 말이고,
`annex` 쪽이 특히 비어 있다 — 별표 적재 경로 점검은 남는다(사람 판단 아님 · 코드 작업).

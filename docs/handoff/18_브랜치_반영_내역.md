## 1. `feature-agent` (정재희)

### 가져온 것

#### ✅ `citation_guard` — 같은 경로 후보를 덮어쓰던 결함 (P0)

```python
by_path[_norm_space(e.qualified_no)] = e     # 덮어쓴다
by_path[_norm_space(e.qualified_no)].append(e)   # 고침
```

★**같은 파일 위쪽에 경고가 이미 있었다** —
「번호 색인은 **list** 다. dict 로 만들면 같은 번호의 다른 조항이 덮인다」.
그걸 적어 놓고 **바로 아래 줄에서** 같은 실수를 하고 있었다.

**무엇이 깨졌나** — 같은 `qualified_no` 가 여러 문서·여러 쪽에 실린다
(중복률 66% 코퍼스에서 드문 일이 아니다). 덮어쓰면 뒤에 온 것만 남아,
인용문이 **앞의 것에 있어도 못 찾는다** → `quote_mismatch`.
**근거가 있는데 없다고 말한다.**

- 반영: `app/core/domain/citation_guard.py`
- 시험: `tests/test_citation_guard.py` — 앞/뒤 후보 각각 찾는지 + 어디에도 없으면 사유가 남는지
- ★우리 구현은 후보가 여럿이면 **인용문이 실제로 든 것**을 고른다(브랜치보다 한 걸음 더)

### 안 가져온 것

| | 왜 |
|---|---|
| **그래프 전체** | ★브랜치 그래프는 `CitationRef.quote` 를 다시 `ClauseRow.text` 로 만들어 **자기 자신과 대조**한다(`precheck_graph.py:299~322`). 조작된 quote 를 저장소 원문으로 검증하지 못한다. 우리 정본은 `verify_against_store()` 로 원문을 재조회한다 |
| **MCP 서버 그대로** | 계약은 Streamable HTTP `/mcp` + `Authorization: Bearer` 인데 브랜치는 `mcp.run()` stdio 이고 **API 키를 도구 인자로 노출**한다 |
| **`audit_log.py` 그대로** | `except Exception: pass`(`:70~73`) — 감사 실패 신호가 사라진다. 무폴백 원칙과 정면 충돌 |
| 레이트리밋 | 프로세스별 메모리라 다중 worker 에서 한도를 우회할 수 있다 |

### 남은 검토

- MCP 도구 3개·리소스 2개의 **계약과 테스트 케이스**는 참고 가치가 있다 → 미착수
- 공통 조상 이후 양쪽이 함께 바꾼 경로가 **33개**다. 전체 merge 금지, 수동 이식만

## 2. `feature-ai1` (서유현)

### 가져온 것

#### ✅ s6 arctic-ko 임베딩 — **다시 만들어서** 반영

> ★★**전달물 파일은 인덱스에 한 조각도 안 들어갔다.**
> DB 의 조각 122,697 은 **전부 우리가 우리 `chunk_clause` 로 다시 만든 것**이다.
> 승인 프로필이 arctic-ko 인 것은 **같은 모델을 골랐다**는 뜻이지
> **그 파일을 넣었다**는 뜻이 아니다.
>
> 이 구분을 흐리면 "델리버리가 부분 통합돼 있다"로 읽히는데(실제로 그렇게 읽은
> 보고가 있었다 · 2026-08-04), 그러면 **어느 벡터가 무엇으로 만들어졌는지**를
> 아무도 대지 못하게 된다. 출처를 못 대는 근거는 쓸 수 없다(CLAUDE.md §0).

전달물 `s6_chunks_delivery.zip` 을 검수했고 **벡터는 진짜였다**(코사인 최소 0.999995).
그러나 그대로 쓰지 않았다.

| | 이유 |
|---|---|
| 스냅샷이 다르다 | 판정대상 62,148 중 벡터 있는 것 **54,540(87.8%)** — 7,608건 구멍 |
| 청킹 방식이 다르다 | 숫자(448/80)는 같지만 **토큰 고정 창** vs **문장 경계** |
| 차원이 안 맞는다 | 1024 vs `vector(768)` 고정 |

→ **우리 `chunk_clause` 로 다시 임베딩**(RunPod 22분 · 조각 122,697).
전달물은 **검증 기준**으로 남겼다 — 쪼개기가 개입 안 하는 조항에서
우리 벡터와 코사인 **0.999998**. 이게 파이프라인 동일성 검산이 됐다.

- 반영: `scripts/index/load_precomputed.py` · `config/accepted_extraction.json`
- 리포트: [인덱스A 적재와 두 경로 정합](../reports/2026-08-04_0100_인덱스A_적재와_두경로_정합_리포트.md)

### 안 가져온 것

| | 왜 |
|---|---|
| `embedding/`·`preprocessing/`·`core/` 전체 | 우리 `app/core`·`app/adapters`·`scripts/index` 와 **별도 아키텍처**. Chroma/FAISS·구 청킹·구 용어 RAG 가 중복된다 |
| `embed_s6_chunks.py` 그대로 | 모델·CUDA·입출력 경로가 하드코딩. revision·프로필 키·checksum 이 없다 |
| `build_chroma_s6.py` · `embed_s6_full.py` | ★**0바이트**다 |
| 브랜치의 `13_임베딩모델_선정_브리핑.md` | 우리 최신 브리핑보다 **앞선 판**이다 |

### 남은 검토

- ★`build_retrieval_set_s6.py` 의 **s6 dedup 조인·적격 필터·제목 누출 제거** —

## 7. 문서 확정 절차 (2026-08-04 신설)

판정은 `identification == "confirmed"` 인 문서만 쓴다. 그 확정을 **어디에 적을지**를 정했다.

| | |
|---|---|
| 원장 | `config/confirmed_documents.jsonl` (저장소 커밋 · 약관 원문 없음) |
| 도구 | `scripts/confirm/identify_documents.py` |
| 왜 매니페스트가 아닌가 | 매니페스트는 **수집 기록**이라 크롤러가 다시 쓴다. 같은 파일에 두면 **사람의 결정이 덮인다** |
| 원장이 덮는 것 | `identification`·`generation_review` **뿐**. 상품명·판매일은 매니페스트가 정본 |

```bash
python -m scripts.confirm.identify_documents --report            # 근거만 본다
python -m scripts.confirm.identify_documents --report --spread   # 보험사×세대 대표만
python -m scripts.confirm.identify_documents --apply --scope machine_verified --confirmed-by "이름"
```

현재 **132건**(수집 1,367 중 **9.7%**)이 확정돼 있다 — `scope` 로 갈린다:
`demo` 10 · `machine_verified` 122. `/v1/support-manifest` 와 화면이
그 분모·비율·범위별 건수·「사람 최종 승인 대기」를 **그대로 말한다.**

★★**부분 확정은 답을 조용히 바꾼다.** `resolve()` 의 「가입일 이전 가장 늦은 것」은
**확정된 것 중에서만** 가장 늦다. 확정을 10 → 132 로 늘리자 `NH농협생명 20180101` 의
적용 판본이 **2세대에서 3세대로** 옮겨졌다 — 원래 3세대였는데 안 보였던 것이다.
그때 판정 응답의 `warnings` 는 **비어 있었다.** 지금은 판본을 골랐을 때
확정 비율과 그 한계를 경고로 싣는다(`routers/precheck.create_precheck`).

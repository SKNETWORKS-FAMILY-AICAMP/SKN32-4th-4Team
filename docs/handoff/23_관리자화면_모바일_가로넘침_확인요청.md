# 관리자 화면 모바일 가로 넘침 — 확인 요청 · 프론트엔드 최연우

수신 **최연우(프론트엔드 · `app/static/admin.html/js` 주 소유)** · 공동 참고 **김지혜(공동 승인)**
작성: 2026-08-25 · 근거: [08_계약_프론트.md](08_계약_프론트.md) · [19_담당자별_코드범위_및_구현현황.html](19_담당자별_코드범위_및_구현현황.html)

> 한 줄 — **관리자 화면이 모바일(375px)에서 가로로 넘칩니다. `body`의 강제 최소 폭(1080px)만
> 우선 제거해 급한 부분(로그인 게이트)은 고쳤지만, 로그인 뒤 대시보드 본문은 2단 grid 레이아웃
> 자체가 좁은 화면을 가정하지 않아 여전히 넘칩니다. 이 이상은 화면 담당자의 설계 판단이
> 필요해서 코드를 더 건드리지 않았습니다.**

이 문서는 결함 신고가 아니라 **설계 의도 확인 요청**이다. 되돌리기 쉬운 최소 조치(미디어
쿼리 하나)는 이미 적용해 급한 부분을 줄였지만, 대시보드 전체를 반응형으로 만들지는 화면
담당자의 판단이 필요해서 임의로 진행하지 않았다.

---

## 1. 실측

별도 Claude 세션이 P1 브라우저 눈검사를 하며 발견했다(관련: [2026-08-25_1032 보고서](../reports/2026-08-25_1032_비장고_잔여작업_재점검과_문서현행화_보고.md) §7).

| 확인 | 결과 |
|---|---|
| 화면 | `http://127.0.0.1:8081/`(관리자 로그인 게이트) |
| 뷰포트 | 375×812 (모바일) |
| `document.documentElement.scrollWidth` | 1080 |
| `document.documentElement.clientWidth` | 375 |
| 넘치는 요소 | `<html>`, `<body>`, `nav.top-nav`, `.login-panel`, `.login-panel-inner`(1020px) |

같은 검사를 고객 화면(`insurance.html`, 8080)에 하면 `scrollWidth === clientWidth === 375`로
넘침이 없다 — 관리자 화면만 다르다.

## 2. 원인

[`app/static/admin.html:36`](../../app/static/admin.html)

```css
body {
  margin: 0;
  min-width: 1080px;   /* 미디어 쿼리 없이 최상위 적용 */
  ...
}
```

`@media (max-width: ...)` 같은 대체 규칙이 파일 안에 없다. 그래서 375px 화면에서도
`body`가 1080px로 강제되고 안의 `nav.top-nav`·`.login-panel-inner`까지 그 폭을 그대로
따라간다.

## 3. 확인이 필요한 이유

관리자 화면은 데이터 테이블·필터·검수 대기열이 많은 내부 운영 도구라 **데스크톱 전용이
의도된 설계일 가능성이 충분히 있다.** 다만 다음을 찾지 못해 단정할 수 없었다.

- `08_계약_프론트.md`나 `19_담당자별_코드범위_및_구현현황.html`에 "관리자 화면은 모바일
  미지원"이라고 명시된 곳이 없음
- `min-width: 1080px`가 의도적 하한선인지, 그냥 반응형 작업을 아직 안 한 것인지 커밋
  이력·주석에서 확인 못함

## 4. 이번에 적용한 최소 조치

담당자 확인이 오기 전까지 급한 부분만 되돌리기 쉬운 방식으로 줄여 뒀다.

```css
/* app/static/admin.html — @media print 바로 위 */
@media (max-width: 1079px) {
  body { min-width: 0; }
  .login-panel-inner { max-width: 100%; }
}
```

- 1080px 이상(기존 데스크톱)에는 이 규칙이 전혀 적용되지 않는다 — 데스크톱 레이아웃은
  손대지 않았다(1280px에서 재확인: `scrollWidth === clientWidth`, 변화 없음).
- **로그인 게이트 화면**(로그인 전)은 375px에서 넘침이 완전히 없어졌다(`scrollWidth 1080 → 375`).
- **로그인 후 대시보드 본문**은 `.dashboard-grid { grid-template-columns: minmax(0, 1.55fr)
  minmax(380px, 0.75fr) }`가 오른쪽 열에 최소 380px를 강제해서 여전히 넘친다
  (`scrollWidth 1080 → 513`, 375 대비 138px 남음). 이건 미디어 쿼리 하나로 안 없어지고
  grid를 좁은 화면에서 1열로 바꾸는 실제 레이아웃 변경이 필요해서 이번에는 건드리지 않았다.

## 5. 요청

둘 중 하나로 짧게 회신해 주시면 된다.

- **(A) 의도된 설계다** — 관리자는 데스크톱 전용으로 확정. 로그인 게이트만 넘치지 않게 한
  이번 최소 조치는 유지하되(부작용 없음), 대시보드 본문까지 반응형으로 만들 필요는 없다고
  `08_계약_프론트.md`에 한 줄 명시해 다음 검수에서 같은 항목이 다시 올라오지 않게 한다.
- **(B) 반응형이 필요하다** — `.dashboard-grid`를 좁은 화면에서 1열로 바꾸는 작업 범위를
  정해 주시면(전체 패널 / 핵심 패널만 등) 그에 맞게 별도로 작업한다.

```text
회신:
판단 (A/B):
근거 또는 참고:
(B라면) 범위:
```

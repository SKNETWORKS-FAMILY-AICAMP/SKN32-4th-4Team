화면이 실제로 무엇을 하는지 — 눌러서 찍은 것만 싣습니다. 캡처 2026-08-04 · 고객 :8080 · 운영 :8081

이 문서는 목업이 아닙니다. 실제로 뜬 서버에 붙어 Playwright 로 화면을 눌러 가며 찍었습니다. 안 되는 것도 같은 무게로 싣습니다 — 컷6 아래에 「증명하지 못한 것」을 따로 적었습니다.
★약관 원문은 캡처에서 가렸습니다. 원문은 저작물이라 data/extracted/·data/structured/ 를 커밋에서 막아 두었는데, docs/ 는 .gitignore 가 막지 않습니다. 그래서 찍는 단계에서 가립니다. 가린 것은 인용 본문뿐이고 조항 ID·약관명·페이지는 그대로 둡니다 — 인용이 동작한다는 증거는 거기에 있습니다.

보험사삼성화재
가입일20190501 (형식은 YYYYMMDD)
질병기호K02.1 치아우식증 — 상아질에 생긴 것

재현: POST /v1/prechecks · 규칙엔진 rules-2026.08.02 · 추출 pymupdf/1.28.0

컷 1 — 입력 동작
  • 보험사·가입일·질병기호를 받습니다.
  • ★상품명은 비워 둡니다. 화면이 상품을 지어내지 않습니다 — 사용자가 고른 경우에만 product_name 이 실립니다.
컷 2 — 사용자 확인 동작
  • 「입력한 질병코드가 제 진료 기록과 맞음을 확인했습니다」를 사용자가 체크해야 등록이 열립니다.
  • 질병기호가 틀리면 판정 전체가 틀립니다. 그 책임 경계를 화면에서 먼저 긋습니다.
컷 3 — 판정하지 않고 되묻는다 ★핵심

같은 시점에 상품이 셋이라 판정을 거부했습니다 (ambiguous_product_line · verdict=needs_expert). 화면 문구 그대로:

★근거 조항을 대지 못해 판정하지 않았습니다. 오류가 아닙니다 — 추측으로 “보장됩니다”라고 말하지 않기 위한 정상 동작입니다.
★고르지 않으면 판정하지 않습니다 — 아무거나 골라 답하면 다른 약관의 조항을 근거로 대게 됩니다.
  • 일반 실손 / 노후실손 / 유병력자실손 — 자기부담금이 달라 섞으면 답이 틀립니다.
  • HTTP 는 200 입니다. 기권은 실패가 아니라 정상 결과입니다.
컷 4 — 판본 확정 → 면책 대조 → 근거 인용 동작
  • 어느 약관으로 봤나를 먼저 밝힙니다 — 무배당 삼성화재 다이렉트 실손의료비보험(1904.3) · 판매 20190401~20190930 · 3세대(착한실손) · 날짜 신뢰도 exact · 추출 상태 ok.
  • 판정 조건부 확인 필요(exception_applies) — K02.1 이 치과치료 K00~K08 면책에 걸리되, 요양급여 해당 여부라는 조건이 남습니다. 「안 됩니다」로 단정하지 않습니다.
  • 근거 조항 5건에 각각 조항 ID·약관명·페이지가 붙습니다 (eb778fa68b56/보통약관/제4조#6dcb03bc · p56–68 등).
  • ★맨 위 경고: 확정된 약관은 1,367건 중 850건(62.2%) — 더 나중 판본이 미확정분에 있을 수 있음을 화면이 먼저 말합니다.

회색 점선 상자가 가려진 약관 원문입니다. 글자 수만 남겼습니다.

컷 5 — 용어 설명 동작
  • 「본인부담금」 정의 구절 1,070개 · 보험사 12곳에서 찾아 원문으로 인용합니다.
  • ★대화창은 보장 여부를 답하지 않습니다. 실제 응답: “보장 여부는 여기서 답하지 않습니다 … 위 판정 양식으로 안내해 드립니다.” 약관을 확정해야 근거를 댈 수 있기 때문입니다.
컷 6 — 운영 화면은 잠겨 있다 동작
  • 고객(8080)과 운영(8081)은 다른 앱입니다. 고객 앱에는 관리자 경로가 아예 실리지 않습니다 — 실측 0개.
  • 고객 앱에서 /static/admin.html·/api/admin/report 모두 404. 운영 앱에서는 /api/admin/report 가 401(로그인 필요) — fail-closed 입니다.
  • 관리자 승격은 CLI 전용입니다 (python -m scripts.manage promote <사용자명>). 화면에 자기 자신을 관리자로 만드는 버튼이 없습니다.

★증명하지 못한 것

  • 관리자 대시보드 안쪽은 찍지 못했습니다. 로그인이 필요한데 자격증명을 대신 입력하지 않았습니다. 컷6이 증명하는 것은 「잠겨 있다」까지이고, 대시보드가 데이터를 옳게 그리는지는 미확인입니다.
  • 코호트 통계는 빈 값입니다. 컷4 아래 「실제 검증 데이터 / DEMO·합성 데이터」가 전부 0건 — 동작 불량이 아니라 제보 콜드스타트(최소 표본 30 미달)입니다. 화면이 「사례 없음」이라고 정직하게 적습니다.
  • 이 스토리보드는 한 흐름(삼성화재·K02.1)입니다. 다른 보험사·다른 질병기호에서 같은 품질이 나오는지는 이 문서가 증명하지 않습니다. 실제로 같은 점검에서 M51.2(현대해상)·J20.9(흥국화재)는 근거를 못 찾아 기권했습니다(no_evidence) — 면책 조항에 없다는 뜻이지 보장된다는 뜻이 아닙니다.
  • 확정 850건은 기계 대조까지입니다. 사람 최종 승인은 0건. 엄격 모드(config/precheck_mode.json → human_signoff)로 바꾸면 판정 가능 약관은 0건이 됩니다.

## 독립 검증에서 잡아 보완한 문제

첫 검증은 구현을 무조건 통과시키지 않고 다음 세 항목 때문에 유료 게이트를 닫았다.

1. `worker-3-status.json`의 비표준 `risks` 속성
2. 429·timeout·빈 응답·보장 단정 출력 각각의 20-way fault fan-out 증거 부족
3. S7 승인 릴리스 지문과 기대 occurrence 수 변조 음성 fixture 부족

각 항목을 별도 remediation 브랜치에서 수정했다. 추가로 통합 검사에서 짧은 latency가
`e-05`로 노출돼 기존 Prometheus 파서가 거부하는 결함을 발견해 고정 소수점 표기로 보완했다.

## 3채널 E2E

동일한 fake provider와 승인 원문을 사용해 공개 `POST /v1/chat`, 등록 에이전트
`POST /v1/agent/terms/explain`, MCP `explain_term`을 실제 라우팅했다. 첫 응답은
`source=call`, 같은 프로세스의 후속 채널은 `source=cache`였고 provider 호출은 1회였다.
등록 에이전트와 MCP 모두 429와 `Retry-After`를 보존했다.

메모리 guard는 프로세스 단위다. uvicorn worker/replica를 늘리면 한도도 인스턴스 수만큼
늘어나므로 운영 확장 시 공유 limiter 또는 앞단 rate limit이 필요하다.

## API 키 시험 대체 판단

사용자 지시에 따라 실제 provider API 키 스모크·부하 시험은 Codex의 독립 의미 검토와
providerless 인메모리 부하 시험으로 대체했다. `OPENAI_API_KEY`, `GEMINI_API_KEY`,
`GOOGLE_API_KEY`를 제거한 프로세스에서 1→2→4→8 동시성으로 각 20건, 총 80건을 실행했고
80/80 성공, 429 0건, 의미 안전 중단 0건, 외부 provider 호출 0건으로 끝났다. S7 골든 계약도
같은 조건에서 12/12 case, 36/36 run을 재확인했다.

이 대체 시험은 애플리케이션의 램프 스케줄링, 체크포인트, 집계, HTTP·의미 안전 중단 게이트와
응답 의미 계약을 검증한다. 실제 provider의 네트워크 지연, 가용성, 과금·토큰 집계,
provider 측 rate limit은 측정하지 않는다. 따라서 합의된 무 API 키 범위는 완료됐지만,
실제 provider 전송 성능과 동일한 결과라고 해석하면 안 된다.

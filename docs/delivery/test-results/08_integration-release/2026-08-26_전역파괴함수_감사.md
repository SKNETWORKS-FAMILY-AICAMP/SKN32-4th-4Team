## 결론

`app/`, `db/`, `scripts/`에서 요청한 성질을 가진 **직접 파괴 sink는 8개 작업, 직접 실행 함수/DB 함수 9개**다. wrapper·CLI·라우터는 중복 집계하지 않고 호출부에 연결했다.

가장 위험한 것은 `drop_incomplete(conn)`이다. 전역 정리 자체는 전체 색인 재적재에 필요한 작업이지만, 함수 인터페이스에는 대상 문서·세대·명시적 apply가 없다. 즉 **운영 작업의 의도는 전역이지만 재사용 API에는 범위가 빠졌다.**

시험 관점의 결론:

- `drop_incomplete` 직접 시험 호출은 **2곳/2곳** 모두 `CREATE SCHEMA` + `SET search_path` + `count(*) == 0`의 **3요건/3요건**을 충족한다. 추가 미격리 호출 없음.
- `assign_ordinals` 직접 시험 호출은 **1곳/1곳**이며 `dry_run=True`다. 3요건 격리는 **0곳/1곳**이지만 파괴 경로를 타지 않는다.
- `ensure_schema` 직접 시험 호출은 **10곳/10곳**이다. 3요건 충족은 **2곳/10곳(20.0%)**, 미격리는 **8곳/10곳(80.0%)**이다.
- PostgreSQL 합성 `reset`, agent history `prune`, embed revision backfill의 직접 DB 시험 호출은 각각 **0곳/0곳**이다.

감사 분모는 Python **329개 파일**, SQL **23개 파일**, shell/PowerShell **14개 파일**, 합계 **366개 파일**이다. 파괴 키워드가 발견된 **35개 파일/366개 파일(9.6%)**을 함수 경계와 호출부까지 분류했다.

## 위험 판정 근거

`drop_incomplete`는 “의도된 전역 운영 정리”와 “범위를 빠뜨린 재사용 API”가 동시에 맞다. 전체 build에서는 반쪽 벡터를 다시 넣기 위해 전역 정리가 필요하지만, 그 사실이 호출 시그니처에 나타나지 않는다. `conn` 하나로 실행되는 이상 테스트·REPL·새 스크립트가 운영 build와 같은 권한을 갖는다.

`assign_ordinals`는 더 좁다. 필수 `generation`이 있어 모든 세대를 건드리지는 않지만, `sha256s=None`이 그 세대 전체이고 쓰기가 기본이다. 정상 적재 경로는 touched 문서 목록을 넘기므로 안전하고, 위험은 소급 CLI와 새 직접 호출에 집중된다.

`ensure_schema`, migration 적용기, 합성 reset, 보존 이력 prune, legacy schema 보정은 전역이어야 목적을 달성한다. 이들은 범위를 빠뜨린 업무 함수가 아니라 운영 도구/DDL이다. 다만 `ensure_schema`를 실데이터 연결을 쓰는 시험 8곳에서 부르는 것은 별도 위험이다. DDL이 멱등이라는 사실은 격리를 대신하지 않는다.

- `tests/test_clause_index.py:109,160,286,344,418,485,547`
- `tests/test_pg_clause_store.py:117`

이 8곳은 `_conn_or_skip()` → `db.postgres.pgvector_index.get_conn()`을 사용한다. `get_conn()`은 설정의 `PGVECTOR_DSN`을 사용한다. 코드 기본값은 `mall_vec`, 기본 schema는 `public`이다.

`tests/conftest.py`는 `DATABASE_URL`만 임시 DB로 바꾸고 `PGVECTOR_DSN`은 바꾸지 않는다. 개발자 환경이 이를 덮을 수 있으므로 실제 연결 DB가 어디인지는 정적 코드만으로는 **모른다**. 그러나 기본 설정에서 공유 `mall_vec.public`인 것은 확인된다.

그 밖의 파괴 sink 시험:

- `assign_ordinals`: **1곳/1곳** 직접 호출이 `dry_run=True`; UPDATE·commit 경로를 타지 않는다.
- migration apply: **1곳/1곳** 직접 `main()` 호출은 새 UUID 임시 database에서 실행한다.
- `_add_missing_columns`: **2회/2회**가 한 시험의 `tmp_path` SQLite 파일에서 실행된다.
- PostgreSQL demo reset, agent history prune, embed revision backfill: 직접 시험 호출 **0곳/0곳**.

## 제외 기준과 추가 후보

필수 식별자나 필수 시간 범위가 있는 다음 함수들은 조건 2를 충족하지 않아 제외했다.

- `delete_face(user_id)`
- `change_role(username, ...)`
- `purge_knowledge_gaps(before)`
- agent client별 UPDATE 함수들
- `prune_occurrences(aliases, generation)`
- `demote_occurrences(rows, generation)`
- 각종 upsert의 `ON CONFLICT ... DO UPDATE`
- 한 trigger row나 필수 키에 묶인 SQL 함수

`scripts/db/migrate_vec_to_insurance_real.py`는 기본 조회이며, `--apply` 때 빈 목적지에 COPY만 하고 옛 DB는 SELECT만 한다. `scripts/index/reconcile_occurrences.py`와 `scripts/db/rollback_vec_schema.py`도 기본 조회다.

위 8개 직접 sink와 방어된 4개 경계 사례 외에는 **추가 후보 없음**.

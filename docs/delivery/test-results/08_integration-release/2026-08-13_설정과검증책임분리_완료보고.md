# 설정과 검증 책임 분리 완료 보고서

작성일: 2026-08-13
대상: `app/core/config.py` 및 전체 호출부

## 결론

`app/core/config.py`에서 환경 설정 선언과 실행 정책 검증을 분리했다. 설정값의 출처는
그대로 유지하고, 기존 호출부는 모두 새 검증 모듈을 사용하도록 전환했다.

## 적용 경로

- `app/core/config.py`
  - `Settings`, `get_settings()`만 유지
  - 환경변수·기본값·경로 필드의 단일 소스 역할
- `app/core/config_validation.py`
  - `require_secret_key`
  - `require_agent_hash_secret`
  - `require_insurance_idempotency_secret`
  - `has_openai_key`, `has_google_key`
  - `settings_readiness`
  - `validate_production_persistence`, `validate_agent_bind`
- `app/obs/readiness.py`
  - DB·인덱스 연결 확인은 기존 운영 readiness 책임으로 유지

설정 readiness는 외부 연결을 시도하지 않는 요약이고, 운영 readiness는 실제 자원을
확인한다. 두 의미를 합치지 않았다.

## 호출부 전환

애플리케이션(`main.py`, `llm_clients.py`), 인증(`auth/*`), 라우터(`auth.py`, `health.py`,
`precheck.py`), 운영 스크립트(`realkey_smoke.py`, `run_agent_server.py`), 관련 테스트를
`app.core.config_validation` 경로로 전환했다. `precheck.py`는 함수 내부 로컬 import 범위까지
확인해 검증 함수가 다른 함수에서 누락되는 런타임 오류를 막았다.

## 검증

- `python -m compileall -q app scripts tests`: 통과
- 이전 메서드 호출(`settings.require_*`, `settings.has_*`, `settings.readiness`) 검색: 잔여 없음
- `app.core.config`에서 검증 함수가 노출되지 않는 회귀 테스트 추가
- 기존 설정·secret·agent bind 테스트는 새 모듈의 함수 계약으로 변경

## 경로 결정의 검수 경계

사용자가 요청한 “Claude 검수”를 실제로 수행할 Claude CLI/MCP 도구는 이 세션에 제공되지
않았다. 따라서 Claude 검수 완료라고 주장하지 않는다. 대신 저장소의 `docs/architecture.md`
계층 계약과 이미 존재하는 `app/obs/readiness.py`의 책임을 근거로 경로를 결정했으며, 그
결정을 계획서와 본 보고서에 명시했다. 외부 Claude 검수 결과가 별도로 전달되면 경로와
호출부를 다시 대조할 수 있다.

## 후속 확인

대상 설정 테스트와 전체 비외부 의존성 테스트를 실행해 회귀 여부를 최종 확인한다.

## 결론

사용자가 승인한 기준인 **API 키 호출 없이 Codex 검토와 providerless 시험으로 대체**하는 범위에서
5개 파트는 모두 완료됐다. 다섯 status JSON이 모두 `complete`이고 외부 생성 호출은 모두 0이며,
파트별 구현 보고서 5개와 독립 검증 보고서가 UTF-8 Markdown으로 정상 존재한다.

이번 최종 점검에서 인메모리 HTTP client를 주입해 1→2→4→8 동시성, 단계별 20건씩 총 80건을
실제로 실행했다. 80/80건이 HTTP 200이었고 중단 사유는 없었다. 같은 키 제거 환경에서 S7 골든
평가 12/12 case·36/36 run과 관련 테스트 25건도 다시 통과했다.

## 차이와 남은 운영상 주의점

Codex 검토는 답변 의미와 코드·fixture 계약을 확인할 수 있지만, 애플리케이션이 실제 OpenAI API
endpoint에 요청을 보낸 것과 같지는 않다. 공식 OpenAI API도 응답 생성 호출에 API 키를 받는 별도
endpoint를 제공한다. 이번 실행은 그 endpoint를 호출하지 않았다.

따라서 다음 항목은 결함이나 미완료가 아니라 사용자가 대체하기로 정한 범위 밖이다.

- 실제 provider TLS/DNS/네트워크 지연과 장애
- 실제 계정의 RPM/TPM 및 429 동작
- 실제 과금과 provider token usage 일치
- 실제 provider 모델 출력의 장시간 품질 편차

프로세스 로컬 rate limit·cache는 다중 worker/replica에서 전역 한도가 되지 않는다. 운영 확장 시
공유 limiter 또는 앞단 rate limit이 필요하다는 기존 주의점도 유지한다.

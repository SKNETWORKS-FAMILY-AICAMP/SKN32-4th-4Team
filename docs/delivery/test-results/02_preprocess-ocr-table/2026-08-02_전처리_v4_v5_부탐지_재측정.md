# 전처리 v5 재측정 — 부(部) 탐지 개선이 인용 문제를 풀었나

작성 2026-08-02 · v4·v5 **전량 1,367문서** 대조

---

## 0. 한 줄 결론

**v5 는 의도한 일을 했다** — 목차로 잘못 버려지던 **본문 24,511쪽을 되찾았다.**
**그러나 인용 식별 문제는 풀지 못했다.** 오히려 충돌이 늘었다.

인용 식별을 실제로 푼 것은 **`clause_id` 에 내용 해시를 붙인 쪽**이다.
조항이 63% 늘었는데도 충돌은 211,131개 중 **28개(0.013%)** 에 머문다.

---

## 1. v5 가 한 일 — 목차 판정을 비율에서 구조로

v4 는 *"조 머리가 촘촘하고 머리당 글자가 짧으면 목차"* 라는 **비율**로 판정했다.
그게 **법령 인용이 조밀한 본문**을 목차로 오판했다.

```
"「국민건강보험법」제5조, 제53조, 제54조에 따라 요양급여 또는
 「의료급여법」제4조, 제15조, 제17조에 따라 의료급여를 …"
```

v5 는 **구조**를 본다 — 목차 줄에는 반드시 쪽번호가 붙는다.

| 지표 | v4 | v5 | |
|---|---:|---:|---|
| **목차로 제외한 쪽** | 29,221 | **4,710** | **24,511쪽 복구** |
| 조항 총수 | 129,525 | **211,131** | +63% |
| 조항/문서 중앙 | 95 | **142** | |
| 부(部) 중앙 | 8 | **9** | |
| 부 최대 | 36 | **71** | |
| 조항길이 중앙 | 423자 | **356자** | |
| 조항길이 p95 | 3,476 | **2,851** | |

부 탐지도 나아졌고(최대 36→71), 조항 길이 분포도 좋아졌다.

---

## 2. 그런데 인용 충돌은 늘었다

| 지표 | v4 | v5 |
|---|---:|---:|
| `qualified_no` 중복 | 31,085건 / 1,181문서 | **56,177건 / 1,201문서** |
| **조항당 충돌률** | **24.0%** | **26.6%** |
| 번호키 중복 | 72,520건 (한 키 최대 187) | **130,769건 (최대 187)** |

**부를 더 잘 찾았는데 충돌이 늘었다.** 본문이 늘어난 만큼 같은 번호의 조항도
늘었기 때문이다. 조항당 비율로 봐도 **24.0% → 26.6%로 오히려 나빠졌다.**

### 왜 부 탐지로는 안 풀리나

부 탐지는 *"이 조항이 어느 특약 소속인가"* 를 정한다.
그런데 충돌의 원인은 **한 부 안에서도 같은 번호가 반복**되는 것이다.

```
p73  보험료 자동납입 특별약관/1.   "보험료 납입"             324자
p73  보험료 자동납입 특별약관/1.   "특별약관의 체결 및 효력"   798자
```

부 라벨이 정확해져도 이 둘은 여전히 같은 키다.
**부 탐지 입도를 아무리 높여도 이 축으로는 유일해지지 않는다.**

## 3. 실제로 푼 것 — 내용 해시

`clause_id` 에 `content_hash` 앞 8자를 붙였다.

| | v4 | v5 |
|---|---:|---:|
| 조항 총수 | 129,525 | 211,131 |
| **`clause_id` 중복** | **8건 / 3문서** | **28건 / 22문서** |
| 비율 | 0.006% | **0.013%** |

**조항이 63% 늘었는데 충돌은 0.013% 다.**
같은 자리에 실린 다른 내용이 구분되기 때문이다.

> ★부 탐지 개선은 **보조**다. 인용을 유일하게 만드는 것은 내용 해시다.
> 근본 원인 수정이 항상 정답은 아니다 — 이 경우 축 자체가 유일성을 줄 수 없다.

## 4. v5 의 대가 — `suspect` 가 늘었다

```
parse_status   ok 1,240 → 1,108   (suspect 108 → 250)
```

**판정 대상이 132문서 줄었다.** 사후 검증이 잡은 사유:

```
  7  p146 한 쪽에서 조항 21개(중앙 98자)    ← 목차가 아직 남은 쪽
  5  조항 하나가 33,682자                  ← 경계를 못 찾음
  5  p2 한 쪽에서 조항 20개(중앙 21자)
```

목차를 덜 배제하다 보니 **일부는 목차가 본문으로 들어왔다.**
조용히 통과시키지 않고 `suspect` 로 내리는 것은 옳은 동작이다.

조항 최대 길이도 119,108 → **147,390자**로 나빠졌다(경계를 못 찾은 구간).

## 5. 어느 쪽을 쓸 것인가 — **v5**

단정하기 이르지만 v5 가 낫다고 본다.

| | v4 | v5 |
|---|---|---|
| 잃은 것 | **본문 24,511쪽** — 면책 조항이 통째로 사라진 사례 확인 | 목차 일부가 본문에 섞임 |
| 되돌릴 수 있나 | ❌ 없는 것은 못 찾는다 | ✅ 걸러낼 수 있다 |
| 판정 가능 문서 | 1,240 | 1,108 |

**잃은 것은 되찾을 수 없지만 섞인 것은 걸러낼 수 있다.**
그리고 섞인 문서는 `suspect` 로 표시돼 자동 판정에서 이미 빠진다.

다만 **판정 대상이 1,108로 줄어든 것은 실질 손실**이다.
목차 잔여를 더 걸러 `ok` 로 되돌리는 것이 다음 과제다.

## 6. 남은 일

1. **`suspect` 250건의 사유별 분류** — 목차 잔여인지 진짜 경계 실패인지 나눠야 한다
2. **한 쪽에 조항 20개 이상** 규칙을 목차 신호로 승격 검토
3. `clause_id` 충돌 28건 확인 — 같은 쪽·같은 내용이 진짜 두 번 실린 것인지

   문서별로 `accepted` 를 지정하는 방식으로 바꿔야 한다)

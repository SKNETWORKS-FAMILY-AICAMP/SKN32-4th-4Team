# s5L 연동계획 단계2 — 부 제목 크기/굵기 확인 신호, 완료보고

- 계획: s5L 레이아웃 to_clauses 연동 계획 (내부 원본 참조: `../plans/2026-08-26_1600_s5L_레이아웃_to_clauses_연동_계획.md`) §단계2
- 상태: **완료.** 판정 불변(§2 YAGNI) 확인 + 코덱스 5.6sol "사람 표본검수자"
  시뮬레이션 + 직접 재보정까지 마쳤다.

## 1. 무엇을 했나

`_SECTION_TITLE`/`_TYPE_LABEL` 이 이미 텍스트 규칙으로 채택한 부(部) 제목
후보에 대해, 그 줄의 글자크기(size)/굵기(bold)가 **바로 다음 줄**보다 큰지
확인해 `stats`에 집계로만 남긴다. **부 경계 채택 여부는 절대 안 바꾼다**
(순수 정보용, 계획서 §2 YAGNI).

## 2. 1차 구현 → 코덱스 표본검수 → 재작업

### 1차 구현의 결함(코덱스 5.6sol이 "사람 표본검수자" 역할로 발견)

계획서가 완료 조건에 "사람 필요: 표본검수"를 못박아 뒀는데, 이 세션에는
실제 사람 검수자가 없어 **코덱스에게 사람 표본검수자 역할을 맡겼다**(실제
표본 40건, 5개 보험사, size/bold 원본 수치 그대로 제공 — 코드 검토가 아니라
"이 판정이 실제로 타당한가"를 원본 데이터로 판단하게 함). 결론: **보류**.
지적한 것:

1. **1차 대리지표가 틀렸다** — "보험사별 크기/굵기 신호 강도"를 조 머리
   (`_ARTICLE`) 로 재고 그대로 부 제목에 재사용했는데, 실제 부 제목
   모집단으로 다시 재보니 완전히 다른 보험사도 있었다(아래 §3).
2. `checked` 카운터가 `None`(비교 불가)까지 분모에 섞여 있었다.
3. 결측 size/bold 를 `or 0`/`bool(None)` 으로 채워 없는 데이터가 있는
   것처럼 셈해질 위험이 있었다.
4. 이름 `section_title_visual_confirmed`가 과장이다 — 이 값은 "진짜
   제목 확인"이 아니라 단순 대비(contrast) 조건 적중이다.
5. **회귀 관문(S1/S3/S4/gated 불변)은 통과**로 인정했다 — diff 가 카운터·
   `stats` 필드만 추가하고 판정 로직을 안 건드림을 코드로 확인했기 때문.

## 3. 발견됐지만 이번 범위 밖으로 둔 기존 결함 2건

Phase 2 진단이 만들어낸 게 아니라 **이미 있던** `_SECTION_TITLE`/러닝헤더
veto 의 결함이다. 코드는 안 고쳤다 — RULE §4.0 "버그는 못 고쳤어도
리포트부터"에 따라 여기 남긴다.

1. **NH 러닝풋터가 `_SECTION_TITLE`에 오채택됨** — nhlife 실측 중 발견.
   페이지 하단 "상품명 + 쪽번호" 조합(예:
   "실속만점NH실손의료비보험(갱신형)(무배당) 주계약 약관")이 "…주계약 약관"
   접미사 때문에 `_SECTION_TITLE`에 걸려 부 제목 후보로 반복 채택된다.
   진짜 제목("지정대리청구서비스특약" 등, 24pt)과 섞여 nhlife 의 대비
   비율을 크게 왜곡시켰다(25.5%로 낮게 나온 원인의 상당 부분).
2. **러닝헤더 veto 가 `_SECTION_TITLE`로 우회됨** — 코덱스 지적을 직접
   재현·확인. `_SECTION_LINE`(`보통약관` 등 5단어)이 위치+반복 신호로
   veto(`m=None`)되면 `else` 로 `_SECTION_TITLE` 재시도가 도는데, 앞에
   공백이 1~2칸이라도 있으면(`"  보통약관"`) `_SECTION_TITLE` 의
   `[^\n]{2,40}?` 프리픽스가 그 공백을 "제목 앞부분"으로 흡수해 **다시
   매치**된다(실측 확인: `bare '보통약관'` 은 `_SECTION_TITLE` 에 안
   걸리지만 `'  보통약관'` 은 걸림). veto 의 의도가 이 경로에서 무력화된다.
   ★단, Phase 1 전량 실측(S1/S3/S4/gated 불변)이 이미 이 경로를 포함한
   상태였으므로 **현재 산출물에 측정 가능한 영향은 없다** — 그래도 설계
   의도와 실제 동작이 어긋나 있다는 사실은 남긴다.

## 5. 계획서 §5(전체 완료 기준) 대비 결론

> "s5L 을 입력으로 한 s6 재생성이 s5 입력 대비 S1/S3/S4/gated 중 어느
> 것도 악화되지 않고 최소 하나는 개선되면 성공. 그렇지 않으면 정직하게
> 리포트하고 접는다."

**정직한 결론: 4개 지표 전부 불변(개선 없음, 악화도 없음)이다.** 이 기능은
설계 자체가 "판정을 안 바꾸는 정보용 집계"이므로 애초에 이 지표들이
움직일 수 없다 — Phase 1(러닝헤더)과 같은 결말이다. **개선은 이 신호를
실제 판정(예: 애매한 부 경계의 tie-break)에 소비하는 별도 단계에서만
나올 수 있다** — 그건 이번 세션 범위 밖이고, 계획서도 "향후 애매한 경계
판정에 씀"이라고 미래 과제로 남겨 뒀다.

## 2. 무엇을 바꿨나

비율을 버리고 **구조**를 본다. 신호 넷, 하나라도 걸리면 목차.

| 신호 | 내용 | 발동 쪽수 |
|---|---|---:|
| 목차제목 | 줄이 `…목차` 로 끝난다 (`상품 목차`·`보통약관(공통조항) 목차`) | 2,696 |
| 점선줄 | 점선+쪽번호로 끝나는 줄 6개 이상 | 2,972 |
| 목차항목 | `제N조/관/절/장` + 쪽번호(같은 줄 끝 **또는 다음 줄**) 6개 이상 | 2,376 |
| 목차연속 | 직전 쪽이 목차 제목 쪽 + 항목 3개 + 조 머리 6개 | 16 |

`목차항목`의 "다음 줄" 조건이 핵심이다. NH 는 조 제목과 쪽번호를 **다른 줄**에 찍는다.

```
제1조【보장종목】
28
제2조【용어의 정의】
28
```

실측: 목차 p19·20·23 은 이 쌍이 15·28·24개, 본문 p29·35·58·86·87·93·102·115·167 은 **전부 0**.

### 조항 머리 정규식도 하나 고쳤다

`_NUMBERED`(특별약관의 `N. (제목)`)가 **제목 속 중첩 괄호**를 못 받아 조항을 통째로 놓쳤다.
하필 판정에 중요한 것들이다.

```
4. (보험료의 납입을 연체하여 해지된 계약의 부활(효력회복))
30. (보험료의 납입이 연체되는 경우 납입최고(독촉)와 계약의 해지)
```

**"줄이 닫는 괄호로 끝나야 한다"는 제약은 유지**했다. 그게 오탐을 막는 핵심이다 —
`38.(해약환급금) ①에 따른 …지급합니다.` 같은 준용 문장이 이 제약에 걸린다.
(`_3rd_project_4` 는 줄 끝 제약이 없어 이런 문장을 전부 조항으로 센다.)

## 3. 코덱스가 반박한 것 — 셋 다 맞았다

### 3-1. "조 머리 밀집도" 신호는 관계법령 부록과 구분 불가 → **폐기**

쪽번호 없는 조판을 잡으려고 "조 머리가 빽빽하면 목차" 신호를 넣었다.
코덱스가 반례를 찾았다 — **약관 뒤에 붙는 인용 법령 페이지가 목차와 구조가 같다.**

```
제250조(살인, 존속살해)          ← 조 머리 줄
① 사람을 살해한 자는 …           ← 본문 줄
제252조(촉탁, 승낙에 의한 살인 등)
```

밀집도 실측: 흥국생명 p131 = 0.33, NH손보 p287 = 0.41 — **목차(0.38~0.51)와 겹친다.**
가를 수 없어 신호를 뺐다.

### 3-2. `\s` 가 줄바꿈을 먹어 **본문 103쪽을 삭제**하고 있었다

`^\s*목\s*차\s*$` 의 `\s` 는 `\n` 을 포함한다. **단독 줄 제한이 사실은 없었다.**
롯데손보는 페이지 옆에 세로 탭으로 `목` / `차` 를 한 글자씩 찍는데, 그게 `목\n차` 로
추출돼 매칭됐다. v4 부터 있던 결함이다.

| | 목차 제외 | 조항 |
|---|---:|---:|
| 롯데 `1cdb018a5867` (165쪽) v4 | 70쪽 | 49 |
| 〃 v5 | **4쪽** | **156** |

같은 원인이 `_NUMBERED` 에도 있었다. `\s*$` 가 줄바꿈을 넘어가
`2. \n(\n…본문…\n)` 같은 조판 아티팩트를 조항 머리로 잡고 있었다(§5 참조).

### 3-3. 현대해상 구형 목차를 놓쳐 **가짜 조항 51개**가 `ok` 로 통과

`dc72bc8035b4`(104쪽)는 쪽번호가 장(章)에만 붙어 신호 3에 안 걸렸다.
결과: 조항 157개 중 **51개(32.5%)가 15~92자 가짜**. 그런데
최대 길이 3,515자라 길이 검사를 통과하고, 가짜가 수를 부풀려 "너무 적다" 검사도 통과했다.
**두 사후검증이 서로의 사각을 못 메운다.**

처음엔 "가짜가 섞이는 편이 본문을 지우는 것보다 낫다"고 감수하려 했으나,
코덱스가 *"51개가 정상과 같은 스키마로 저장되고 `parse_status="ok"` 인 점이 위험하다"* 고
반박했고 맞다. `목차제목`·`목차연속` 신호를 넣어 해결했다.

```
현대해상 dc72bc8035b4:  조항 157 → 106   (p33 목차제목 · p34 목차연속)
```

## 5. 내가 틀린 기준 — "조항 감소 0건"

`조항이 줄어든 문서 39건`이 나와 회귀를 의심했다. 실물을 열어 보니 **잃은 것이 전부 가짜**였다.

```
2. \n(\n하는 대가로 수수한 금액 등은 감면받은 의료비에 포함…\n)
3. \n(\n따라 산출된 보험요율을 말함을 적용하며…\n)
```

v4 의 `\s*` 가 줄바꿈을 먹어 **여러 줄에 걸친 조판 아티팩트**를 조항으로 세고 있었다.
39건 전부 `numbered→numbered` 로 번호 체계 전이는 없었다.

**"조항 수가 줄면 안 된다"는 DoD 자체가 틀렸다.** 가짜가 줄어드는 건 개선이다.
같은 이유로 **"3rd 보다 조항 수가 많아야 한다"도 나쁜 기준이었다**(§6).

## 6. `_3rd_project_4` 와의 대조 — 조항 수로는 우열을 못 가린다

같은 PDF 244건:

| | v4 | **v5** | 3rd |
|---|---:|---:|---:|
| 조항 합계 | 25,457 | **30,652** | 30,569 |
| 조항 중앙값 | 94 | **113** | 121 |

보험사별 합계:

| 보험사 | v4 | **v5** | 3rd | 판정 |
|---|---:|---:|---:|---|
| 삼성화재 | 5,846 | **8,259** | 7,023 | v5 우세 |
| DB손해보험 | 16,789 | **17,848** | 17,767 | v5 근소 우세 |
| 동양생명 | 903 | **1,600** | 1,137 | v5 우세 |
| NH농협생명 | 1,919 | 2,945 | **4,642** | 아래 설명 |

**NH 의 차이는 3rd 의 과대계상이다.** 우리가 목차로 뺀 페이지 안에 조 머리가 **2,482개** 있다.

```
v5 조항 2,945 + 목차 페이지 속 조 머리 2,482 = 5,427  >  3rd 4,642
```

3rd 는 목차를 페이지 단위로 제외하지 않고 **점선 줄만** 지우는데, NH 목차에는 점선이 없다.
그래서 목차 항목이 조항으로 들어간다.

DB 도 같은 성격이다. 3rd 의 `RE_NUM` 은 줄 끝 제약이 없어 준용 문장을 조항으로 센다
(실측 25문서: 우리 엄격 2,661 vs 저쪽 느슨 3,046, 차이의 대부분이 준용 문장).

> **결론: 조항 수는 품질 지표가 아니다.** 다음 단계부터는 인용 정확도로 재야 한다.

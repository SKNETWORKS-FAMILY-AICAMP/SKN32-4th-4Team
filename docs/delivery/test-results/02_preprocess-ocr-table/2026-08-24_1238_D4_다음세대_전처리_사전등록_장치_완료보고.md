S7 결과를 이미 본 뒤 사후 비교를 D4 사전등록 완료로 잘못 세지 않도록 바로잡고, 다음
extraction generation부터는 결과 생성 전에 품질 계약을 해시로 고정해 fail-closed로 검증할
최소 장치를 만든다.

발견한 역사적 결함은 코드 변경 전에

### 2.2 read-only 검증 CLI

신설: `scripts/verify/verify_preprocess_preregistration.py`

```powershell
python -m scripts.verify.verify_preprocess_preregistration
python -m scripts.verify.verify_preprocess_preregistration --generation-id s7_hybrid-table-v1
python -m scripts.verify.verify_preprocess_preregistration `
  --evidence data/eval/<next_generation_d4_evidence.json> `
  --artifact-root .
```

검증기는 다음을 확인한다.

1. registry 실제 파일 바이트와 sidecar SHA-256 일치
2. 현행 `s7_hybrid-table-v1`의 `not_eligible_retroactively` 상태
3. registry보다 먼저 생성된 manifest에 대한 소급 적용 거부
4. manifest가 가리키는 출력/config 바이트의 실제 재해시
5. 문서 수·mismatch·참조 위반·serving/citation 누출 0 계약
6. D6 결함 변이 3종 전부 탐지 여부
7. D5 사람 평가와 threshold binding 누락 시 실패
8. threshold binding의 정책/registry/generation 지문 및 manifest 이전 등록 시각
9. 모든 품질 게이트 통과 뒤에도 사람 release 승인 요구

registry를 검증하는 것만으로 serving 포인터를 바꾸지 않는다.

### 2.3 회귀·변조 시험

신설: `tests/test_preprocess_preregistration.py`

- registry 1바이트 변조 → sidecar mismatch 탐지
- 현행 S7 → `not_eligible_retroactively`
- 문서 수·manifest mismatch·참조 위반·serving/citation 누출을 각각 변조 → 모두 실패
- D6 3종을 하나씩 빼기 → 각 생존 mutant 탐지

사전등록 값이 아니다. production registry에는 미합의 수치가 `null`로 남아 있다.

## 4. 미완료·외부 입력

D4 자체는 완료가 아니다. 다음 항목은 책임 있는 사람의 입력 없이 대신 만들 수 없다.

1. D5 층화 사람 라벨, 이중판정, 불일치 adjudication, P/R/F1 및 95% CI
2. `word_coverage`·셀 오연결·문장 절단의 다음 세대 사전 임계값 합의
3. 그 값을 담은 threshold binding artifact의 manifest 생성 전 동결
4. 다음 extraction generation 전량 생성과 evidence 제출
5. 최종 사람 release 승인

이 다섯 항목이 들어오기 전 검증기는 다음 세대를 통과시키지 않는다. 현행 serving 포인터는
이번 작업에서 변경하지 않았다.

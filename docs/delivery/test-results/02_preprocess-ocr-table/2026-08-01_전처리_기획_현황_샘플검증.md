## 1. 기획 — 어떤 단계를 거치나

```
원본 PDF
  │  to_page_json.py      (PyMuPDF)
  ├─ 텍스트 추출 + 표 추출 + 정규화
  ▼
페이지 JSON   data/extracted/{보험사}/s2_pymupdf-1.28.0/{sha12}.json
  │  to_clauses.py
  ├─ 목차 페이지 판별 → 부(部) 경계 → 조항 경계 → 계층 청킹
  ▼
조항 JSON     data/structured/{보험사}/s2_pymupdf-1.28.0/{sha12}.clauses.json
```

배치는 `run_all.py` 가 감싼다. **변환 로직을 복제하지 않고** 두 모듈을 부른다.

### 설계에서 지킨 것

| 원칙 | 이유 |
|---|---|
| 산출 경로에 **추출기 버전**을 박는다 | 추출기가 바뀌면 결과가 달라진다. 덮어쓰지 않고 공존 |
| 이미 있으면 **건너뛴다** | 중단 후 재실행이 안전하다 |
| 한 건 실패로 **전체가 죽지 않는다** | 실패를 모아 JSON 으로 남긴다 |
| 조항 해시에 **번호를 넣지 않는다** | 번호가 바뀌어도 내용이 같으면 같은 조항 |
| 표는 **어느 조항 것인지 추정하지 않는다** | 같은 페이지에 있다는 사실만 기록 |

### 보험사별 형식 차이 — 실제로 다르다

| 차이 | 실측 | 대응 |
|---|---|---|
| 조항 번호 체계 | 보통약관은 `제N조`, **특별약관은 `N.`** | 두 형식 지원. **섞지 않는다**(섞으면 본문 번호목록이 끼어든다) |
| 제목 괄호 | `()` `【】` `[]` | 셋 다 인정 |
| 제어문자 오염 | 표본 64건 중 **27건(42%)**, `\x01` 279,623회 | 정규화 후 제거. 지운 수를 `stats.normalized` 에 기록 |
| 목차 표기 | 점선 유무·`목 차` 푸터 유무 | **여기서 결함이 났다**(§2) |

## 2. 샘플 검증 — 코덱스와 함께 뜯어본 결과

샘플: **동양생명 `무배당우리WON하는급여실손의료비보장보험(갱신형)`** · 403쪽 · 조항 462개
(가장 조항이 많은 실손 본약관을 골랐다)

### 결함 1 — 목차 줄이 조항으로 잡혔다 (근본 원인)

조항이라며 나온 내용:

```
제1 조 【보장종목】 ............................................. 1
```

목차 판정 규칙은 *"한 쪽에 조 머리 6개 이상 & (글자수/머리수) < 200 이면 목차"*.

```
쪽    조머리   글자    글자/머리   판정
25     27    5,454     202     본문(!)   ← 임계 200을 간발로 넘김
26     33    5,710     173     목차
```

**점선이 글자수를 부풀려 비율을 밀어올렸다.** 점선을 지우고 다시 재면:

```
p25: 비율 202 → 33   목차로 정판
```

그리고 더 확실한 신호를 찾았다 — **페이지 푸터에 `목 차` 라고 찍혀 있다.**

```
251 / 401              목 차
```

### 결함 2 — 부(部) 구분이 안 된다  ★코덱스 P0

403쪽 약관인데 부가 `['머리말', '약관요약서']` 둘뿐이다.
그 결과 **조 번호가 충돌**한다.

```
조 번호 중복 52종:  제2조 51회 · 제3조 27회 · 제4조 24회 · 제1조 23회 …
```

특별약관이 여러 개면 조 번호가 1부터 다시 시작하는데, 부로 구분이 안 되니 섞였다.

코덱스가 짚은 것 — **경계 후보가 더 있다:**

```
○○ 주계약 약관 · ○○ 보통약관 · ○○ 특별약관 · ○○ 특약
제도성특약 · 단체취급특약 · 지정대리청구서비스특약
1-1. [건강] ○○ 특별약관   (번호·분류 접두어)
```

반면 **`제N편` `제N장` `제N절` `제N관` 은 내부 계층이지 경계가 아니다.**
`특별약관 → 제1관 일반사항 → 제1조` 구조가 실재하므로,
`제N관` 마다 번호를 초기화하면 **과분할**된다.

식별키도 `(문서, 조번호)` 가 아니라 **`(문서, 특약ID, 조번호)`** 여야 한다.

### 결함 3 — 25,000자짜리 조항  ★코덱스 P0

코덱스가 *"다음 조를 삼켰다고 단정하지 말고 안을 다시 검색해 보라"* 고 했다. 해 봤더니:

```
[제7조] '의료급여의 내용 등' 25,000자 p246-252
  본문 안 조 머리 후보 147개
  줄 시작 조 머리 144개 → '제7 조(의료급여의 내용 등) ..................'
```

**전부 목차였다.** 즉 결함 3은 독립 결함이 아니라 **결함 1의 결과**다.
목차 구간을 본문으로 오판해 그 안의 조 머리를 못 찾았고, 그래서 하나로 삼켰다.

### 코덱스가 매긴 우선순위

| 우선 | 결함 | RAG 검색 | 보장 판정 |
|---|---|---|---|
| P0 | 부 경계 누락 | 같은 제2조가 섞여 출처가 잘못 붙음 | **다른 특약의 지급사유·면책을 적용할 수 있어 가장 위험** |
| P0 | 초대형 조항 | 임베딩 희석·토큰 절단 | 뒤쪽 면책·한도가 누락되거나 엉뚱한 조에 귀속 |
| P1 | 목차 오인 | 목차가 본문보다 상위에 뜸 | 본문 대신 제목·페이지번호만 근거로 반환 |

## 3. 지금 진행 중인 변환은 옳게 되고 있나 — **부분적으로만**

| 항목 | 상태 |
|---|---|
| PDF 손상·잘림 | **없다** — 매직바이트 이상 0, `%%EOF` 없음 0, 65,536B 0 |
| 텍스트 누락 | **없다** — 페이지 수·글자 수 정상 |
| 제어문자 오염 | **해결** — v2 에서 제거, 검색 복구 확인 |
| 특별약관 번호 | **해결** — `N. (제목)` 인식 |
| **목차 오인** | ❌ **미해결** — 재실행 필요 |
| **부 경계** | ❌ **미해결** — 재실행 필요 |
| 표 의미 부착 | ❌ 미착수 — 셀만 뽑고 "무슨 표인지"는 모른다 |
| 별표 분리 | ❌ 미착수 |

**"파일마다 누락되거나 잘리는 자료가 있나"에 대한 답:**
파일 자체는 온전하다. **잘리는 것이 아니라 잘못 나뉘고 있다.**

## 4. 고칠 것 — 순서

1. **목차 판정을 다시 만든다** (결함 1·3 동시 해결)
   - 푸터·헤더의 `목 차` 표시를 **1순위 신호**로
   - 점선(`\.{6,}`)을 지운 뒤 비율 계산
   - 줄 끝 페이지번호 패턴을 보조 신호로
2. **부 경계를 넓힌다** (결함 2)
   - `○○ 특별약관` `○○ 특약` `제도성특약` 등 제목형 경계 추가
   - `제N관/장/절` 은 **경계가 아님을 명시**
   - 조 번호가 1로 초기화되는 지점을 보조 신호로
   - 식별키를 `(문서, 특약ID, 조번호)` 로
3. **`SCHEMA_VERSION` 을 3으로** 올려 재실행 (v2 와 공존)
4. 재실행 후 코덱스가 제안한 지표로 검증
   - 계약 단위별 조 번호 단조성
   - 조항 안에 남은 미검출 조 머리 수
   - 목차에만 있고 본문에 없는 조 / 그 반대

## 5. 한계 (정직 기록)

- 샘플 **1건**으로 찾은 결함이다. 코덱스 말대로 **층화 표본 30~50건**으로
  (목차·특약 시작·본문·표·별표·2단·문서끝) 다시 재야 한다.
- 2단 편집에서 좌우 열이 섞이는지 **아직 안 봤다.**
- 표의 행·열 붕괴율을 **아직 안 쟀다.**
- 별표(장해분류표 등)가 어느 조항에 귀속되는지 **아직 안 정했다.**
  코덱스는 보장 판정에서 조항 텍스트보다 **특약 귀속과 별표 연결 정확도가 더 중요**할 수 있다고 했다.

# population A 사람 재검토 → S3·S4 정밀도 수정 완료보고

- 계획: S1 ABA 부경계검출 개선 계획 (내부 원본 참조: `../plans/2026-08-26_1500_S1_ABA_부경계검출_개선_계획.md`) §3-1(같은 날 별개 시도)
- 이 작업은 §15(자기참조 vs 정당한 타조 인용, 여전히 미해결)와 **다른** 결함을
  다룬다 — 헷갈리지 않게 분리해서 적는다.

## 1. 작업 목표

기존에 population B(참조로 제외된 문장)만 Codex 표본검수를 받았고, population A
(인용이 막힌 조항)는 "왜 막혔는지"(S1/S3/S4 어느 신호인지)를 Codex 에게
안 알려준 채 검토해서 판정 신뢰도가 낮다는 게 확인돼 있었다(직전 4라운드
디버그 리포트). 이번엔 순서를 바꿔 **내가 먼저 원인까지 보고 직접 판정**한
뒤 Codex 에게 반박(감사)을 맡겼다.

## 2. 실제 수행 내용

1. `structure_faults()` 를 그대로 복제하되 어느 신호(S1_aba/S3_embedded/
   S4_annex)가 각 조항을 gate 했는지 태깅하는 스크립트를 짜서 전량
   재빌드 — 모집단 S1_aba 1,871 · S3_embedded 68 · S4_annex 4(전수).
2. 시드 고정 무작위 표본(S1_aba 20 · S3_embedded 20 · S4_annex 4=전수) 뽑아
   원문 문맥과 함께 내가 직접 읽고 판정.
3. 발견한 것 두 가지를 Codex 에게 반박시켰다(읽기 전용 감사, 코드 미제시
   전 상태):
   - **S4_annex 모집단 4건 전부가 "<붙임2>에서 정한 이율로…"(정상 문장
     중간 인용)를 부록 시작으로 오판한 것** — Codex 확인: 오탐 맞음. 단,
     내가 제안한 수정안(정규식 매치 직후 조사 검사)은 실제로는 작동
     안 하는 코드였음을 지적(`_ANNEX` 가 `<붙임` 까지만 소비해서 뒤에
     "2>"가 남음) — 대신 `to_clauses.py` 에 이미 있는
     `_ANNEX_HEAD`/`_ANNEX_REF_TAIL`(닫는 괄호까지 확인 + 참조꼬리 판정)을
     재사용하라고 제안.
   - **S3_embedded 표본 20건 중 13건이 "정한→정하는" 활용형 불일치로 생긴
     오탐**(dbins "43. 분쟁의 조정" 표준조항 반복) — Codex 확인: 원인분석
     맞음. "정하는" 하나만 완결형으로 추가하는 건 예전에 되돌린 "정하"
     열린 어간 확장과 위험 프로파일이 다르다(노출 면적이 훨씬 좁음)고
     확인. 단, "13/20=65%가 전체 개선"이라는 내 외삽은 반박됨 — 같은
     표준조항이 반복된 군집 표본이라 유효 표본 수가 훨씬 작고, 실제
     개선량은 S3 이벤트 수가 아니라 `gated_clause_count` 로 봐야 한다고
     지적.
4. Codex 감사를 반영해 수정:
   - `scripts/eval/struct_audit.py` — S4 게이트가 자체 `_ANNEX` 대신
     `to_clauses.py` 의 `_ANNEX_HEAD`/`_ANNEX_REF_TAIL` 을 import 해서 씀
     (S3 가 `_ARTICLE`/`_REF_TAIL` 을 재사용하는 것과 같은 원칙 — "정답
     소스를 다시 베끼지 않는다").
   - `scripts/extract/to_clauses.py` — `_REF_TAIL` 에 "에서\s*정하는" 을
     "에서\s*정한" 옆에 완결형으로 추가(열린 어간이 아님).
5. 회귀 테스트 3개 추가(`tests/test_to_clauses_section_boundary.py`) —
   `test_ref_tail_matches_jeonghaneun_inflection_not_just_jeonghan`,
   `test_annex_gate_reuses_annex_head_ref_tail_not_bare_marker`,
   `test_annex_gate_still_catches_a_real_swallowed_annex`(회귀 방지).
   둘 다 되돌리면 실제로 실패함을 확인(load-bearing).

## 4. 미해결 이슈·다음 작업 제안

  미해결이다 — 계획서 §3-1, 디버그 리포트 참조.

  확인된 4건(samsunglife "제46조 특칙의 적용"→"제47조 피보험자" 패턴)과
  같은 종류일 가능성이 높으나 전수 재검증은 안 했다.

  계획서 §3-2.

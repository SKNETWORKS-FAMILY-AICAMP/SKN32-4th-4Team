## 1. 무엇이 없었나

v4 의 `_PARA` 는 항과 호를 **같은 것으로 봤다.**

```python
_PARA = re.compile(r"(?:^|\n)\s*([①-⑳]|\d{1,2}\.)\s")   # ① 과 1. 이 같다
...
"paragraph_count": max(len(paras) - 1, 0)               # 개수만 세고 버린다
```

약관의 층은 **조 > 항(①②③) > 호(1./가./1)) > 목((1)/(가))** 이다.
둘을 섞으면 `paragraph_count` 가 항 수도 호 수도 아니고, **"제N조 제M항"을 조립할 수 없다.**

CLAUDE.md 0장이 요구하는 건 "몇 쪽"이 아니라 **"제○조 몇 항"** 이다.

---

## 2. 무엇을 만들었나

조항마다 `paragraphs[]` 를 붙였다.

```json
{ "clause_no": "제4조", "title": "보상하지 않는 사항",
  "citation": "제4조(보상하지 않는 사항)",
  "statute": false,
  "paragraph_count": 6, "unresolved_paragraphs": 0,
  "paragraph_no_ambiguous": true,
  "paragraphs": [
    { "paragraph_no": 1, "marker": "①",
      "citation": "제4조(보상하지 않는 사항) 제1항",
      "char_length": 846,
      "items": [ {"item_no": "1", "offset": 42, "length": 94}, … ] } ] }
```

**제4조 제1항 제1호 = "피보험자가 고의로 자신을 해친 경우"** — 면책 사유를 이 단위로 인용한다.

### 설계에서 지킨 것

| | 왜 |
|---|---|
| `items` 를 **위치(offset/length)** 로 준다 | 본문을 복사하면 산출물이 두 배가 되고 두 벌이 어긋난다 |
| 조 단위 `text`·`content_hash` 를 **안 바꿨다** | 기존 색인·해시가 그대로 유효해야 한다 |
| 항 번호를 못 읽으면 `paragraph_no=null` | **지어내지 않는다.** 틀린 "제10항"은 없는 것만 못하다 |
| 줄머리 마커만 인정 | 본문 중간의 `①` 은 인용이거나 표 기호다 |

## 3. 코덱스가 잡은 것 — 셋 다 실재

### 3-1. `[가-하]` 는 **10,585자**를 매칭한다 ★

```python
_ITEM_MARK = re.compile(r"^[ \t]*(\d{1,2}\.|[가-하]\.|\d{1,2}\))[ \t]")
```

정규식의 `-` 는 **유니코드 코드포인트 범위**다. `가`(U+AC00)~`하`(U+D558) 사이
한글 음절 전부가 걸린다. 확인:

```
가 True · 나 True · 다 True … 값 True · 강 True · 곱 True · 약 True
범위 크기: 10,585자
```

**아무 한글 한 글자 + 마침표**가 호가 됐다. 문장이 한 글자로 끝나고 마침표가 오면 전부.
가나다 호 기호는 **14개뿐**이므로 그대로 나열하도록 고쳤다.

### 3-2. 조 머리 자신이 호로 잡힌다

특별약관 조 머리는 `1. (보장종목)` 꼴이라 `_ITEM_MARK` 에 그대로 걸렸다.
조 본문의 맨 앞은 언제나 그 조의 머리이므로 건너뛰게 했다.

### 3-3. 숫자 호 뒤의 `가.` 가 목(目)인데 호로 잡혀 **범위가 잘린다**

```
1. 제1차 의료급여기관              ← 호
   가. 「의료법」 제33조 …          ← 목 (호 아래)
   나. 제1항제2호부터 …             ← 목
2. 제2차 의료급여기관 …             ← 호
```

전부 호로 세면 `1.` 호의 범위가 `가.` 에서 잘린다.
약관 조판은 한 층에 한 표기를 쓰므로, **한 항 안에서 우세한 표기만 호로 인정**하고
나머지는 그 호의 본문 안에 남긴다(목은 나누지 않는다).

효과: 호 **825,965 → 538,319**. 287,646개가 목이었다.

> 셋 다 실측으로 재현했고 단위 시험을 붙였다(`[가-하]` 7건 · 조 머리 1건 · 목 분리 1건).

## 4. 계획에 없었지만 고쳐야 했던 것 — 인용 안전성

인용 정확도 감사를 돌리다 표본에서 이런 인용이 나왔다.

```
"단체취급 특별약관 제651조(고지의무위반으로 인한 계약해지) 제1항"
"제15조(개인정보의 수집·이용) 제2항"
"제657조(보험사고발생의 통지의무) 제1항"
```

**그런 약관 조항은 없다.** 제651조는 **상법**, 제15조는 개인정보보호법이다.
약관 뒤에 붙는 인용 법령 원문이 조항으로 잡혔고, 부(部) 이름이 직전 특별약관에서
안 바뀌어 그대로 따라붙었다.

실측(표본 300문서): 조 번호 100 이상 3,086개 중 **604개가 약관 부 이름**을 달고 있었다.

### 문서가 스스로 표시한 경계를 읽는다

추정하지 않는다. 보험사별 표기를 실측(표본 250문서)했다.

| 표기 | 문서 |
|---|---|
| `[법규5] 상법` | 삼성화재 1,494 · 현대해상 196 · DB 50 · NH손보 37 · KB 22 |
| `인용법·규정` | 현대해상 163 · 롯데 5 · 메리츠 2 |
| `○ 개인정보보호법` | 흥국생명 81 · 현대해상 11 |

이 줄을 만나면 부(部)를 **법령명**으로 바꾸고 `statute=true` 를 붙인다.

```
삼성화재 3c67b035a1bc:  법령 조항 77개 → section="의료법"·"상법", statute=true
                        약관 조항 중 조 번호 100 이상 = 0개  (수정 전 5개 이상)
```

전량: **`statute` 조항 33,257개(15.8%)** 가 약관 조항과 분리됐다.

> `○` 뒤에 **공백을 요구**한다. 없으면 `○보험금지급안내및심사절차조회방법` 이
> `…방법` 의 `법` 때문에 걸린다(실측).

### 부수 수정 — `4-1.` 이 `4.1` 로 나가고 있었다

`label = f"{no}." + sub` 로 조립해 원문에 없는 번호가 됐다. `4-1.` 로 고쳤다.

## 6. 남은 문제

| 항목 | 상태 |
|---|---|
| **인용이 모호한 조항 9,838개(4.7%)** | 한 조 안에서 항 번호가 되풀이된다(보장종목마다 ①이 재시작). `paragraph_no_ambiguous=true` 로 **표시만** 한다. 특정하려면 목(目) 층까지 내려가야 하는데 안 한다 — 판정은 이 값을 보고 항 번호만으로 근거를 대면 안 된다 |
| 항이 없는 조항 38.9% | 한 문장짜리 조항·법령 조문이 많아 정상 범위로 보이나 **표본 검수를 안 했다** |
| 번호 못 읽은 항 3,340 | 미매핑 보조 PUA(⑩ 이상). `to_page_json` 이 복구를 안 한 결과라 여기서는 셀 수만 있다 |
| 인라인 항 마커 | DB손보 일부는 `①` 이 문장 중간에 온다. 못 잡는다(잡으려다 오탐 만드느니 놓치고 센다) |
| `_ARTICLE` 제목 중첩 괄호 절단 | `제18조(보험료의 납입이 연체되는 경우 납입최고(독촉)` 로 잘려 인용에 노출된다. **머리 검출은 정상** |
| 혼합 페이지 6쪽 | 1단계에서 넘어온 미해결. 3단계(추출)와 묶는다 |
| 코덱스 최종 결론 | **못 받았다.** 내가 s5 를 계속 덮어써서 코덱스가 읽는 스냅샷이 `679 → 1,367 → 728` 로 흔들렸다. 코덱스가 그 사실을 지적했다. 지적 3건은 그전에 확정됐고 전부 반영했다 |

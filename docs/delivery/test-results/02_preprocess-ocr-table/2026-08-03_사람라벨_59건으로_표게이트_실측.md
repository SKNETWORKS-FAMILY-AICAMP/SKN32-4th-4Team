## 1. 이 라벨이 왜 중요한가

L1(정답셋 확장)이 막혀 있었다. 우리 후보 65개는 **라벨이 없고**, 내가 임계값을
맞출 때 쓴 것은 **내가 눈으로 고른 참 4 · 거짓 3** 이었다.
그 문턱을 전량에 적용했더니 통과분의 **80%가 본문**이었다.

이 파일은 **다른 사람이 원문을 보고 찍은 59건**이다. 편향이 다르다.

### 형식 — 유효한 JSON 이 아니다

```
★JSON 아님: Extra data: line 1 column 7 (char 6)
```

최상위 객체 없이 `"true": [...]` 가 반복되고 일부 줄은 `]` 가 빠졌다.
줄 단위로 복구해 **61건**, `(sha12, page)` 중복 2건을 빼 **59건**을 들여왔다.
복구 실패 줄 **0**, 코퍼스에 없는 문서 **0**.

## 3. 오탐 20건이 어떻게 생겼나

원문을 열어 보면 세 부류다.

### ① 코드 목록을 열로 쪼갬 (`위험 코드가 나뉘어져야 한다`)

```
{'1': '비위험 21698', '2': '중위험 21700', '3': '고위험 21702'}
{'1': '21699',        '2': '21701',        '3': '21703'}
```

원문은 `비위험 21698 21699 / 중위험 21700 21701 / …` 인데
**세로로 읽어야 할 것을 가로로** 읽었다. 격자는 그럴듯하고 `word_coverage` 도 1.0 이다.

### ② 본문을 여러 열로 쪼갬 (`86c536ac20ac` p25, 6열)

```
{'1': '해지된 납입연체로 이내에 보험회사는 거절하거나',
 '2': '보험계약의 보험계약이 보험계약의 피보험자의 건강', …}
```

**한 문장이 여섯 조각으로 흩어져 어절이 뒤섞였다.** 2열 경로에서 이미 본 실패인데
**선 경로에서도 같은 일이 난다** — 안내문 상자의 세로 구분선을 열 경계로 잡는다.

### ③ 셀 병합·주석 혼입 (`쪼개져야 할 내용이 합쳐짐`, `'주)'가 잘못 들어감`)

사람이 남긴 사유 중 우리 지표에 **대응하는 것이 하나도 없다**:

| 사유 | 건수 |
|---|---:|
| 위험 코드가 나뉘어져야 한다 | 3 |
| 셀 분류가 잘못됨 | 3 |
| 쪼개져야 할 내용이 합쳐짐 | 2 |
| `주)` 글씨가 잘못 들어감 | 2 |

## 4. 한계 — 이 수치를 어떻게 읽어야 하나

- **라벨 단위가 `(문서, 쪽)`** 이다. 한 쪽에 표가 여럿이면 **어느 표를 보고 찍었는지 모른다.**
  그래서 그 쪽의 표를 전부 같은 라벨로 봤다. 실제보다 나쁘게 나올 수도, 좋게 나올 수도 있다.
- 참 표본이 **5건**이다. 이걸로 "정밀도 0.4" 같은 값을 말하지 않는다 — **분리도만** 말한다.
- `check` 3건은 적합에서 뺐다. `true` 로 반올림하지 않는다.
- 라벨은 **`_3rd_project_4` 의 전처리 산출물**을 보고 찍혔을 수 있다. 우리 s5 와 다른 판이면
  같은 쪽이라도 표가 다르다. **확인하지 못했다.**

## 4-2. 조치 — T9(본문 모양) 신호를 넣었다

`선` 경로에 **한쪽 문턱**을 걸었다. 참 5건의 최댓값 바깥에만 문턱을 둔다.

| 조건 | 문턱(참 최대) |
|---|---:|
| 셀 최대 길이 | > 84 |
| 문장부호 비율 | > 0.30 |
| 긴 셀(40자↑) 비율 | > 0.25 |

셋 중 하나라도 넘으면 **본문으로 본다.**

### 효과 (사람 라벨 기준)

| | 조치 전(페이지 JSON) | 조치 후(**조항 JSON**) |
|---|---:|---:|
| `true` 실림 | 5 / 5 | **4 / 5** |
| `false` 실림 | **22 / 51** | **5 / 51** |
| `false` 보류 | 33 / 51 | **46 / 51** |

**오탐이 22 → 5 로 줄었다(−77%).**

### ★빠진 `true` 1건은 T9 때문이 아니다

`e05cbfdbdf6d` p25. 그 표의 신호는 `is_table=True · prose=False` 로 **T9 를 통과했다.**
안 실린 이유는 따로 있다 — **그 쪽을 덮는 조항이 하나도 없다.**

표본 395 ok문서에서 **쪽의 17.1%(6,463/37,869)** 가 조항·부록 어디에도 안 덮인다
(목차 제외). 별건이라 따로 리포트했다 →
조항범위 밖 페이지 17% (내부 원본 참조: `debugs/2026-08-03_조항범위_밖_페이지_17퍼센트.md`)

### 남은 오탐 — 못 잡는다

거짓 20건 중 T9 가 잡는 것은 **9건(45%)** 이다. 나머지 11건은 셀이 짧다.

```
maxlen=9  sent=0.00 longr=0.00     ← `비위험 21698` 코드 목록
maxlen=52 sent=0.00 longr=0.04
```

**세로로 읽어야 할 코드 목록을 가로로 읽은 것**이라 텍스트 통계로는 표와 구분되지 않는다.

★**문턱이 약하다.** 참 표본이 **5건**뿐이라 여섯 번째 참이 이 선을 넘을 수 있다.

## 5. 그래서 무엇을 할 것인가

### 지금 하지 않는 것

- **T7·T8 임계값을 사람 라벨에 다시 맞추기** — 겹치는 신호로는 문턱을 만들 수 없다.
  억지로 고르면 참 5건 중 일부를 버리게 된다(재현율이 지금 완벽한데 그걸 깨는 셈).

### 해야 할 것

1. **`선` 경로에 새 신호가 필요하다.** 지금 신호는 전부 2열용이거나(T1~T6)
   다열 전용(T7·T8)이다. 오탐 20건 중 다수가 **2~6열**이다.
   후보: 세로 읽기 여부(①), 어절 파손(②) — ②는 T5 를 선 경로에도 붙이면 될 수 있다.
2. **참 라벨을 늘려야 한다.** 지금 5건이라 어떤 신호를 만들어도 검증이 안 된다.
   우리 후보 65개(`data/eval/table_labelset_candidates.jsonl`)에 라벨을 받는 것이 가장 싸다.
3. **`check` 3건을 확정한다.** 팀원이 원문 확인이 필요하다고 남긴 것이다.
4. `_3rd_project_4` 산출물과 우리 s5 가 같은 표를 보는지 확인한다.

# D1 — 페이지 JSON(s5) ↔ 조항 JSON(s6) 참조 무결성 검사 결과

- 날짜: 2026-08-03
- 계획서: `docs/plans/2026-08-03_1200_표추출_한계5종_해결계획.md` (내부 원본 참조: `../plans/2026-08-03_1200_표추출_한계5종_해결계획.md`) §0 의 **D1**
- 대상: **1,367 문서쌍 전량** (표본 아님)
- 결론: **확정 위반 0건.** s5 와 s6 은 정합하다. 검수 신호 A2 2,239건은 **측정 방식의
  경계 효과**로 확인됐다(§4.2). 다만 이 검사는 "둘이 서로 맞는가"만 보며,
  **둘이 같이 틀린 것은 못 잡는다**(§6).

---

## 1. 작업 목표

전처리 산출물이 두 층인데 **정합을 아무도 검사하지 않았다.**

```
data/extracted/{보험사}/s5_pymupdf-1.28.0/{sha12}.json          ← 페이지
data/structured/{보험사}/s6_pymupdf-1.28.0/{sha12}.clauses.json ← 조항 (s5 에서 만든다)
```

s6 은 s5 를 읽어 만든다. 그런데 **한쪽만 다시 도는 일이 실제로 일어난다** —
여러 세션이 같은 저장소에서 동시에 일하고(계획서 §0), 원격 GPU 상자에 페이지 추출만
나눠 넘긴 전례가 있다(RULE §3.5). s5 가 갱신되고 s6 이 옛 판으로 남으면 조항은
**자기가 가리키는 쪽이 이제 무엇인지 모른 채** 살아 있다.

이 서비스에서 그건 조용한 오답이다. 판정문은 "약관 몇 쪽 제몇조"를 대는데,
그 쪽 번호가 원문 밖이거나 다른 내용을 가리켜도 **아무 데서도 걸리지 않는다.**

## 2. 수행 내용

### 변경 파일

| 파일 | 상태 | 내용 |
|---|---|---|
| `scripts/eval/consistency_check.py` | **신규** | 28종 검사 + 자기검사(`--selftest`) |
| `docs/reports/2026-08-03_D1_산출물_정합검사_결과.md` | **신규** | 이 문서 |

그 밖의 파일은 **건드리지 않았다.** 산출물(s5·s6)도 수정하지 않았다 — 읽기 전용 검사다.

### 검사 설계

★**두 등급으로 나눈다.** `struct_audit.py` 의 "확정 신호 / 검수 우선순위 신호"와 같은 원칙이다.

- **확정 위반** — 구조상 있을 수 없다. 하나라도 나오면 재생성이 어긋난 것이다
- **검수 신호** — 오탐이 섞인다. 세어서 보고하되 **자동 실패로 쓰지 않는다**

★**단일 종합 점수를 만들지 않는다.** 정답셋 없이 가중치를 정당화할 수 없다.

### 검사 목록 (28종)

| 계열 | 코드 | 무엇을 보는가 |
|---|---|---|
| 짝 맞음 | P1·P2·P3 | s5 만 있음 / s6 만 있음 / 보험사 폴더 불일치 |
| 원본 대조 | H1·H2 | `source.sha256` 양쪽 일치 / 파일명 sha12 = sha256 앞 12자 |
| 스키마·판 | V1·V2·V3·V4 | `schema_version` 5·6 / `extractor` 에 `1.28.0` / 양쪽 추출기 문자열 일치 |
| 페이지 수 | G1·G2·G3 | `stats.pages` = 실제 / s6 = s5 / 쪽 번호 1..N 연속 |
| 페이지 범위 | L1·L2·L3·L4 | locator 형식 / 원문 범위 안 / `page_to ≥ page_from` / `toc_pages` 범위 |
| 표 참조 | T1~T8 | `tables[].page` 범위·`table_id` 실재·접두 일치·조항 범위 안·게이트 경로·**내용 일치**·`tables_on_pages` 키와 개수 |
| 표 역방향 | **T9** | s5 의 `선` 표가 조항 범위 **안**인데 s6 에 안 실렸는가 |
| 보류 수 | W1 | `stats.tables_withheld_unverified` = s5 실측 |
| 본문 앵커 | A1·A2 | 조항 앞 16자가 s5 문서에 있는가 / `page_from` 쪽에 있는가 |

**과제에 없었지만 데이터를 보고 추가한 것 (§"그 밖에 필요하다고 판단한 검사")**

- **T6 내용 일치** — `table_id` 만 맞고 값이 갈리면 *표는 있는데 다른 표*다.
  `rows`·`cols`·`word_coverage`·`method`·`panel`·레코드 수를 s5 원본과 대조한다.
- **T8 `tables_on_pages` 개수 대조** — s6 이 기록한 쪽별 표 개수를 s5 실측과 맞춘다.
- **T9 역방향** — ★T1~T6 은 **s6 → s5** 만 본다. 그것만으로는 "s6 이 아무 표도
  안 실었다"가 **만점으로 나온다.** 실제로 그런 착시가 있었다 —
  `table_coords` 는 F1 1.000 인데 부르는 곳이 평가 스크립트뿐이었다.
  그래서 **s5 → s6** 도 본다.
- **W1 보류 수 대조** — ★s5 가 조용히 갈렸는지 잡는 **가장 값싼 전면 지문**이다.
  s6 이 stats 에 적어 둔 "게이트에서 거른 표 수"는 s5 의 `tables_coords` **전량**에서
  계산된 값이라, s5 가 한 장이라도 다시 추출되면 어긋난다.
  locator·표 참조가 다 맞아도 여기서 걸린다.
- **A1·A2 본문 앵커** — 쪽 번호가 범위 안이라는 것과 *그 쪽에 그 내용이 있다*는 것은
  다른 말이다. 조항 본문 앞 16자가 실제로 `page_from` 쪽 텍스트에 있는지 본다.
- **V4 추출기 문자열 일치** — 같은 폴더에 다른 판이 섞이는 것을 잡는다(RULE §3.5-4).

## 3. 검증 방법 — ★"0건"을 그대로 믿지 않았다

위반 0건이라는 보고는 **검사가 죽어 있어도 똑같이 나온다.** 실제로 이 저장소에서
그런 일이 있었다 — 판별 신호를 만들어 놓고 페이지 JSON 에 키를 안 실어
`is_table` 이 항상 `None` 이었다(계획서 §9). **신호가 아무 일도 하지 않고 있었다.**

그래서 세 겹으로 확인했다.

### 3.1 자기검사 `--selftest` — 25/25 통과

성한 문서 한 쌍을 메모리에서 **일부러 망가뜨려** 각 검사가 걸리는지 본다.

```
$ export PYTHONIOENCODING=utf-8
$ python -m scripts.eval.consistency_check --selftest
[자기검사] 기준 문서 002496fe7873 · 성한 상태 위반 0건
  ✓ H1  s6 의 sha256 을 (파일명 뒤에서) 한 글자 바꾼다
  ✓ V1  s5.schema_version 을 옛 판으로 되돌린다
  ✓ G1  s5 마지막 페이지를 지운다 (stats 는 그대로)   (함께 걸림: A1,L2,W1)
  ✓ G3  s5 페이지 번호를 0-based 로 밀어 버린다   (함께 걸림: A2,T2,T8)
  ✓ T2  s5 에서 그 표를 지운다 (s6 은 계속 가리킨다)   (함께 걸림: W1)
  ✓ T9  s6 에서 실린 표를 전부 떼어 낸다 (s5 에는 그대로 있다)
  ✓ A2  본문은 그대로 두고 page_from 만 다른 쪽으로 옮긴다
  … (전체 25종)
  ★자기검사가 덮지 못한 검사: ['P1', 'P2', 'P3']
    (파일 배치 검사다 — 목록 단계에서 돌며 한 쌍 안에서 재현할 수 없다)
[자기검사] 25/25 통과
```

★**자기검사가 자기 자신의 결함을 잡았다.** 초안의 H1 망가뜨리기는
`sha256` 첫 글자를 `0` 으로 바꿨는데 **하필 그 해시가 `0` 으로 시작해** 아무것도
안 바뀌었다. `✗ H1 → 걸린 것: 없음` 으로 드러나 13번째 글자를 바꾸도록 고쳤다.
망가뜨리기가 **실제로 망가뜨렸는지**도 확인해야 한다는 뜻이다.

★P1·P2·P3 은 파일 배치 검사라 한 쌍 안에서 재현할 수 없다. **덮지 못한다고 정직하게 적는다.**

### 3.2 조건 뒤집기 — 원본 코드에서 직접

자기검사는 *데이터*를 망가뜨린다. *코드*가 도는지도 따로 봤다.
`T2`·`T5`·`L2` 세 조건을 소스에서 뒤집고 실제 데이터 120문서에 걸었다.

```
★ L2    19,847 건 · 문서   120(100.0%)   (뒤집음: 범위 '안'일 때 걸리게)
★ T2        91 건 · 문서    42( 35.0%)   (뒤집음: table_id 가 '있을' 때 걸리게)
★ T5        91 건 · 문서    42( 35.0%)   (뒤집음: 신뢰 경로'일' 때 걸리게)
확정 위반 합계 20,029건
```

★**뒤집은 건수가 분모와 정확히 같다.**
`L2 19,847 = clauses 18,998 + annexes 849`, `T2·T5 91 = 실린 표 참조 91`.
즉 원래의 0 은 **전량을 보고 난 0** 이지, 검사가 안 돈 0 이 아니다.
확인 후 **원복했고**, 원복 뒤 다시 0건·자기검사 25/25 를 확인했다.

### 3.3 분모를 함께 낸다

"0건"이 무엇을 보고 난 0인지 밝힌다(CLAUDE.md §4 — 숫자를 인용할 때 분모를 함께 적는다).


### 4.2 검수 신호 — A2 2,239건 (문서 775건 · 56.7%)

**조항 본문 앞 16자가 `page_from` 쪽에 없다 (문서 안엔 있다).**

★**정합 결함이 아니라 측정의 경계 효과다.** 2,239건 전수를 분해했다.

| | 건수 | 비율 |
|---|---:|---:|
| 조 머리는 `page_from` 에 **있음** (앞 8자 이상 일치) — 쪽 경계에서 잘림 | **2,211** | 98.7% |
| 앞 4~7자만 일치 (조 머리가 짧은 경우) | **28** | 1.3% |
| `page_from` 에 흔적 없음 | **0** | 0.0% |

전형적인 모습 — 쪽 번호 각주가 조 머리와 본문 사이에 낀다.

```
제6조[보험금의지급절차]49①…     ← '49' 는 쪽 번호 각주
제2조(정의)-73-이법에서사…      ← '-73-' 는 쪽 번호 각주
```

즉 `page_from` **은 맞다.** 조 머리는 그 쪽 맨 아래에 있고 본문이 다음 쪽으로 넘어갈 뿐이다.
그래서 A2 를 **자동 실패로 쓰지 않는다.** 다만 검사에서 빼지도 않는다 —
쪽 번호가 통째로 밀리는 사고를 잡을 유일한 검사이기 때문이다
(자기검사 A2 항목이 그것을 증명한다).

### 4.3 ★검사 쪽 오진 하나 — 기록해 둔다

첫 전량 실행에서 **A1(확정 위반) 이 124건** 나왔다. 전부 같은 모양이었다.

```
015c910c03ae clauses[13] 제34조(보험계약대출) p5 · '제34조(보험계약대출)06기타'
023fc5ca39d4 clauses[14] 제35조(보험계약대출) p5 · '제35조(보험계약대출)06기타'
…
```

원인은 **데이터가 아니라 검사였다.** `to_clauses.py:928` 이 조항 본문을 모을 때
`if p in toc_pages: continue` 로 목차 쪽을 건너뛴다. 내 앵커 검사는 s5 를 **전 쪽**
이어 붙여 비교해서 **이어붙임 지점이 달랐다.** 목차 바로 앞 조항이 통째로
"원문에 없다"로 찍혔다.

생성기와 같은 규칙(목차 쪽 제외)으로 고친 뒤 **A1 = 0건**.

> ★**위반이 나오면 데이터를 의심하기 전에 생성기와 같은 규칙으로 재고 있는지 먼저 본다.**
> 그대로 보고했으면 "조항 124개가 원문 밖을 가리킨다"는 **없는 결함**을 띄울 뻔했다.

## 5. ★부수 발견 — 상태표의 표 관련 숫자가 디스크와 다르다

D1 을 돌리며 분모를 세다가 나왔다. **정합 위반은 아니지만 기록된 수치가 틀렸다.**
RULE §4.0-5(내가 잘못 보고했던 수치의 정정)에 따라 적는다.

| 항목 | 문서 기록 | **디스크 실측** | 근거 |

| 그 레코드 | **12,561** | **8,849** | 〃 |
| 보류(`2열짝짓기`) | **162,170** | **109,421** (s6 stats 합계 109,192 + fallback 9문서 229) | 〃 |
| s5 `선` 표 (원천) | — | **813** (레코드 9,823) | |

재현:

```bash
export PYTHONIOENCODING=utf-8
python -m scripts.eval.consistency_check      # '검사 모수' 줄에 분모가 다 나온다
```

★**s5 의 `선` 표 813개 중 613개만 s6 에 실린다.** 나머지 200개를 전수 분류했다.

| | 건수 | 판정 |
|---|---:|---|
| 조항·부록 페이지 범위 **밖** (표지·안내문 등 앞머리 쪽) | **189** | 정상 — 어느 조항에도 속하지 않는 쪽이다 |
| 목차 쪽 | **11** | 정상 — s6 이 의도적으로 제외한다 |
| **범위 안인데 누락** | **0** | ★없다 (= T9 0건) |

즉 **누락이 아니라 커버리지**다. 다만 이 200개는 판정이 근거로 들 길이 없으므로
"조항에 실린 표"를 말할 때 813 이 아니라 **613** 을 써야 한다.

> 이 표를 CLAUDE.md·계획서에 반영하는 것은 **D3(문서 기록 = 디스크 실측)의 몫**이라
> 이 세션에서는 고치지 않았다(RULE §2 — 계획서 범위 밖 임의 작업 금지).
> **D3 담당자는 위 표를 그대로 쓰면 된다.**

## 6. ★이 검사가 못 하는 것 (한계를 숨기지 않는다)

1. **둘이 같이 틀린 것은 못 잡는다.** 이 검사는 "s5 와 s6 이 **서로** 맞는가"만 본다.
   s5 가 표를 잘못 뜯었고 s6 이 그것을 충실히 옮겼으면 **전 항목 0건이 나온다.**
   표 추출 정확도는 계획서 **L1·D5**(정답셋 확장 → precision/recall)의 몫이다.
2. **원본 PDF 를 열지 않는다.** `source.sha256` 이 s5·s6 에서 같은지만 보고,
   그 해시가 `data/raw/` 의 실제 파일 해시와 같은지는 **확인하지 않았다.**
   (약관 원문은 커밋하지 않으므로 별도 검사가 필요하다 — §7 제안)
3. **표 검사의 분모가 얇다.** T1~T6 이 보는 것은 **1,313개 참조**뿐이다.
   `2열짝짓기` 게이트가 닫혀 있어(계획서 §8) s5 좌표표 110,234개 중 1.2% 만
   s6 에 실린다. **게이트를 열면 T 계열을 다시 재야 한다.**
4. **A2 의 오탐을 코드가 자동으로 가르지 못한다.** 98.7%가 쪽 경계 효과라는 것은
   이 리포트를 쓰며 **별도 분석으로** 확인했다. 스크립트는 등급만 나눈다.
5. **P1~P3 은 자기검사가 덮지 못한다** (§3.1).

# s6 전량 재생성이 색인에 무엇을 했나 — 실측

다른 세션이 `s6_pymupdf-1.28.0` 을 전량 재생성했다(2026-08-26 17:06~17:07,
[실행결과](../02_preprocess-ocr-table/2026-08-26_1712_s6_전량재생성_실행결과.md)).
**DB·색인 쪽 영향만** 실측한다. 산출물 자체의 품질 판단은 그쪽 리포트에 있다.

숫자는 전부 이 저장소에서 다시 셌다 — 그쪽 리포트 값을 옮겨 적지 않았다.

---

## ☠0. 정정 (2026-08-27) — 아래 §4 의 **논거가 틀렸다**

§4 는 「같은 `(문서, 순번, 종류)` 자리의 **89.3%가 다른 조항을 가리킨다**」를
이 작업의 핵심 근거로 삼았다. **그 비교 자체가 성립하지 않는다.**

- **산출물의 `ordinal`** 은 그 문서의 **모든** 조항에 0부터 빠짐없이 매긴 번호다.
- **색인의 `ordinal`** 은 인용 게이트를 **통과한 행만** 골라 0부터 **촘촘히 다시** 매긴다
  (`assign_ordinals`: `row_number() OVER (PARTITION BY source_kind
  ORDER BY page_from, qualified_no, content_hash)`).

즉 **애초에 다른 번호 체계**다. 게이트로 하나만 빠져도 그 뒤가 통째로 밀린다.
실측 규모: 산출물 자리 **196,355** vs 색인 자리 **167,482** — 게이트가 **28,873자리**를 뺀다.

실제 예 (`7c09b79a72c8`): 산출물 조항 179 · 색인 175(게이트 탈락 4) →
**순번 7부터 어긋난다.** 낡음과 무관하게 어긋나는 것이 정상이다.

확인 사살: 낡은 행을 **전부 지웠다고 가정**하고 같은 규칙으로 다시 매겨 봐도
일치율은 **71.32%** 에 그친다. 100%가 되지 않는다 — 목표로 삼을 수 있는 수가 아니었다.

### 그래서 무엇이 남나 (이건 그대로 유효하다)

- §3 의 **신선도** 측정은 **해시**로 잰 것이라 영향받지 않는다 —
  1,172/1,302 문서가 산출물에 없는 해시를 들고 있었다.
- §5 의 **인용가능 발생의 32.6%가 현행 산출물에 없는 내용**도 해시 기준이라 유효하다.
  이것이 §0 위반의 진짜 근거다.
- §5.1 의 **발급된 인용 0건**도 유효하다. 다만 이유를 바로 적으면 —
  색인 순번은 **그 문서에서 색인된 행 집합이 바뀌면 언제든 바뀐다.**
  그래서 재색인은 `occurrence_id` 를 무효화한다. 발급분이 0이라 피해가 없을 뿐이다.

★**교훈**: 두 체계의 번호를 같은 이름(`ordinal`)으로 부른다고 같은 뜻이 아니다.
  비교하기 전에 **무엇을 세는 번호인지**부터 확인했어야 했다.

## 4. ~~★★가장 중요한 것 — 수록 순번이 밀렸다~~ ☠**논거 무효 — §0 을 읽을 것**

> 아래는 **틀린 근거**다. 지우지 않고 남긴다 — 무엇을 어떻게 잘못 쟀는지가
> 다음 사람에게 필요하기 때문이다. **인용하지 말 것.**

`occurrence_id` 는 `릴리스:sha256:source_kind:**순번**` 이다. 순번은 **자리**지 이름이 아니라서,
앞쪽 조항 하나가 합쳐지거나 갈라지면 **그 뒤가 전부 한 칸씩 민다.**

같은 `(문서, 순번, 종류)` 자리 **184,801** 개를 대조했다:

| | |
|---|---|
| 내용 그대로 | 19,759 (**10.7%**) |
| ★★내용이 바뀜 | **165,042 (89.3%)** |
| 색인에만 있는 자리 / 디스크에만 | 11,359 / 8,237 |

### 4.1 「일정하게 밀린 것」이 아니다 — 확인했다

전체가 +1 같은 식으로 통째로 밀린 것이라면 되돌리기 쉽다. 그래서 문서마다
**-5~+5 칸 이동을 다 넣어 보고 95% 이상 설명되는 이동이 있는지** 봤다.

- 일정 이동으로 설명되는 문서: **113** (전부 `+0`, 즉 원래 안 바뀐 문서)
- ★★**어떤 일정 이동으로도 설명 안 되는 문서: 1,181 / 1,294**

### 4.2 「해시 계산 방식이 바뀐 것」도 아니다 — 확인했다

내용이 같은데 해시만 달라졌을 가능성을 배제하려고 **본문을 직접 대조**했다
(무작위 40문서 · 224자리):

| | |
|---|---|
| ★본문이 실제로 다름 | 150 |
| 해시 같음 | 51 |
| 색인에 그 자리 없음 | 13 |
| 본문 공백만 다름 | 10 |

실제 예 (`5097a7755861` #73):

```
옛 색인 : 제1조(특별약관의 체결 및 효력) …
새 산출물: 제2조(특별면책조건의 내용) …
```

**같은 자리가 다른 조를 가리킨다.** A-B-A 재진입 오탐이 없어지면서 헛갈린 분할이
사라졌고, 그 뒤 조항이 통째로 당겨진 결과다. 산출물이 좋아진 것이 맞고,
**색인이 낡은 것이 문제**다.

## 5. 판정 안전 영향

| | |
|---|---|
| 색인의 인용가능 발생 | 188,850 |
| ★그중 **현행 산출물에 없는 내용** | **61,599 (32.6%)** |
| ★그중 **현행에서 인용금지로 바뀐** 내용 | 544 |

544건은 §0 에 정면으로 걸린다 — 지금 코드가 「이건 인용하면 안 된다」고 판정한 조항을
색인은 **인용 가능**으로 들고 있다.

### 5.1 ★그런데 이미 발급된 인용은 0건이다

순번이 밀리면 **어제 발급한 판정의 근거가 다른 조항을 가리킨다** — 이건 코드 주석이
이미 경고해 둔 위험이다(`pgvector_clause_index.py:885`). 실제 피해가 있는지 세어 봤다:

```
core.clause_reference               0행
app.assessment_clause_citation      0행
```

**0행이다.** 판정 결과가 아직 원장에 안 쌓이고 있어서 **소급 피해자가 없다.**
지금이 순번이 통째로 바뀌어도 되는 **유일하게 싼 시점**이다.

## 7. 판단 — 지금 재적재할 것인가

★**한 가지 걸리는 것이 있다.** `s5L→to_clauses 연동 계획` (내부 원본 참조: `../plans/2026-08-26_1600_s5L_레이아웃_to_clauses_연동_계획.md`)
이 진행 중이다. 레이아웃 신호가 조 경계 판정에 들어가면 **s6 는 또 한 번 전량 바뀐다.**
그러면 23,782개 임베딩이 한 번 더 필요하다.

그럼에도 **지금 재적재하는 쪽**을 권한다:

1. 지금 색인은 **인용가능이라고 말하는 것의 32.6%가 현행에 없는 내용**이다. §0 위반이 이미 진행형이다.
2. **소급 피해가 0인 지금**이 순번을 바꾸기에 가장 싸다. 판정 원장이 쌓이기 시작하면 이 창은 닫힌다.
3. 임베딩은 한 번 더 들지만, 65.8% 재사용률이 유지되면 두 번째는 더 싸다.

★단, **이건 GPU 를 쓰는 큰 작업이고 s5L 일정과 겹친다** — 실행 시점은 사람이 정할 일이라
이 리포트까지만 하고 재적재는 하지 않았다.

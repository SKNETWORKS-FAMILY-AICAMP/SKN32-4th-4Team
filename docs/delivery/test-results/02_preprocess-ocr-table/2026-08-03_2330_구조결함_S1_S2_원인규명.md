## 0. 결론 셋

1. **S1(A-B-A 재진입 4,613건)의 87.2% 는 세 헤더가 다 진짜다.** 헤더를 잘못 찾은 게 아니라

   진짜 추출 누락은 **2,235건(8.1%)** 뿐이다.
3. 두 진단 모두 **정답셋 없이** 나왔다. 원본 PDF 를 다시 열어 분할기가 안 보는 것으로 확인했고,
   음성 대조군으로 탐지기가 헐겁지 않음을 보였다. **다만 게이트 규칙 변경은 표본 사람 판정이 있어야 한다.**

## 2. 방법 — 순환논증을 피했다

조 머리 분할기는 s5 의 `pages[].text` 를 보고 헤더를 찾는다.
**그 text 로 "헤더가 있나"를 물으면 찾아낸 것은 언제나 있다.** 답이 정해진 질문이다.

그래서 **PDF 를 span 단위로 다시 열어** 분할기가 안 보는 것으로 확인했다 —
글자 크기·굵기·x 좌표·표 영역.

### 음성 대조군

| 시험 | 결과 |
|---|---|
| S1 — 있을 리 없는 번호(`제997조`)로 탐색 | **0/300 (0.0%)** |
| S2 — 빠진 번호 + 500 으로 탐색 | **0.0%** |

탐지기가 헐거워서 다 찾은 게 아님이 이걸로 확인됐다.

### 자기 대조

두 사건 추출기 모두 **재계산한 사건 수가 산출물의 `structure_faults` 와 문서별로 전부 일치**한다
(4,613 / 27,602). 판정 로직을 잘못 옮겼다면 여기서 깨진다.
번호 파싱은 `to_clauses._clause_num` 을 **import** 한다 — 복제하면 갈라진다(ARCH-003).

★코덱스가 독립적으로 잰 S1 관찰값과 **네 자리 다 일치**한다
(same_section 91.4 · a_titles_equal 71.8 · same_page 31.1 · any_table 61.7).

## 3. S1 — 고칠 곳은 조항 게이트가 아니라 부 경계 검출

현재 `struct_audit.structure_faults` 는 A-B-A 를 만나면
**B 와 두 번째 A 의 ordinal 을 끈다**(첫 A 만 살린다).
어느 경계가 거짓인지 A-B-A 만으로는 확정할 수 없다는 이유였다.

그런데 실측은 **87.2% 가 셋 다 진짜 헤더**라고 말한다.
새 특약이 시작해 번호가 재시작했는데 부 경계를 못 잡은 것이다.

```
사건 4,613 × 조항 2개 = 최대 9,226건이 꺼져 있다
그중 거짓 헤더로 확인된 것은 25건(0.6%)
```

**제안**: A-B-A 를 조항 게이트 신호에서 빼고, **부 경계 후보 신호**로 돌린다.
`header_in_table`(12.2%)만 조항 게이트에 남긴다.
★단, 이 변경은 **표본 사람 판정 뒤**에 한다(§6).

## 4. S2 — 전체 게이트는 틀렸다

코덱스가 1라운드에서 지적한 두 가지가 실측으로 확인됐다.

**① 전체 게이트 불가.** 27,602건을 끊으면 **최소 41.9% 는 멀쩡한 문서를 버린다.**

**② 게이트 대상이 다르다.** 번호가 진짜 빠졌어도 **A·B 는 잘못되지 않았다.**
이웃 ordinal 을 끄면 안 되고, 그 **페이지·문서의 completeness 를 게이트하고 재추출**해야 한다.
`B` 를 조항 게이트하는 건 **B 가 거짓 헤더로 확인된 경우에만**.

### 발췌본 신호

```
사건 50건 이상인 문서   220개
big_gap(5개 이상 연속)  16,189건 (58.7%)
unknown 사유 1위        "빠진 번호 12개 초과"
```

이건 개별 조항 결함이 아니라 **문서가 발췌본**이라는 신호다.
조항을 끌 일이 아니라 **문서를 "완결본 아님"으로 표시**할 일이다.

## 5. 사람 검수 파일과의 대조 (`_3rd_project_4/ai-1/table_true_false.json`)

들여오기는 `scripts/eval/import_table_labels.py` 가 이미 한다(59건 · 복구 실패 0).
여기서는 **우리 탐지 상태와 교차**한 결과만 남긴다.

| 사람 라벨 | 우리 method | `is_table` | 건수 |
|---|---|---|---:|
| **false** | 2열짝짓기 | **True** | **29** |
| false | 선 | null | 20 |
| true | 선 | null | 5 |
| check | 선 | null | 3 |

★**우리가 `2열짝짓기` 로 채택한 29건을 사람이 전부 `false` 로 판정했다. 참은 0건이다.**
`CLAUDE.md` 의 "2열짝짓기 162,170개는 미검증이라 보류" 결정이 **처음으로 사람 판정으로 뒷받침**됐다.

★**`선` 방식은 `is_table` 이 `False` 가 아니라 `null`(미채점)** 이다.
채점 게이트가 `2열짝짓기` 에만 걸려 있다. 처음에 `bool()` 로 읽어 "기각"으로 오분류했다가 정정했다.

사람이 `true` 라 한 5건을 s6 에서 직접 확인한 결과:

```
21b4c72eedc6 p105 → annexes 에 실림 (레코드 7)
443e03252244 p72  → 실림 (10)
914701875724 p176 → 실림 (9)
68e46cfdc2fd p80  → 실림 (4)
e05cbfdbdf6d p25  → ★안 실림
```

**4건은 이미 실려 있고, 진짜 누락은 1건이다.**

> ⚠ 이 표로 precision/recall 을 계산하면 안 된다. **표본 프레임이 없다** —
> 무엇에서 몇 개를 어떻게 뽑았는지가 없어 분모를 모른다.
> 라벨 단위도 **(문서, 쪽)** 이라 한 쪽에 표가 여럿이면 어느 표인지 모른다.

## 6. 아직 못 하는 것 — 사람이 필요한 지점

게이트 규칙을 바꾸려면 **precision 하한**이 필요하다(코덱스 권고: one-sided 95% 하한 ≥ 99%,
무오류 기준 약 **299건** 검수).

| 필요한 것 | 누가 |
|---|---|
| 층화 표본 프레임·seed·가중치 | 자동 |
| 판정 지침 초안 | 자동 |
| **최종 정답 판정·불일치 조정** | ★**사람만** |
| κ·CI 계산 | 자동 |

부록 recall 도 같다 — **정답셋 없이는 못 잰다.** proxy 3종
(독립 레이아웃 헤더 전수 탐색 · 목차↔본문 교차참조 · PDF outline)만 가능하고,
번호 연속성은 **가장 약한** 신호다(section 마다 재시작 · 무번호 부록 · 의도적 결번).

## 8. 내가 중간에 낸 결함 (기록)

같은 실수를 반복하지 않도록 남긴다.

| # | 결함 | 어떻게 드러났나 |
|---|---|---|
| ① | `in_table` 을 s5 `tables_coords.bbox` 로 봤는데 **그 필드에 좌표가 없다** | 1,367문서 전부 `False` 였다. 고치니 표본에서 0% → 35.7% 로 답이 바뀌었다 |
| ② | **편향된 표본** — 앞에서 300건을 잘라 `header_in_table 35.7%` 라 했는데 전량은 **12.2%** | 파일이 보험사 정렬 순이라 앞부분이 몰렸다 |
| ③ | Git Bash `kill` 로 Windows PID 를 죽였다고 **착각** | 좀비가 같은 파일에 계속 써서 결과가 깨졌다(4,614행·UTF-8 오류). PowerShell `Stop-Process` 로 정리하고 재실행 |

①④는 **`None` 과 `False` 를 구분하지 않아** 생겼다 — 모르는 것을 아니라고 단정한 것이다.

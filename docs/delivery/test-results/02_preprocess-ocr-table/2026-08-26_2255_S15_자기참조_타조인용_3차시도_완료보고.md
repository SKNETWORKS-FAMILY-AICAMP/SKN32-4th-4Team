# §15(자기참조 vs 정당한 타조 인용) 3차 시도 — 완료보고

- 설계: §15 관계법령신호 Codex설계안 (내부 원본 참조: `reports/debugs/2026-08-26_2030_S15_관계법령신호_Codex설계안.md`)(3차 설계, 이번에 구현)
- 상태: **고쳤다.** 코드·테스트·전량 재측정·사람 표본검수까지 완료.

## 1. 무엇을 했나

`scripts/extract/to_clauses.py` 의 heads 탐지 루프 안에 좁은 뒤집기 로직을
추가했다 — `_REF_TAIL` 자체와 `struct_audit.py` 의 S3 판정식은 **전혀
건드리지 않는다.** 다섯 조건(제목 있음·`제M조` 형태 인용·인용 대상
(본번호,가지번호)가 자기 자신과 다름·policy 구역·같은 부 발생 안에서 처음
보는 제목)을 전부 만족할 때만 "참조"를 "머리"로 뒤집는다.

★내 판단(구현 당시, 사람 지시 없이 스스로 세운 가설): 뒤집힌 후보는 heads
리스트에 들어가 **자기 자신의 조항 경계**를 갖게 되므로, 더 이상 어떤
블록의 "본문 안"에도 남지 않는다 — 그래서 S3(파묻힌 머리, 최종 블록 본문을
`_ARTICLE`/`_REF_TAIL` 로 재스캔) 는 뒤집힌 후보를 애초에 스캔 대상으로
보지 않는다. 따라서 Codex 원 설계가 권고한 "heads ↔ S3 판정 기록 공유
구조(CandidateDecision)"는 이번 3차 시도에서는 **불필요**하다고 보고
만들지 않았다. 이 판단은 구현 후 코덱스에게 diff 그대로 교차검증받았다
(§2).

## 2. 코덱스 5.6sol 구현 검토 — 결론과 실제 발견

**"공유 구조 불필요" 판단은 맞다**(코덱스 확인) — 뒤집힌 후보가 최종
`heads` 에 남는 한 S3 재스캔 대상에서 빠진다. 다만 "판정이 어긋날 방법이
없다"는 표현은 과했다 — `heads` 가 나중에 `numbered_cand` 로 통째로
교체되는 예외 경로가 있으면(article/numbered 번호체계 경쟁) §15 복구가
조용히 폐기될 수 있다(S3 폭증은 안 생기지만 복구 자체가 무효화됨 — 이번
세션 범위 밖의 잔여 한계로 남겨 둔다, §4 참조).

코덱스가 diff 를 직접 읽고 **재현까지 해서** 지적한 실제 결함 4건을 전부
고쳤다:

| 등급 | 결함 | 재현 결과 | 조치 |
|---|---|---|---|
| 높음 | 역순 법령 표지(`_STATUTE_LAW_REV`+`○`, 글리프 순서 뒤집힌 판본. 역순 9문서는 정순을 하나도 안 씀) 를 §15 의 section_kind 스캔이 놓침 | 관계법령 구역이 계속 `policy`로 남아 외부 법령 인용("개인정보보호법 제3조")을 이 정책 자신의 조항으로 착각해 회복 | `_statute_events()` 와 같은 방식(다음 줄 `○` 짝 확인)으로 section_kind 스캔에도 추가 |
| 높음 | `seen_titled_heads` 서명이 부 **이름**(표시 문자열)만 쓰고 부 **발생**(occurrence)을 구분 못함 | 이름이 같은("보통약관") 서로 다른 두 부의 **두 번째 부**의 정당한 조항이 "중복 제목 자기참조"로 오판돼 삭제 | `_section_context_at` 이 부 이벤트 색인(`sec_idx`)도 같이 돌려주게 하고, 서명에 이름 대신 색인을 넣음 |
| 중간 | "정규화 제목"이 실제로는 `.strip()` 뿐 | "기본형 실손"과 "기본형실손"(공백 차이)을 다른 제목으로 봐서 같은 조가 두 번 회복 | 부 이름 정규화와 같은 방식(`re.sub(r"\s+", "", ...)`)으로 공백 전부 제거 |
| 중간 | 자기참조 비교가 본번호만 쓰고 가지번호는 무시 | `제4조의2` 가 `제4조의1`을 인용해도 본번호(4=4)만 같으면 자기참조로 오판, 회복 실패(조용한 과소인용 — S3 도 못 잡음) | `(본번호, 가지번호)` 쌍 전체로 비교 |

4개 전부 회귀 테스트를 추가하고, 각각을 **개별적으로 껐다 켜서** 테스트가
load-bearing 함을 확인했다(D6 뮤턴트 테스트와 같은 취지, 이 파일의 기존
관례).

**고치지 않은 것(범위 밖, §15 이전부터 있던 별개 결함 또는 안전한 방향의
잔여 한계)**:
- 중첩 대괄호(`【】`/`[]`)로 제목이 잘리는 경우 — `title_truncated` 검사가
  `(`/`（` 만 본다(§15 이전부터 있던 기존 검사의 한계, 이번 세션에 만든 게
  아님). 영향은 §15 이전과 동일(과소인용 방향, 새로 나빠지지 않음).
- 첫 등장이 항상 진짜 머리라는 보장 없음, 명시적 부 제목 없는 문서는 §15
  미작동(둘 다 실효 = 0건, 위험 없음), article/numbered 번호체계 경쟁으로
  회복이 폐기되는 경우, 로마숫자 이벤트가 항상 policy 로 고정되는 것.

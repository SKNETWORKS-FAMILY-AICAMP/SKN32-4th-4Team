# s5L 연동계획 단계3 — 탐색 결과, 접는다

- 계획: s5L 레이아웃 to_clauses 연동 계획 (내부 원본 참조: `../plans/2026-08-26_1600_s5L_레이아웃_to_clauses_연동_계획.md`) §단계3
  ("선택, 낮은 우선순위 — §15류 결함에 레이아웃이 도움되는지 탐색")
- 상태: **탐색 완료, 접는다.** 코드 변경 없음 — 계획서 §5가 정한 원칙
  ("신호가 기대만큼 안 갈리면 정직하게 리포트하고 접는다")대로.

## 1. 전제 — §15는 이미 텍스트 신호만으로 해결됨

계획서가 단계3의 전제로 삼은 "관계법령 구역 신호" 방향은
[§15 3차시도 완료보고](2026-08-26_2255_S15_자기참조_타조인용_3차시도_완료보고.md)에서
**이미 구현·완료됐다** — `S3_embedded_header` 9→1, 전량실측 회귀 없음.
단계3은 원래 "그 방향이 부족할 때만" 보조로 검토하는 것이었는데, 그
전제(부족함) 자체가 사라졌다. 그래도 계획서에 남은 항목이라 실측으로
확인은 해 둔다.

## 2. 측정 방법

s5L(레이아웃 포함) 코퍼스 1,362문서에서, `build()`가 이미 계산하는
`statute_of_page`(관계법령 구역 페이지 판정, `_STATUTE_HEAD`/`_STATUTE_LAW`/
`_STATUTE_ZONE` 텍스트 규칙 — §15가 실제로 쓰는 바로 그 신호)를 이용해
각 조항의 `locator.page_from`~`page_to`를 "법령원문 전용 페이지"와
"정책 전용 페이지"로 갈랐다(겹치는 페이지는 신호가 섞이므로 양쪽에서
제외). 각 그룹의 s5L `layout` 줄들에서 글자크기 중앙값·bold 비율을
보험사별로 집계했다.

## 4. 코덱스 5.6sol 검토

측정 방법과 잠정 결론("접는다")을 코덱스에게 검토시켰다(준용 참조
추출기 검토와 같은 세션에서 함께 진행,
[V1한계 2건 수정 완료보고](../04_backend-db-api/2026-08-27_준용참조_추출기_V1한계_2건_수정_완료보고.md)
참조). **단계3을 접는 결론 자체에는 동의**했지만, 측정·서술의 정확성에
대해 지적 5건을 남겼다:

1. "방향이 일관되지 않는다"는 표현이 부정확함 — 위 §3에서 정정.
2. 페이지 **중앙값**은 페이지 안 소수의 법령 인용문 스타일을 본문
   다수가 덮어버릴 수 있다(페이지 단위 집계의 태생적 한계).
3. 혼합 페이지를 제외한 것이 오히려 **가장 유용한 법령↔약관 전환
   구간**을 버렸을 수 있다.
4. `statute_of_page`로 집단을 가르는 방식으로는, **기존 텍스트 규칙이
   이미 놓친** 법령 인용을 레이아웃이 새로 찾아낼 수 있는지는 애초에
   평가할 수 없다(이 측정은 "이미 아는 것"만 재확인하는 구조).
5. 표본 부족 5개사를 근거로 "이 보험사엔 별도 조판이 없다"고
   일반화하면 안 된다 — "법령 부록 자체가 없는지" vs "법령·정책이
   항상 같은 페이지에 섞이는지"를 먼저 갈라야 한다.

### 4-1. 지적 5번 후속 확인 — "법령포함 0" 5개사 분해

코덱스가 요구한 최소 확인 중 하나(표본 부족 5개사를 "법령 부록 없음"과
"항상 혼합 페이지"로 분해)를 직접 실측했다. `build()`가 계산하는
조항별 `statute` 플래그를 이용해, 그 문서 안에 **법령원문으로 분류된
조항이 단 하나라도 있는지**를 전량(1,362문서 중 해당 5개사분) 확인:

| 보험사 | 문서 수 | 법령원문 조항이 하나라도 있는 문서 |
|---|---:|---:|
| dbins | 236 | **0** |
| heungkukfire | 194 | **0** |
| lotteins | 92 | **0** |
| nhlife | 52 | **0** |
| samsunglife | 196 | **0** |

**답은 명확하다 — "항상 혼합"이 아니라 "법령 부록 자체가 없다".** 이
5개사(770개 문서)는 `_STATUTE_HEAD`/`_STATUTE_LAW`/`_STATUTE_ZONE`
텍스트 규칙이 단 한 조항도 법령원문으로 분류하지 못했다. 관계법령
부록을 안 쓰는 조판 관행이거나, 이 규칙이 못 잡는 다른 표기 방식을
쓰는 것일 수 있다 — 어느 쪽인지는 이 확인만으로는 모른다(지어내지
않는다). 어느 쪽이든 **레이아웃이 여기서 도울 대상 자체가 없다**(법령
구역이라는 개념이 이 5개사 산출물에 없다).

코덱스가 제안한 나머지 확인(§15 잔여 S3=1건·혼합 페이지의 법령↔정책
경계 줄 짝짓기 비교)은 이번 세션 범위에서 생략한다 — §15가 이미 텍스트
신호만으로 완료됐고 고칠 결함 자체가 없어(§5), 추가 확인의 한계효용이
낮다고 판단했다.

## 5. 결론

§15는 이미 텍스트 신호만으로 완료됐고(S3_embedded_header=1), 이번 실측도
관계법령 구역에 레이아웃이 별도로 도움될 만한 신호가 없음을 확인했다.
코덱스도 "생산 코드에 레이아웃 신호를 배선하는 단계3은 접어도 된다 —
남은 결함을 고칠 대상이 없고, 제시된 집계는 강한 공통 신호를 보여주지
않는다"고 결론지었다(측정 방법의 한계는 §4에서 정직하게 남긴다).
**단계3은 여기서 접는다** — 계획서 §4~5의 "신호가 없으면 정직하게
리포트하고 접는다" 원칙 그대로. 코드 변경 없음.

## 6. 재현

측정 스크립트는 임시 파일(세션 scratchpad)로 작성해 실행했으며 저장소에는
남기지 않았다. 재현하려면 `build()`의 `statute_of_page` 계산 로직을
그대로 재사용해 조항 `locator`와 s5L `layout`을 대조하면 된다
(`scripts/extract/to_clauses.py` 1229~1269행 부근).

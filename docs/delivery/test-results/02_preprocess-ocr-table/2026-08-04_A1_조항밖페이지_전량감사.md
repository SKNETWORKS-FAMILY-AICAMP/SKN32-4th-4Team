# A1 조항·부록 밖 페이지 전량 감사

- 날짜: 2026-08-04
- 기준: 페이지 `s5_pymupdf-1.28.0` / 조항 `s6_pymupdf-1.28.0`
- 범위: `parse_status=ok` 1,306문서 전량
- 상태: **원인 분해용 감사 완료 / 복구 미적용 / serving 변경 없음**

## 결론

기존 395문서 표본의 `6,463 / 37,869쪽(17.1%)` 문제는 전량에서도 재현됐다.
ok 문서의 비목차 152,299쪽 중 **23,645쪽(15.53%)**이 어떤 조항·부록 locator에도
속하지 않는다.

이 23,645쪽이 모두 결함이라는 뜻은 아니다. 앞 조항 전에 있는 안내문·요약서와 빈 페이지가
포함된다. 그러나 **앞뒤 조항 사이의 7,993쪽**도 고립돼 있고, 그중 **6,154쪽**에는 표·금액·
비율·KCD·보험 판정 용어 중 하나 이상이 있다. 따라서 A1은 표지·백지로 설명되지 않는다.

## 실제 손실 확인 예시

DB손보 `29f737ae8ff8`, p22–24:

- 앞 조항: `담보종목별 보장내용`, locator p19–21
- 다음 조항: `보상하지 않는 사항`, locator p25–27
- 고립된 p22–24: 공제금액·보상한도 표와 `1만5천원`, `8천원`, `20%` 포함
- 앞 조항 본문에는 `1만5천원`과 `8천원`이 들어 있지 않음

따라서 이 사례는 locator만 짧고 본문은 살아 있는 문제가 아니다. 페이지 본문과 표가 모두
조항 산출물에서 떨어져 판정·검색에 도달하지 않는다.

반대로 DB손보 `15d0cf40e56c`의 긴 고립 구간 일부는 `【법규】` 참고 페이지다.
이런 페이지를 보험 조항으로 자동 부착하면 법령 문구를 상품 약관으로 오인할 수 있다.
그래서 23,645쪽 전부를 이웃 조항에 붙이는 수정은 금지해야 한다.

## 권고 복구 순서

1. **`between_covered` 7,993쪽부터 원인 분류**: 연속 본문 절단, 부록 경계 실패,
   법규 참고, 정상 공백으로 나눈다.
2. 그중 신뢰 표 65쪽, 금액·비율 1,548쪽, 자기부담/공제 표기 835쪽을 우선 확인한다.
   **6,154쪽은 수정 대상 수가 아니라 검수 후보 수**이며, 실제 복구 수는 사람 판정 뒤 확정한다.
3. 복구는 페이지를 무조건 앞 조항에 붙이지 않고, 앞 조항의 연속 문장인지 또는 새 부록인지
   근거를 남기는 `parse_pages(prev, cur, next)` 계약으로 수행한다.
4. 첫 조항 앞 15,283쪽은 상품 안내와 약관 본문을 별도 document type으로 가른 후 처리한다.
5. A1 위반 수와 고위험 고립 수를 consistency gate에 추가하되, 안내문까지 자동 실패시키지 않는다.

## 현재 우선순위 판단

A1 **진단**부터 가는 판단은 맞다. 다만 23,645쪽을 곧바로 고치는 것이 아니라
**앞뒤 조항 사이의 고위험 후보 6,154쪽을 분류·검수**하는 것이 먼저다.
annex 참조는 A1 진단과 병렬로 shadow 연결할 수 있고, 이후 쪽 경계 자기부담금 복구(A2~A4),
C1/C2 게이트 수정 순으로 진행한다.

`outside_clause_pages.py`는 `citation_eligible`과 무관하게 `clauses`·`annexes`의 모든 locator를
coverage에 포함한다. 따라서 C1 게이트가 조항을 물리적으로 삭제하지 않는 현재 스키마에서는
C1의 `citation_eligible=false`가 A1 고립 페이지 수를 부풀리지 않는다.

최초 재측정에서 `consistency_check`는 T9 53 + W1 85 = 138건, 옛 `manifest_s6`는
s5+s6 파일 2,734개 해시 불일치였다. 후속 조사에서 138건은 최신 표 게이트를 검사기가
따라가지 못한 오진, 2,734건은 전량 재생성 전 매니페스트로 확인했다. 단일 게이트 적용과
매니페스트 재스냅샷 뒤 확정 위반 0, S6·S7 해시 불일치 0으로 정상화했다.

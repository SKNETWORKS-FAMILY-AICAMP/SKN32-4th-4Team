## 2. 실제 수행 내용

Codex 설계 검토를 먼저 받았다 — `_ARTICLE`/`_REF_TAIL`/heads 탐지(조항
경계 자체)는 안 건드리고, **S3(`struct_audit.py`) 게이트 전용 예외**로
좁게 고치라는 권고를 그대로 따랐다(조항 경계 산출물은 전혀 안 바뀜, S3
게이트 정밀도만 바뀜).

- `scripts/eval/struct_audit.py` — `_is_law_list_rider_reference()`(가.~하.
  법령 나열 항목 안, 「형법」...및 뒤에 "제N조(제목) (한정문)의 죄"로 그
  줄이 끝나는 형태만 좁게 판정) · `_is_summary_terminal_reference()`(section
  이 정확히 "약관요약서"이고, 직전이 "숫자→항목명" 표 행이며, 뒤가 쉼표로
  끝나고 그 이후 본문이 전혀 없는 경우만) 추가, S3 검사 루프에 배선.
- `tests/test_to_clauses_section_boundary.py` — **실제 원문(s3_residual.json
  전수 추출분)을 그대로 가져온** 회귀 테스트 5개 추가: 새 오탐 2종 억제
  확인 2개, 같은 section("약관요약서")·법령 인접 상황에서도 진짜 파묻힌
  머리는 계속 잡히는지 확인 2개. 전부 되돌리면 실패함을 확인(load-bearing).

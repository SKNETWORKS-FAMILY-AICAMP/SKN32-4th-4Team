# 오프라인 OCR SOTA 5종 x600 실측

- 시각: 2026-08-03 18:50~20:10 KST
- 목표: 최신 오프라인 OCR만으로 109,192개 보류 표 후보의 커버리지를 의미 있게 높일 수 있는지 확인
- 장비: x600, RTX 4070 SUPER 12GB, Windows, CUDA 12.6 torch
- 안전: 원본 PDF·DB·운영 manifest는 전송하지 않았다. SHA로 검증한 평가 이미지 7장만 전송했고 모든 결과는 serving/citation 차단 상태다.

## 결론

**커버리지는 올릴 수 있다. 그러나 단일 OCR 전수 투입으로 끝나지는 않는다.**

이번 표본에서 `MinerU2.5-Pro-2605-1.2B`가 가장 실용적이었다. KCD 코드 22행 중 코드 묶음은 22/22,
질병명과 같은 HTML 행 exact는 21/22였고, 자기부담금 6쪽 모두에서 rowspan/colspan을 포함한 HTML 표를 만들었다.
OvisOCR2도 KCD 21/22였지만 반복 생성과 중국어·일본어 계열 문자 혼입이 심했다.

따라서 기존 하이브리드의 **개념은 유지**하되, 차이는 `2열짝짓기`를 억지로 보편 복원하는 대신
고가치 페이지를 MinerU로 구조화하고 업무별 binder/validator로 승인 후보를 만드는 데 있다.
이 변경은 커버리지 곡선을 개선하지만, 검증·라우팅·사람 승인을 없애지는 않는다.

## 1. 후보 선정 근거

| 모델 | 공식 공개 포지션 | 이번 용도 |
|---|---|---|
| OvisOCR2 0.9B | OmniDocBench v1.6 96.58, page→Markdown | 전역 최신 end-to-end 비교군 |
| PaddleOCR-VL 1.6 0.9B | OmniDocBench v1.6 96.33, element table prompt | 기존 실패 경로의 공식 element 재검증 |
| MinerU2.5-Pro 1.2B | OmniDocBench v1.6 95.72, Table TEDS 93.62 | 2단계 layout→region 구조 복원 |
| GLM-OCR 0.9B | OmniDocBench v1.5 94.62 | 빠른 table region 비교군 |
| BizOnAI-OCR 9B | KDoc-OCRBench 자체 보고 overall 83.0, table 68.0 | 한국 산업 문서 특화 비교군 |

벤치 점수는 제작자가 보고한 서로 다른 평가셋 수치이므로 이 표만으로 서열화하지 않았다.
동일 보험 약관 이미지 실측을 최종 판단 근거로 사용했다.

## 2. 실행 환경과 설치 관찰

- 공용 GPU 확인: 시작·종료 모두 Python 프로세스 없음, GPU 0%, VRAM 0MiB 확인.
- 공통 Python 3.14 환경: torch 2.13.0+cu126, transformers 5.14.1, Pillow 12.3.0, torchvision 0.28.0.
- MinerU 공식 utils는 Python 3.14를 거부해 Python 3.12.13 격리 venv를 만들었다.
  `mineru-vl-utils` 1.0.5, transformers 4.57.6, torch 2.13.0+cu126을 사용했다.
- BizOnAI는 bitsandbytes 4bit NF4로 실행했다. cold download 4 shards 약 6분 33초, load 약 37초였다.
- Paddle은 transformers 5.14.1 호환 보정 후 실행됐다. 2,048토큰 run은 20분 넘게 GPU 100%,
  VRAM 11,978/12,282MiB를 점유하고 결과를 반환하지 못해 종료했다. 256토큰 bounded run만 성공했다.

설치·호환 실패와 장기 실행은 `docs/reports/debugs/2026-08-03_*OCR*`, `*MinerU*`, `*Paddle*`에 원문 로그와 함께 기록했다.

입력: 흥국화재 `ff0521a99902` PDF p109 렌더, 이미지 SHA256

| GLM-OCR | 512 | 14.497 | 4,539.5 | 3/22 | 9/22 | 3/22 | 빠르지만 한글 이름 오독, 10행 중간에서 truncated |

Paddle/GLM/BizOnAI의 짧은 상한은 전체 22행 recall을 불리하게 만든다. 그러나 Paddle/BizOnAI는
출력 앞부분의 첫 KCD 코드부터 `I`를 숫자 `1`로 바꿨으므로 이번 조건에서는 확대 우선순위가 아니다.

### Paddle 양자화 후속 실측

- 공식 `PaddlePaddle/PaddleOCR-VL-1.6-GGUF` 1.82GB와 llama.cpp 경로가 존재한다.
- x600에서는 공식 llama.cpp Windows Vulkan·CUDA 12.4 바이너리 모두 모델 다운로드 전
  `0xC0E90002` Bad Image로 차단됐다. 호스트 보안 정책은 변경하지 않았다.
- 동일 Transformers 모델에 bitsandbytes NF4 4bit를 적용한 대조는 성공했다.

| Paddle 경로 | 상한 | 추론 초 | peak VRAM MB | 출력 | KCD pair exact |
|---|---:|---:|---:|---|---:|
| BF16 element | 256 | 81.425 | 2,162.5 | `I00→100` | 0/22 |
| NF4 4bit element | 256 | 84.225 | 1,173.4 | `I00→100` | 0/22 |

양자화로 계측 VRAM은 약 45.7% 감소했지만 속도는 3.4% 느려졌고 핵심 문자 오독은 동일했다.
따라서 **양자화는 가능하지만 이번 커버리지·정확도 병목의 해결책은 아니었다.**

## 4. P1 7쪽(KCD 1 + 자기부담금 6): 공동 1위 두 모델 확장

| 모델 | 성공 | 추론 합계 | 평균/쪽 | HTML 표 | 중국계 문자 | 중복 라인율 |
|---|---:|---:|---:|---:|---:|---:|
| MinerU2.5-Pro | 7/7 | 203.386초 | 29.055초 | 7/7 | 전 페이지 0 | 전 페이지 0% |
| OvisOCR2 | 7/7 | 515.700초 | 73.671초 | 7/7 | 페이지당 8~66자 | 페이지당 33.33~96.04% |

MinerU가 복원한 구조의 대표 사례:

- NH p26: `표준형/선택형II × 외래/처방조제비 × 기관군 × 1만원/1만5천원/2만원/8천원 × 급여10%+비급여20%`를 rowspan으로 보존.
- 삼성 p40: 외래 기관 3종과 처방조제비 4행을 각각 금액식에 결합.
- 롯데 p15: 급여/비급여/3대 비급여 담보와 20%/30%/50%, 1/2/3만원을 rowspan으로 보존.
- DB p35: 이전 페이지에서 이어진 표의 현재 페이지 셀은 복원했지만 부모 행의 앞부분은 없다.

남은 오류:

- MinerU: `당뇨병→당 뇌 병`, `희귀의약품센터→회귀의약품센터` 등 한글 오독.
- 페이지 연속 표: NH p27 첫 행의 상위 `선택형II` 부모 셀이 빈 값으로 나온다. 공식 모델 카드도 cross-page table merging을 미지원으로 표시한다.
- 출력 HTML은 fact 후보일 뿐이다. `기관군→금액식`, `급여/비급여→비율`, 출처 bbox를 업무 스키마에 묶는 별도 검증이 필요하다.

## 5. 109,192개에 대한 의미

1후보=1페이지 호출이라고 단순 가정하면 MinerU 실측 평균으로 단일 GPU 약 36.7일, Ovis는 약 93.1일이다.
실제로는 한 페이지에 후보가 여러 개 있을 수 있어 **페이지 단위 묶음**으로 줄일 수 있고, 반대로 재시도·검수 비용은 늘어난다.
어느 쪽이든 5개 모델 전수 앙상블은 타당하지 않다.

권장 실행 순서:

1. 109,192개 원시 후보 보존 및 serving/citation 차단 유지
2. 문서 계열·부록 제목·업무 키워드로 관련 페이지 선별
3. 레이아웃 hash와 페이지 기준으로 중복 호출 제거
4. MinerU shadow page parsing
5. KCD/자기부담금 전용 binder로 candidate fact 생성
6. 코드 문자형·금액·축·bbox 출처 validator
7. 층화 검수 승인 후에만 release pointer 전환

즉 기존 방식과 **토폴로지는 유사**하지만, 범용 휴리스틱 복원기가 맡던 구조 후보 생성을 최신 VLM이 대체한다.
전수 규모를 감당하는 것은 모델이 아니라 page grouping·hash dedupe·업무 라우팅이며, 정확성을 보장하는 것은 validator와 승인 게이트다.

## 6. 다음 게이트

- MinerU만 48개 원문 3쪽 창 층화 평가로 확장한다.
- 자기부담금 전용 스키마를 `plan × service × institution × coverage × amount/formula × source_bbox`로 정의한다.
- 자동 채택 조건은 KCD `I/1`, `O/0` 오류 0건, 금액/비율 오결합 0건이다.
- 48개 표본을 통과하기 전 109,192개 전량 처리와 serving 연결은 하지 않는다.
- Ovis는 MinerU 불확실 행에 대한 비교 출력만 생성하며, 반복·CJK 오염 필터를 먼저 둔다.

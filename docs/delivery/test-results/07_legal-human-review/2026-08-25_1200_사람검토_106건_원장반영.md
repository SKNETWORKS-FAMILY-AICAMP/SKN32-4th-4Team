## 2. 원장 반영

`config/confirmed_documents.jsonl`: **1,248 → 1,352건** (+104 신규 · 2 강화).

강화 2건은 기계가 이미 `name_only` 근거로 확정해 놓은 것을 AI1이 실물 대조까지
마쳐 `content_verified`로 근거 등급을 올린 경우다(상품명 자체는 이미 맞았다) —
`무배당 프로미라이프 다이렉트 실손의료비보험(계약전환용)2404(CM)`,
`무배당 프로미라이프 실손의료비보험2604`.

새로 들어간 104건은 모두 `confirmed_by`에 `"대기"`가 들어 있어 기존 1,248건과
같은 **"사람 최종승인 대기"** 상태로 취급된다(`identification_mode.is_pending_signoff()`
가 그대로 걸린다) — 자동으로 판정에 쓰이지 않는다.

백업: `backups/confirmed_documents_20260825_before_human_review_merge.jsonl`

## 3. 원장에 넣지 않은 것 — misfiled 1건

현대해상 sha256 `5fc609ca…` — 매니페스트는 "임신출산질환" 특약이라는데 실제
파일은 "법률비용손해" 특약이다. 현대해상 공시실 자체가 다른 파일을 걸어 놓은
**원천 데이터 오류**다. `identification="confirmed"`가 아니므로 판정에 쓰이지
않는다(추가 차단 로직 불필요, fail-closed 기본값이 이미 막는다) →
디버그 리포트 (내부 원본 참조: `debugs/2026-08-25_1200_현대해상_2509_임신출산질환_약관이_법률비용손해로_오등록.md`)

## 4. 아직 미해결 — pending 2건

AI2가 "두 근거가 상충한다"고 판단해 확정하지 않은 것들이다. 삼성생명
`인터넷급여` vs `급여` 계열 2건 — 개요면 공식 항목은 인터넷급여로 명시돼
있는데 문맥만으로는 확정 못 함. 사람이 더 봐야 한다. 원장에 안 넣었으니
그대로 미확정으로 남는다.

## 5. 검증

- 병합 후 `config/confirmed_documents.jsonl` 전체 1,352줄 JSON 파싱 통과.
- sha256 충돌(=기존 원장에 이미 있던 건) 2건 모두 같은 상품명 — 내용 상충 없음,
  근거 등급만 강화.
- ★pytest 는 이번엔 못 돌렸다 — 로컬 postgres 테스트 DB(127.0.0.1:5433)가
  현재 응답하지 않는다(`tests/conftest.py`가 2026-08-14 세션에 postgres로
  옮겨 놓은 그 인스턴스). 이 작업은 `config/confirmed_documents.jsonl`
  데이터만 건드리는 순수 데이터 병합이라 코드 회귀 위험은 낮다고 판단해
  JSON 유효성 검사로 갈음했다. DB가 복구되면 `test_rival_matching.py`·
  `test_cover_match.py`·`test_verify_url_anchor.py`로 재확인할 것.

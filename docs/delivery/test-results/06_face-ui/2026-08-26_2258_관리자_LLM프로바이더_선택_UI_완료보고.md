# 관리자 패널 LLM 프로바이더 선택 UI — 완료 보고

- 작성: 2026-08-26 22:58
- 계획: 별도 계획서 없음 — 27_LLM생성모델_선정_브리핑.md (내부 원본 참조: `../handoff/27_LLM생성모델_선정_브리핑.md`)
  §8 항목 5("관리자 패널 LLM 프로바이더 선택 UI(로컬/제미나이/openai)")의 실행.
  사용자가 처음 요청(2026-08-26 낮)했다가 LLM 비교 작업과 분리해 후속으로 미뤄뒀던 것을
  이번에 착수.

## 1. 무엇을 만들었나

관리자가 `.env`의 `LLM_PROVIDER` 기본값을 **런타임에**(재배포 없이) local/openai/gemini
중 하나로 바꿀 수 있는 기능. 이미 저장소에 있던 판정 모드 스위치
(`app/core/domain/identification_mode.py` → `PUT /api/admin/precheck-mode`)와 **완전히
같은 설계 패턴**을 그대로 따랐다 — admin·customer가 별도 프로세스로 뜨기 때문에
(`app/main.py`) 오버라이드를 프로세스 메모리가 아니라 파일(`config/llm_provider_override.json`)에
남겨 두 프로세스가 같은 값을 보게 한다.

### 변경 파일

| 파일 | 변경 |
|---|---|
| `app/core/domain/llm_provider_override.py`(신규) | `current()`/`set_override()` — 오버라이드 없으면 `None`, 있으면 프로바이더 문자열. 파일 손상 시 조용히 기본값으로 안 돌아가고 `InfraError` |
| `app/core/llm_clients.py` | `get_chat_client`·`get_langchain_chat`·`get_active_model` 세 함수 전부 `provider = llm_provider_override.current() or settings.LLM_PROVIDER`로 수정 — 그 외 ConfigError 로직은 그대로(폴백 추가 없음) |
| `app/routers/admin.py` | `GET/PUT /api/admin/llm-provider` 추가. `PrecheckModeRequest`/엔드포인트와 동일한 형태 — 감사 로그(`record_event`)·관측 스트림(`agent_stream.publish`) 양쪽 기록 |
| `app/static/admin.html` | 판정 모드 패널 바로 아래에 "LLM 프로바이더" 패널 추가(기존 CSS 클래스 재사용, 새 CSS 없음) |
| `app/static/admin.js` | 요소 참조·초기 로드(`Promise.allSettled` 배치에 편입)·변경 핸들러·렌더 함수 추가 — 판정 모드 코드와 같은 구조 |
| `tests/test_llm_provider_override.py`(신규) | `test_identification_mode.py`와 같은 fixture 패턴. 9개 케이스 |

## 2. 코덱스(gpt-5.6-sol) 활용 — 실패하고 직접 구현으로 전환

사용자가 "코덱스 5.6sol 최대한 써서" 작업하라고 명시해 실제로 `codex exec --model
gpt-5.6-sol`로 2회 시도했다(전체 6단계 통합 프롬프트 1회, 실패 후 1단계만 떼어낸
좁은 프롬프트 1회). **두 번 다 파일을 못 썼다** — 원인을 실측으로 확인:

- Codex CLI가 Windows에서 파일을 읽을 때 내부적으로 PowerShell
  `Get-Content -Raw`를 호출하는데, 이 환경의 PowerShell이 UTF-8 한국어 파일을
  읽으며 **글자를 깨뜨린다**(`docs/manuals/README.md`가 이미 문서화한 known issue —
  "PowerShell 5.1이 BOM 없는 비ASCII 스크립트 파일을 망가뜨린다"와 같은 부류의 문제,
  이번엔 스크립트가 아니라 **참조로 읽은 소스 파일**에서 발생).
  `codex_llm_provider_output.log`에 실제로 `identification_mode.py`의 한국어
  docstring이 `?좎뼵?섏? ?딆? ?좏깮`처럼 깨진 채로 찍힌 것을 확인했다.
- 1차 시도는 이 깨진 내용을 그대로 4개 파일(신규 1 + 수정 3)에 한 번에
  patch하려다 `apply_patch` 자체가 실패했고, 이후 15분+ 무응답으로 멈췄다.
- 2차 시도(1개 파일로 범위를 좁힘)도 같은 인코딩 문제로 파일을 못 썼다.

★**결론**: 이 프로젝트 환경에서 Codex CLI로 **한국어 소스 파일을 참조해 새 한국어
코드를 생성하는 작업**은 신뢰할 수 없다(영어 전용 파일이나, 참조 없이 순수 생성하는
작업이면 다를 수 있음 — 이번엔 확인 안 함). 2회 확인 후 시간·신뢰성을 고려해
Claude가 직접 구현으로 전환했다 — Codex 탐색 에이전트가 미리 만들어 둔 정확한
file:line 스펙(§1의 6개 파일 매핑)을 그대로 따랐으므로 설계 자체는 코덱스·탐색
결과를 활용한 것이다.


`test_rbac_admin.py`의 다른 20여 개 테스트는 `relation "knowledge_gaps" does not exist`로
실패했다 — **이 세션의 변경과 무관한 사전 존재 문제**다(`git diff --stat`으로 이번
변경이 위 6개 파일에만 있음을 확인, `knowledge_gaps` 테이블은 이번에 건드린 어떤
파일에도 나오지 않는다 — 이 dev DB에 그 테이블 마이그레이션이 아직 안 올라간 것으로
보인다. 고치는 건 이번 작업 범위 밖).

### 실제 화면 확인 (RULE.md §4 — 프론트엔드는 실제로 열어서 확인)

`python -m scripts.run_admin_server`(8081)로 실제 기동 후 브라우저로 직접 확인:

1. 테스트 계정 생성(`llmtest_admin`) → `python -m scripts.manage promote` → 로그인.
2. `GET /api/admin/llm-provider` → `{"override":null,"default":"openai","effective":"openai"}` 확인.
3. `PUT .../llm-provider {"provider":"openai"}` → 반영 확인, 재조회로 영속 확인.
4. `PUT .../llm-provider {"provider":"anthropic"}`(잘못된 값) → **422**, Pydantic
   `Literal` 검증이 내 코드에 닿기도 전에 거절 — 조용한 통과 없음 확인.
5. `PUT .../llm-provider {"provider":null}` → 오버라이드 해제, `config/llm_provider_override.json`
   파일 삭제까지 확인.
6. **화면에서 직접**: select box를 `local`로 바꿈 → 배지 `local`로 바뀜, 설명문
   "`.env` 기본값(openai)을 덮어씀 — 현재 local 사용 중." 표시, 안내 문구 표시.
   **페이지 새로고침 후에도 `local`이 그대로 유지**됨(파일 기반 영속 확인 —
   이게 이 기능의 핵심 요구사항이었다).
7. 기본값으로 되돌리고 마무리 — 오버라이드 파일 삭제 확인.
8. 테스트 계정은 `scripts.manage demote`로 다시 USER로 낮춰 정리(삭제 명령은 없음 —
   ADMIN 권한만 회수).

## 4. 의도적으로 하지 않은 것

- Gemini 프로바이더를 고르면 여전히 `GOOGLE_API_KEY` 미설정 시 기존 `ConfigError`가
  그대로 난다 — 이 기능은 "고를 수 있게" 하는 것이지 키를 대신 채워주지 않는다
  (RULE.md 3.2, 폴백 금지 원칙 그대로 유지).
- 오버라이드 이력(누가 언제 어떤 값에서 어떤 값으로 바꿨는지 전체 로그)은 감사
  이벤트(`record_event`)에만 남고 별도 UI 타임라인은 안 만들었다 — 판정 모드도
  마찬가지 수준이라 일관성 유지.
- `tests/test_admin_llm_provider_api.py` 같은 FastAPI TestClient 레벨 통합 테스트는
  추가하지 않았다 — `test_rbac_admin.py`가 이미 이 DB 마이그레이션 문제로 막혀 있어
  같은 클라이언트 픽스처를 재사용하는 새 테스트도 똑같이 막혔을 것이다. 대신 §3의
  실제 서버 기동 + curl/브라우저 검증으로 대체했다.

## 2. 가져오면 안 되는 것 — 실측으로 확인한 회귀 5건

### R1. `Idempotency-Key` 누락 -> 운영모드에서 판정이 **항상 422**

`app/routers/precheck.py:483-484`


## 5. 2페이지 분리를 어떻게 볼 것인가

front 는 한 화면이던 `insurance.html` 을 둘로 쪼갰다.

- `insurance.html` — 챗봇 전용. 좌측에 입력 패널.
- `coverage-detail.html` — 판정 결과(`#result`) · 코호트 · 관찰 제보.

두 페이지는 `sessionStorage` 핸드오프(`savePrecheckHandoff` / `loadHandoff`)로
결과를 넘기고, 상세 페이지에서 `rerunPrecheck` 로 다시 부른다.

**방향은 납득이 가는데, 지금 구현으로는 못 쓴다.**

1. 판정을 **두 번** 호출한다(챗봇에서 한 번, 상세에서 `rerunPrecheck` 로 또 한 번).
   운영모드에서는 `Idempotency-Key` 가 다르면 원장에 **두 건이 쌓인다.**
2. 판정 결과를 `sessionStorage` 로 옮기면 `trace_id` 연결이 끊기기 쉽다.
   실제로 `coverage-detail.js` 는 `trace_id` 를 **표시만** 하고 관찰 제보에 안 싣는다.
3. 로컬은 같은 화면에서 판정->인용->제보가 이어진다(`CLAUDE.md` §5 「보장 판정」 행,
   실측 2026-08-04). 분리하면 이 흐름을 다시 검증해야 한다.

-> **결론**: 분리 자체는 다음 단계로 미루고, 지금은 **로컬 단일 화면에 front 의
디자인만 입힌다.**

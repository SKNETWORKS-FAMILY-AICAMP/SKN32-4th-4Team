## 3. ★4-2 가 잡은 결함 여섯 개

**이 단계를 「확인 절차」로만 봤는데 실제로 결함을 잡았다.**

| | 결함 | 어디 |
|---|---|---|
| ① | `p.stem` 이 `"…clauses"`(20자) — sha 가 깨짐 | 적재 |
| ② | 시험 스크립트가 sha12 를 넘김 | **내 시험** |
| ③ | 인용 게이트 값을 저장 안 함 → `load_clauses()` 가 0건 | 스키마 |
| ④ | `ON CONFLICT` 가 기본키와 불일치 — 적재가 죽음 | 적재 |
| ⑤ | 산출물 키가 `statute` 인데 `is_statute` 로 읽음 | 적재 |
| ⑥ | 페이지가 `locator` 안인데 최상위를 봄 | 적재 |

★**①③⑤⑥이 전부 적재기가 산출물 구조를 잘못 읽은 것**이다.
`file_clause_store` 에 올바른 읽기 코드가 이미 있었는데, 새로 쓰면서 다시 틀렸다.
**있는 것을 안 보고 새로 만든 대가**다.

★⑤는 `eligibility.py:80` 에 **경고가 이미 적혀 있었다** —
「키 이름이 `statute` 다. 처음에 `is_statute` 로 읽어…」. 적어 둔 것을 안 읽고 되풀이했다.

### 내가 저지른 것 둘

**로그를 필터로만 봤다.** `grep "발생 적재|ready"` 로 보다가 `Traceback` 을 놓치고
"재적재 완료"라고 보고했다. 실제로는 ④ 때문에 죽어 있었다.
→ 이후 확인은 **종료코드와 `Traceback` 개수를 먼저** 찍는다.

**시험이 틀렸는데 코드를 의심했다**(②).

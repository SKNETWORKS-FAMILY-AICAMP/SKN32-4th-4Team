**의미가 반대인데 표면이 닮았다.** 벡터만으로는 이걸 못 가른다.
리랭커가 hit@1 을 0.4844 → 0.6379 로 올리는 것이 바로 이 지점이다.

## 2-2. 메트릭 스크레이프 인증 — 실물 HTTP 7가지

`/metrics-scrape` 는 Prometheus 가 긁을 수 있어야 해서 관리자 로그인 **밖**에 있다.
그래서 인증을 실제로 걸어 본다.

| # | 상황 | 응답 | 기대 |
|---|---|---|---|
| ① | `METRICS_SCRAPE_TOKEN` 미설정 | **404** | 안 켰으면 **없는 경로**다 |
| ② | 토큰 없이 요청 | **401** (`WWW-Authenticate: Bearer`) | |
| ③ | 틀린 토큰 | **401** | |
| ④ | **접두사만 맞는** 토큰(끝 한 글자 빠짐) | **401** | `compare_digest` 가 길이·내용 모두 본다 |
| ⑤ | `X-Metrics-Token: <토큰>` | **200** `text/plain; version=0.0.4` | Prometheus 노출 형식 |
| ⑥ | `Authorization: Bearer <토큰>` | **200** | 둘 다 받는다 |
| ⑦ | **고객 앱**에 토큰 들고 요청 | **404** | 운영 앱에만 싣는다 |

★①이 가장 중요하다. 「설정 안 했으니 다 열어 준다」가 가장 나쁜 기본값이다.
  토큰이 비면 라우트 자체가 없다 — 무폴백.

★④는 타이밍 공격 방어의 부수 확인이다. `==` 였다면 앞자리부터 맞는지가
  응답 시간에 남아 토큰을 한 글자씩 맞출 수 있다.

본문 예:

```
# HELP clause_rerank_enabled 조항 리랭킹 스위치(1=켜짐)
# TYPE clause_rerank_enabled gauge
clause_rerank_enabled 0
# HELP clause_rerank_worker_up 리랭크 워커가 떠 있는가(1=떠 있음)
# TYPE clause_rerank_worker_up gauge
clause_rerank_worker_up 0
```

## 3. 실측 환경에서 부딪힌 것

### 3-1. 로컬 Qwen 캐시가 **미완성본**이었다

`~/.cache/huggingface/hub/models--Qwen--Qwen3-Reranker-4B` 가 3.8 GB 를 차지하고 있는데
`model.safetensors.index.json` 이 요구하는 **2조각 중 1조각만** 있다
(`model-00002-of-00002` 만 있고 `00001` 이 없다). 디스크가 모자라 받다 만 것이다.

★**이건 캐시가 아니라 못 쓰는 덩어리다.** 로드하면 실패한다.
  이 기계는 `torch.cuda.is_available() == False` 라 4B 를 돌릴 수도 없다.
  지우면 3.8 GB 가 나오지만 **작업 트리 밖이라 사람 승인이 필요하다** — 남겨 둔다.

### 3-2. C: 가 1.2 GB 인데 **D: 에 871 GB 가 있었다**

임베더(2.2 GB)를 못 받아 참고 조항 검색이 실패했었다.
`HF_HOME=/d/hf_cache` 하나로 풀렸다. 지울 것을 찾기 전에 **다른 곳에 자리가 있는지**를 먼저 본다.

### 3-3. ★★프로세스 워커가 **세그폴트를 가뒀다** — 예상 못 한 두 번째 값

로컬 CPU 로 `bge-reranker-v2-m3` 를 fp32 로 올리자 **세그폴트(exit 139)** 가 났다.
RAM 15.7 GB 중 여유 3.9 GB 인데 임베더(2.2 GB)가 이미 올라와 있었고
리랭커가 ~2.3 GB 를 더 요구했다.

| 방식 | 결과 |
|---|---|
| 인프로세스(`CrossEncoderReranker` 직접) | **세그폴트 · exit 139** |
| `CLAUSE_RERANK_WORKER=process` | **성공** — 적재 32.7초, 부모 생존 |

자식은 자기 주소공간을 쓰므로 부모의 임베더를 안 문다. 같은 기계인데 갈렸다.

재정렬 결과도 맞았다 — 「치과치료 보철료는 보상하나요」에
「보철치료에 든 비용을 보상하지 않습니다」 **0.8355**,
무관한 「입원의료비를 보상합니다」 **0.0056**.

★프로세스 워커를 만들 때 적은 값은 「시한에 진짜 취소된다」 하나였다.
  **적재 자체가 서버 메모리를 안 먹는다**는 것이 실측으로 하나 더 붙었다.
  스레드 워커였다면 이 세그폴트가 **서버 프로세스를 죽인다.**

### 3-4. 종단 스크립트가 **서비스와 다른 경로**를 타고 있었다

라우터는 `rw.build_worker_from_settings()` 를 쓰는데 스크립트는
`CrossEncoderReranker` 를 직접 만들었다. 위 세그폴트가 그래서 안 보였다 —
스크립트만 죽고 서비스 경로는 멀쩡했는데, 스크립트는 그걸 알 방법이 없었다.
「테스트가 통과한다 ≠ 서비스가 돈다」를 검증하려는 스크립트가 **스스로 그 함정에 빠져 있었다.**
같은 경로를 타도록 고쳤다(`cc0e637c`).

### 3-5. 파이프가 종료 코드를 가렸다

`python ... 2>&1 | tail -40` 은 **tail 의 종료 코드**를 낸다.
그래서 세그폴트가 「exit 0 인데 출력이 없다」로 보였다 — 한참 헤맸다.
리다이렉트(`> log 2>&1`)로 바꾸니 `Segmentation fault ... 종료코드 = 139` 가 바로 나왔다.

★**진단 도구가 사실을 잘못 전하면 오진 위에 수정을 쌓게 된다**(CLAUDE.md §3).

### 3-6. 죽은 자식을 시한만큼 기다렸다 (결함 · 수정)

프로세스 워커가 자식을 띄우고 `results.get(timeout=600)` 을 **한 번** 불러 기다렸다.
자식이 OOM 으로 죽으면 예외도 안 남고 **큐에 아무것도 안 들어온다** —
부모가 10분을 꽉 채우고서야 「준비되지 않았습니다」라고 말했다.
밖에서는 **아무 일도 안 일어나는 것처럼** 보였다.

0.5초씩 끊어 기다리며 `is_alive()` 를 보도록 고쳤다. 죽었으면 즉시,
**종료 코드와 원인 추측(OOM)까지** 붙여 말한다(`31338a3d`).
시험도 붙였다 — 가짜 리랭커가 `os._exit(139)` 로 네이티브 크래시를 흉내 낸다.

### 3-7. `daemon=True` 가 SIGKILL 에는 안 통한다 (주석 정정)

「부모가 죽으면 자식도 죽는다」고 주석에 단정해 뒀는데 **틀렸다.**
`daemon=True` 는 파이썬이 **정상 종료할 때** 정리한다는 뜻이다.
배경 작업을 강제로 끊자 자식이 **696 MB 를 문 채 고아로 살아남았다.**
한계를 주석에 적었다(`89f2bd57`) — 프로세스 그룹·job object 로 묶는 것은 남은 일이다.

### 3-8. 역터널이 막혀 GPU→로컬 PG 를 못 물렸다

`ssh -R 5433:...` 이 거부됐다. 그래서 종단을 **두 쪽으로 나눠** 검증했다 —

| 쪽 | 어디서 | 무엇이 진짜인가 |
|---|---|---|
| 검색 | 로컬 | 진짜 PG(조각 122,772) · 진짜 임베더 · 진짜 유스케이스 |
| 재정렬 | GPU 호스트 | 진짜 리랭커 · **같은 색인에서 나온** 진짜 후보 417질의 |

★두 쪽이 **같은 후보셋**을 쓰므로 이어 붙은 값이다.

★**「한 프로세스에서 끝까지」는 §2-3 에서 따로 돌렸다** — 로컬에서 진짜 PG ·
  진짜 임베더 · 진짜 워커(process) 를 한 프로세스에 올려 3질의를 통과시켰다.
  다만 거기 쓴 리랭커는 CPU 용 작은 모델이다. **품질 수치는 §1 의 GPU 실측이 근거이고,
  §2-3 은 경로가 도는지만 잰다.** 둘을 섞어 읽지 않는다.

  아직 못 한 것: **GPU 에서 4B 로 한 프로세스 종단.** GPU 기계가 PG 를 봐야 하는데
  역터널이 막혔다. 배포 기계(GPU + DB 같은 망)에서는 그냥 된다.

## 4. 스위치를 켤까

### 켤 근거
- hit@1 **+15.35%p** (0.4844 → 0.6379). 작은 차이가 아니다.
- 실패 0/417. 시한(30초) 안에 여유 있게 들어온다(p95 3.5초).

### 켜지 말아야 할 자리
- **`/v1/prechecks` 에는 안 켠다.** 판정 경로에 2.8초를 얹는 것도 문제지만,
  더 중요한 건 **판정은 리랭킹을 안 쓴다** — 질병기호 대조는 결정적이다.
- **GPU 없는 기계에서 기본으로 켜면 안 된다.** 이 개발 기계가 그렇다(cuda False).
  기본값을 켜면 그런 곳에서 503 이 난다.

### 그래서
`INSURANCE_CLAUSE_RERANK_ENABLED` **기본 꺼짐을 유지**하고,
GPU 가 있는 배포에서 `.env` 로 켠다. 켤 때 함께 볼 것 —

```dotenv
INSURANCE_CLAUSE_RERANK_ENABLED=true
RERANKER_MODEL=Qwen/Qwen3-Reranker-4B
RERANKER_DEVICE=cuda            # ★뒤에 공백이 붙으면 'Invalid device string'
RERANKER_DTYPE=float16
CLAUSE_RERANK_SCORE_BODY=chunk  # 실측 근거: +5.04%p
CLAUSE_RERANK_MAX_LENGTH=1536
CLAUSE_RERANK_TIMEOUT_SECONDS=30    # p95 3.5초 — 여유가 충분하다
CLAUSE_RERANK_WORKER=thread         # 시한초과·OOM 이 관측되면 process
METRICS_SCRAPE_TOKEN=<토큰>          # 위 판단 근거를 계속 볼 수 있게
```

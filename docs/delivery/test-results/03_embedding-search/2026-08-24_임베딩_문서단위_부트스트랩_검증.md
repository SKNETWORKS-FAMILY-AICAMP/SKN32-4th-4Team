# 임베딩 브리핑 §3-3-★ 4번 — 문서 단위 부트스트랩 검증

## 배경

`docs/handoff/13_임베딩모델_선정_브리핑.md` §3-3-★가 지적한 5개 중 4번:
같은 문서·상품에서 나온 질의들은 독립이 아닐 수 있는데, 기존 부트스트랩은
**질의를 개별 표본으로 재표집**해서 그 상관을 무시하고 있었다(§5-4-1).

## 한 것

`scripts/eval/bench_embedders.py`의 `compare()`에 `--cluster` 플래그를 추가했다.
질의 index를 `data/eval/embed_bench.json`의 `corpus[gold_id].sha12`로 되짚어
**문서(sha12) 단위 라벨**을 만들고, 부트스트랩마다 질의가 아니라 **문서를
재표집**한 뒤 그 문서에 속한 질의를 전부 묶어 평균을 낸다.

GPU·모델 재적재가 필요 없다 — 이미 저장된 `ranks`만 다시 조합한다.

## 검증

```
python -m scripts.eval.bench_embedders --compare "<기준모델>" --task tail --dtype float16 --cluster
python -m scripts.eval.bench_embedders --compare "<기준모델>" --task title --dtype float16 --cluster
```

- tail: 질의 60개 → 문서 26개로 묶임
- title: 질의 145개 → 문서 32개로 묶임

## 결과 — §3-3의 9개 후보 선별은 **바뀌지 않는다**

기준 모델(tail=`arctic-ko`, title=`arctic`) 대비 16개 후보 전부, **판정(★차이
확인 / 구간이 0을 걸침)이 질의 단위·문서 단위 사이에 하나도 안 바뀌었다**
— tail 10승·6패, title 10승·6패 그대로.

구간 폭은 모델마다 다르게 움직였다(예: tail `Snowflake/arctic-embed-l-v2.0`은
`[-0.082,+0.018]` → `[-0.064,+0.009]`로 **좁아짐**, 반대로 넓어진 모델도 있다) —
문서 내 상관이 항상 한 방향으로 작용하지 않는다는 뜻이다. 그래서 "문서
단위로 하면 다 넓어진다"고 예단하면 안 된다.

## 결론

- ★이 데이터셋·이 16개 비교에서는 **질의 단위 부트스트랩이 결론을 왜곡하지
  않았다.** §3-3-★가 우려한 방향(과신)으로 틀렸다는 증거는 안 나왔다.
- ★그렇다고 §3-3-★의 나머지(δ 설정·s6 재구축·구어체 질의·holdout)가
  필요 없어지는 건 아니다 — 이건 그중 **한 항목만** 확인한 것이다.
- `--cluster`는 `--compare`의 옵션으로 남겨 앞으로도 재사용한다.

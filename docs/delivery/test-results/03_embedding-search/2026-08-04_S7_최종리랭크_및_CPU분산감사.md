# S7 accepted 기준선 리랭크 및 SSH CPU 분산 감사 결과

- 작성일: 2026-08-04 KST
- 검색 모델: `dragonkue/snowflake-arctic-embed-l-v2.0-ko`
- 리랭커: `Qwen/Qwen3-Reranker-4B`
- 릴리스 상태: `shadow`, serving/citation 차단 유지

## 결론

S7 accepted 청크를 대상으로 한 **회귀 기준선 리랭크** 산출물을 생성했다. 417개 질의의 dense top20, 총 8,273쌍을 RTX 4000 Ada에서 채점했으며 모든 점수가 유한하고 후보 membership도 입력과 일치했다. 검색 가능한 314문항에서 Hit@1은 `84.71%`, MRR@10은 `0.9101`이다.

동시에 S5 1,367문서를 보험사별 6개 샤드로 나눠 다섯 RunPod와 x600 CPU에서 A2~A4 경계 감사를 실행했다. 10,726개 자기부담 레코드 중 경계 절단 지문 20건을 찾았고, 값 추론 없이 인접 쪽이 유일하게 결합되는 KB손보 4건만 복구했다. 나머지 16건은 계속 `partial/unparsed`로 기권해야 한다.

S7의 OCR candidate fact 4,562건은 이번 임베딩과 리랭크 입력에 포함하지 않았다. 따라서 **이 결과만 운영하면 OCR 커버리지 증가는 0**이다. 현재 결과는 S6보다 안전하게 나쁘지 않은 accepted 기준선을 고정한 중간 산출물이며, OCR로 얻은 추가 커버리지는 사람 승인 뒤 재임베딩해야 실제 serving 지표에 나타난다.

강한 자동 게이트를 통과한 1,072건은 의미 정규화 후 35패턴이며, 서로 다른 문서 2개 이상에서 반복되는 것은 29패턴·1,066건이다. `docs/review/s7_fact_signature_review_20260804.html`에서 이 29개 대표 원문을 승인하면 S7.1 증분 청크 생성으로 이어간다.

복구 4건은 모두 KB손보이며 금액과 단일 비율을 함께 가진 행이다. 인접 이전 쪽에서 금액 상위 단위와 기관명 앞부분이 발견되고 축 충돌이 없으며 후보가 정확히 하나인 경우에만 결합했다. 예를 들어 `1만` + `5천원`을 `15,000원`으로 복구하지만 표준값을 대입하지 않는다.

미복구 16건의 값 유형은 다음과 같다.

- 금액+급여/비급여 분리율: 4건
- 단일 비율: 5건
- 값 자체를 못 읽음: 7건
- 경계 의심 행 중 `한도` 토큰: 0건

### 병렬 실행

S5 JSON 831.6MB를 보험사별 6개 압축 샤드(13.0~28.9MB)로 만들었다. 다섯 RunPod와 x600에 동시에 전송했으며 작업자 수는 `6/6/18/12/6/6`으로 제한했다. 샤드 준비 20.9초, 동시 전송 35초, 원격 계산은 샤드별 0.439~0.971초였다. 여섯 결과의 payload hash가 모두 일치했고 보험사 집합은 서로 겹치지 않으며 문서 합계는 정확히 1,367이다.

## Annex 안전 diff

해소된 별표 참조 3,354건을 clause-only 판정과 비교했다. 구조상 unique/nonconditional subset만 사용하면 53문서에서 10,705개 코드 판정이 바뀌지만, 다목적 부록 전체를 특정 질병 참조에 붙이는 과연결이 실측됐다. 명시 KCD 범위와 부록 범위가 겹치는 엄격한 semantic gate를 추가한 결과 safe ref는 94건, safe annex mention은 1,678건이며 **새로 바뀌는 판정은 0건**이다.

따라서 annex는 계속 shadow다. 현재 안전 subset은 clause에 이미 존재하는 정보를 중복 확인할 뿐 serving recall을 늘리지 않는다. 실제 이득을 얻으려면 부록 전체가 아니라 참조된 section/range만 잘라 연결해야 한다.

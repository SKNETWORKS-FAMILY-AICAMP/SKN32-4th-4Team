## 1. 한눈에 보기

이번 작업으로 “약관을 찾는 단계 → 규칙으로 판단하는 단계 → AI가 쉬운 말로 설명하는
단계 → 인용문을 다시 검사하는 단계”가 하나의 안전한 흐름으로 연결됐다.

쉽게 비유하면 다음과 같다.

1. **AI 1은 서류 담당자**처럼 고객에게 해당하는 약관 조항만 모은다.
2. **AI 2의 규칙 코드는 심사표**처럼 모은 근거로 판정을 만든다.
3. **LLM은 안내문 작성자**처럼 이미 정해진 판정을 쉬운 말로 바꿀 뿐이다.
4. **인용 검증기는 최종 교정자**처럼 안내문의 문구가 실제 약관에 있는지 다시 확인한다.

LLM이 판정을 바꾸거나 없는 문장을 인용하면 결과를 내보내지 않고 전문가 확인으로
돌린다. 근거가 없는 경우도 “아마 보장될 것”이라고 추측하지 않는다.

### 2.1 AI 1 검색 안전장치

- 문서 상태가 `ok`가 아니면 검색 자체를 중단한다.
- 조항도 인용 가능 표시, 파싱 상태, 문서 SHA가 모두 맞아야 쓴다.
- 의미검색 결과를 곧바로 믿지 않고 조항 저장소의 원문으로 다시 찾아 대조한다.
- 낱말검색과 의미검색은 RRF 방식으로 합치되 같은 조항을 중복 가점하지 않는다.
- “제3조를 따른다” 같은 연결 조항은 최대 3단계까지만 따라간다.
- 같은 번호의 조항이 여러 개면 하나를 임의로 고르지 않고 모호함으로 남긴다.

### 2.2 AI 2 판정과 설명 안전장치

- 약관에 질병 코드와 보장 문구가 같은 문장에 명시된 경우에만
  `likely_covered`를 허용한다.
- 면책 근거는 `unlikely`, 예외나 추가 서류 조건은 `needs_documents`, 근거가 없거나
  서로 충돌하면 `needs_expert`로 처리한다.
- LLM은 규칙 판정 뒤에만 호출된다. LLM 출력이 판정을 바꾸면 폐기한다.
- LLM이 쓴 인용 손잡이와 문구가 실제 선택 조항에 있는지 다시 확인한다.
- 모델 장애나 잘못된 출력 형식을 평범한 안내문으로 숨기지 않고 오류로 올린다.

처음에는 JSON 문법만 보장하는 모드 때문에 실제 20건 모두 계약 형식에서 탈락했다.
OpenAI 공식 Structured Outputs 방식의 `json_schema`와 `strict=true`로 바꾼 뒤 해결했다.
상세 원인은 `docs/reports/debugs/2026-08-25_1142_gpt4o-mini_JSON모드_20건_스키마전패.md`에
기록했다.

### 2.3 자기부담금과 장해지급률

자기부담금은 범용 표 모양을 억지로 복원하지 않고, 사람이 승인한 사실을 다음 조건축으로
찾는다.

- 어느 약관 판본인지
- 가입 유형이 무엇인지
- 입원·통원 등 의료서비스가 무엇인지
- 의료기관과 급여 구분이 무엇인지
- 고정 금액과 비율 중 어떤 공식인지

조건이 여러 공식에 걸리면 계산하지 않는다. 현재 승인 원장에 있는 850개 사실은 파일
해시와 문서 원장을 함께 확인한 뒤 사용할 수 있다.

장해지급률은 8,586개 후보와 26개 문서 패턴까지 추출됐지만 아직 사람이 원문을 보고
승인하지 않았다. 따라서 서비스와 인용에서 계속 차단한다. 이것은 구현 누락이 아니라
잘못된 지급률을 자동 승인하지 않기 위한 의도적인 안전 경계다.

승인 뒤 사용할 기술 경로는 미리 구현했다. 문구를 비슷하다고 추측하지 않고 정확히
일치시킨다. 같은 문구에 서로 다른 승인 지급률이 있으면 하나를 고르지 않는다. 후보 상태,
서비스 불가 또는 인용 불가 표시가 하나라도 있으면 반환하지 않는다. 지급률만으로 실제
보험금을 계산할 수는 없으므로 가입금액·한도 규칙이 없는 현재는 지급액 계산을 만들지
않았다.

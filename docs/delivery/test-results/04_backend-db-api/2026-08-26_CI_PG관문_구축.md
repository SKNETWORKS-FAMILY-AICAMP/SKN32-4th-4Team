# CI PostgreSQL 관문 구축 보고서

작성일: 2026-08-26

## 1. 변경 범위

- `.github/workflows/ci.yml`의 기존 `test` 잡은 그대로 두고 `postgres-schema-gate` 잡을 추가하도록 설계했다.
- 테스트 코드와 PostgreSQL 구현·마이그레이션은 수정하지 않았다.
- 로컬 PostgreSQL에는 접속하거나 변경을 가하지 않았다.
- 작업공간 쓰기 권한 오류로 실제 파일에는 반영하지 못했다.

## 2. 변경 전 현황

`.github/workflows/`에는 `ci.yml` 한 파일만 있다. 기존 `test` 잡은 다음 두 pytest 명령을 실행한다.

```text
pytest -q -m "not llm and not ml and not mcp and not pg and not legacy_data and not delivery"
pytest -q tests/delivery -m delivery
```

따라서 PostgreSQL service가 없고, 첫 명령은 `not pg`로 PG 시험을 전부 제외한다. 두 번째 명령은 전달 계층 전용 시험만 실행한다.

`pytest.mark.pg`가 붙은 테스트 함수는 총 **41개**다. 모듈 수준 `pytestmark = pytest.mark.pg`도 포함해 Python AST로 세었다. 해당 함수들에는 매개변수화가 없다.

| 파일 | PG 시험 수 |
|---|---:|
| `tests/test_clause_index.py` | 8 |
| `tests/test_clause_store_parity.py` | 4 |
| `tests/test_erd_matches_db.py` | 2 |
| `tests/test_occurrence_ordinal.py` | 3 |
| `tests/test_pg_agent_access.py` | 4 |
| `tests/test_pg_clause_store.py` | 4 |
| `tests/test_pg_demo_store.py` | 4 |
| `tests/test_pg_insurance_repository_integration.py` | 11 |
| `tests/test_pgvector.py` | 1 |
| **합계** | **41** |

로컬 DB를 건드리지 말라는 조건 때문에 실제
`pytest --collect-only -m pg`는 실행하지 않았다. 41개는 import 없이
소스를 읽어 센 정적 수치다.

## 3. 새 관문 설계

`postgres-schema-gate` 잡은 다음 순서로 실행한다.

1. `pgvector/pgvector:pg16` service를 `insurance_pytest` 빈 DB로 시작한다.
2. 운영에서 마이그레이션 밖에서 준비하는 `insurance_runtime` role을 CI fixture로 만든다.
3. `python -m scripts.db.apply --track core`를 실행한다.
4. 읽기 전용 질의로 `vector`·`pg_trgm`, `vec`의 세 테이블, 두 RESTRICT FK, `index_generation` 기본값 제거를 확인한다.
5. 아래 10개 PG 시험을 실행하고 JUnit XML에서 collected/passed/skipped/failed/error 수를 GitHub step summary에 기록한다.
6. 수집 0건, skip 과반, pytest 실패 중 하나라도 발생하면 잡을 실패시킨다.

CI의 `PGVECTOR_DSN`은 같은 DB의 `vec,public` search path를 명시한다.
이 설정으로 무수정 SQL이 새 `vec` 스키마를 실제로 사용하게 한다.

## 4. 고른 시험과 근거

관문 명령은 다음과 같다.

```text
pytest -q -ra -m pg tests/test_erd_matches_db.py tests/test_clause_index.py
```

수집 대상은 총 10개다.

- `tests/test_erd_matches_db.py`의 2개는 문서에 선언된 FK와 실제 `pg_constraint`, `ON DELETE RESTRICT`, `index_generation` 기본값과 세대 설명을 대조한다. 문서와 실제 DDL이 갈라지면 직접 실패하는 검사다.
- `tests/test_clause_index.py`의 PG 8개는 조항 본문·청크·발생 테이블에 실제 쓰기, 검색, 삭제를 수행하고 FK, 자식→부모 정리 순서, 고아 방지, 불완전 적재 정리와 롤백 경로를 검사한다. `search_path=vec,public` 아래에서 실행되므로 DSN 전환이나 스키마 이름이 어긋나면 실패한다.

`test_clause_index.py` 일부가 `ensure_schema()`를 호출해 스키마를 보정할 수 있으므로 시험 앞에 별도의 cutover contract 검사를 둔다. 이 검사는 세 테이블이 `vec`에만 존재하는지와 FK namespace 및 참조 대상까지 직접 확인한다.

## 5. 빈 DB와 skip 가시성

CI DB에는 마이그레이션 이외의 업무 데이터가 없다. 데이터 의존 시험이 skip되는 것은 허용하지만 숨기지 않는다.

최종 단계가 JUnit XML을 읽어 수집·통과·skip·실패·error 수와 pytest 종료 코드를 `$GITHUB_STEP_SUMMARY`에 표로 남긴다.

수집 0건은 무조건 실패한다. 또한 skip이 수집 수의 과반이면 초록불을 허용하지 않는다. PostgreSQL 연결 자체가 실패해 `_conn_or_skip()`가 관문 대부분을 건너뛰는 경우도 이 규칙에 걸린다.

## 6. 실행 여부와 현재 알려진 결과

**GitHub Actions 워크플로는 실제로 돌려 보지 못했다.**

현재 환경에서는 GitHub hosted runner와 service container를 기동할 수 없다. 로컬 PostgreSQL도 의뢰 조건에 따라 사용하지 않았다.

정적 검토에서 `tests/test_erd_matches_db.py`의 첫 시험은 아직 다음 조건으로 `public` namespace를 조회한다.

```sql
connamespace='public'::regnamespace
```

반면 core 마이그레이션 017은 FK와 테이블을 `vec`에 만든다. 따라서 현재 소스 그대로라면 새 관문은 이 불일치를 실제 실패로 드러낼 가능성이 높다. 통과할 것이라고 주장하지 않는다.

## 7. 남은 한계

- GitHub Actions에서 이미지 pull, service health check, 의존성 설치, 마이그레이션, pytest를 끝까지 실행한 결과는 아직 없다.
- PG 시험 41개 전체가 아니라 schema cutover와 직접 관련된 10개만 관문으로 삼았다. demo, agent, 보험 원장 repository 동작은 이번 관문의 목적과 별개라 제외했다.
- `insurance_runtime`은 운영에서 외부 provisioning 대상이다. 깨끗한 CI DB에서는 017/018의 GRANT 대상이 필요하므로 NOLOGIN role만 fixture로 만든다. 실제 로그인, 비밀번호, 운영 권한 배포는 검증하지 않는다.
- 현재 ERD 시험과 문서가 `public`을 전제로 하는 불일치는 별도 수정이 필요하다. 이번 의뢰의 파일 범위상 테스트 본문과 문서는 고치지 않았다.
- 작업공간 쓰기 권한이 복구된 뒤 위 워크플로와 보고서를 실제 파일로 반영해야 한다.
```

파일을 쓰지 못했습니다. 작업공간 전체가 `Access denied` 상태였고, 임시 probe 파일 작성도 실패했습니다. 기존 `.github/workflows/ci.yml`의 변경분은 작업 전부터 존재하던 사용자 변경이며 제가 만든 변경은 0건입니다. 로컬 DB와 커밋도 건드리지 않았습니다.

확인 결과:

- PG 마커 시험: 41개
- 기존 워크플로: `.github/workflows/ci.yml` 1개
- 기존 CI: `not pg`로 PG 시험 전부 제외
- GitHub Actions/service container: 실행하지 못함
- 알려진 관문 실패: `test_erd_matches_db.py`가 아직 `public` namespace를 검사하지만 마이그레이션은 `vec`에 FK를 생성함

적용하려던 워크플로 변경은 기존 `jobs.test` 뒤에 다음 `postgres-schema-gate` 잡을 추가하는 것입니다.

```yaml
postgres-schema-gate:
  runs-on: ubuntu-latest
  timeout-minutes: 30
  services:
    postgres:
      image: pgvector/pgvector:pg16
      env:
        POSTGRES_USER: postgres
        POSTGRES_PASSWORD: <TEST_PASSWORD>
        POSTGRES_DB: insurance_pytest
      ports:
        - 5433:5432
      options: >-
        --health-cmd "pg_isready -U postgres -d insurance_pytest"
        --health-interval 5s
        --health-timeout 5s
        --health-retries 12

  env:
    PG_DSN: host=127.0.0.1 port=5433 user=postgres password=<TEST_PASSWORD> dbname=insurance_pytest
    PGPASSWORD: <TEST_PASSWORD>
    PGVECTOR_DSN: host=127.0.0.1 port=5433 user=postgres password=<TEST_PASSWORD> dbname=insurance_pytest options=-csearch_path=vec,public

  steps:
    - uses: actions/checkout@v4

    - uses: actions/setup-python@v5
      with:
        python-version: "3.12"
        cache: pip
        cache-dependency-path: |
          requirements.txt
          requirements/*.txt

    - name: Install dependencies
      run: |
        python -m pip install --upgrade pip
        pip install -r requirements.txt

    # 운영 로그인 role은 마이그레이션 밖에서 만드는 전제다.
    - name: Bootstrap external database role
      run: |
        python - <<'PY'
        import os
        import psycopg

        with psycopg.connect(os.environ["PG_DSN"], autocommit=True) as conn:
            conn.execute(
                "DO $$ BEGIN "
                "IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname='insurance_runtime') THEN "
                "CREATE ROLE insurance_runtime NOLOGIN; "
                "END IF; END $$"
            )
        PY

    - name: Apply core migrations
      run: python -m scripts.db.apply --track core

    - name: Verify PostgreSQL cutover contract
      run: |
        python - <<'PY'
        import os
        import psycopg

        expected_tables = {
            "policy_clause_content",
            "policy_clause_chunk",
            "policy_clause_occurrence",
        }
        expected_fks = {
            "policy_clause_chunk_content_fk",
            "policy_clause_occurrence_content_fk",
        }

        with psycopg.connect(os.environ["PG_DSN"]) as conn, conn.cursor() as cur:
            cur.execute(
                "SELECT extname FROM pg_extension "
                "WHERE extname IN ('vector', 'pg_trgm')"
            )
            extensions = {row[0] for row in cur.fetchall()}
            assert extensions == {"vector", "pg_trgm"}, extensions

            cur.execute(
                "SELECT table_schema, table_name "
                "FROM information_schema.tables "
                "WHERE table_name = ANY(%s)",
                (list(expected_tables),),
            )
            locations = set(cur.fetchall())
            assert locations == {
                ("vec", name) for name in expected_tables
            }, locations

            cur.execute(
                "SELECT conname, confdeltype, "
                "connamespace::regnamespace::text, "
                "confrelid::regclass::text "
                "FROM pg_constraint WHERE conname = ANY(%s)",
                (list(expected_fks),),
            )
            constraints = {row[0]: row[1:] for row in cur.fetchall()}
            assert set(constraints) == expected_fks, constraints
            assert all(
                delete_type == "r"
                and namespace == "vec"
                and target == "vec.policy_clause_content"
                for delete_type, namespace, target in constraints.values()
            ), constraints

            cur.execute(
                "SELECT column_default "
                "FROM information_schema.columns "
                "WHERE table_schema='vec' "
                "AND table_name='policy_clause_occurrence' "
                "AND column_name='index_generation'"
            )
            assert cur.fetchone() == (None,)
        PY

    - name: Run PostgreSQL schema gate tests
      id: pg-tests
      shell: bash
      run: |
        set +e
        pytest -q -ra -m pg \
          tests/test_erd_matches_db.py \
          tests/test_clause_index.py \
          --junitxml=postgres-schema-gate.xml
        status=$?
        echo "exit_code=$status" >> "$GITHUB_OUTPUT"
        exit 0

    - name: Publish counts and enforce a truthful result
      if: always()
      env:
        PYTEST_EXIT_CODE: ${{ steps.pg-tests.outputs.exit_code }}
      run: |
        python - <<'PY'
        import os
        import pathlib
        import xml.etree.ElementTree as ET

        report = pathlib.Path("postgres-schema-gate.xml")
        collected = skipped = failures = errors = 0

        if report.exists():
            root = ET.parse(report).getroot()
            cases = root.findall(".//testcase")
            collected = len(cases)
            skipped = sum(
                case.find("skipped") is not None for case in cases
            )
            failures = sum(
                case.find("failure") is not None for case in cases
            )
            errors = sum(
                case.find("error") is not None for case in cases
            )

        passed = collected - skipped - failures - errors
        exit_code = int(os.environ.get("PYTEST_EXIT_CODE") or 5)

        lines = [
            "## PostgreSQL schema gate",
            "",
            "| collected | passed | skipped | failed | errors | pytest exit |",
            "|---:|---:|---:|---:|---:|---:|",
            (
                f"| {collected} | {passed} | {skipped} | "
                f"{failures} | {errors} | {exit_code} |"
            ),
        ]

        summary = os.environ.get("GITHUB_STEP_SUMMARY")
        if summary:
            with open(summary, "a", encoding="utf-8") as fh:
                fh.write("\n".join(lines) + "\n")
        print("\n".join(lines))

        if collected == 0:
            raise SystemExit("PostgreSQL gate collected zero tests")
        if skipped * 2 > collected:
            raise SystemExit(
                f"PostgreSQL gate skipped a majority: "
                f"{skipped}/{collected}"
            )
        if exit_code != 0 or failures or errors:
            raise SystemExit("PostgreSQL gate tests failed")
        PY
```

CI DB에는 마이그레이션 이외의 업무 데이터가 없다. 데이터 의존 시험이 skip되는 것은 허용하지만 숨기지 않는다.

최종 단계가 JUnit XML을 읽어 수집·통과·skip·실패·error 수와 pytest 종료 코드를 `$GITHUB_STEP_SUMMARY`에 표로 남긴다.

수집 0건은 무조건 실패한다. 또한 skip이 수집 수의 과반이면 초록불을 허용하지 않는다. PostgreSQL 연결 자체가 실패해 `_conn_or_skip()`가 관문 대부분을 건너뛰는 경우도 이 규칙에 걸린다.

## 6. 실행 여부와 현재 알려진 결과

**GitHub Actions 워크플로는 실제로 돌려 보지 못했다.**

현재 환경에서는 GitHub hosted runner와 service container를 기동할 수 없다. 로컬 PostgreSQL도 의뢰 조건에 따라 사용하지 않았다.

정적 검토에서 `tests/test_erd_matches_db.py`의 첫 시험은 아직 다음 조건으로 `public` namespace를 조회한다.

```sql
connamespace='public'::regnamespace
```

반면 core 마이그레이션 017은 FK와 테이블을 `vec`에 만든다. 따라서 현재 소스 그대로라면 새 관문은 이 불일치를 실제 실패로 드러낼 가능성이 높다. 통과할 것이라고 주장하지 않는다.

## 7. 남은 한계

- GitHub Actions에서 이미지 pull, service health check, 의존성 설치, 마이그레이션, pytest를 끝까지 실행한 결과는 아직 없다.
- PG 시험 41개 전체가 아니라 schema cutover와 직접 관련된 10개만 관문으로 삼았다. demo, agent, 보험 원장 repository 동작은 이번 관문의 목적과 별개라 제외했다.
- `insurance_runtime`은 운영에서 외부 provisioning 대상이다. 깨끗한 CI DB에서는 017/018의 GRANT 대상이 필요하므로 NOLOGIN role만 fixture로 만든다. 실제 로그인, 비밀번호, 운영 권한 배포는 검증하지 않는다.
- 현재 ERD 시험과 문서가 `public`을 전제로 하는 불일치는 별도 수정이 필요하다. 이번 의뢰의 파일 범위상 테스트 본문과 문서는 고치지 않았다.
- 작업공간 쓰기 권한이 복구된 뒤 위 워크플로와 보고서를 실제 파일로 반영해야 한다.

# 판정 경로에 벡터 검색을 잇다 — 참고 조항만, 판정은 그대로

2026-08-25 · 커밋 `9468e3ff`

---

## 1. 무엇이 문제였나

`/v1/prechecks` 는 조항 벡터 **122,772조각**을 적재해 두고 **한 번도 조회하지 않았다.**
판정은 이렇게만 했다 —

1. 가입일로 적용 약관 확정
2. 그 문서의 조항을 **전량** 읽어 `kcd_ranges.scan_clause` 로 질병기호 언급을 수집
3. 요청 코드가 면책 범위 안에 드는지 대조

정확한 방법이다. 근거를 댈 수 있고 재현된다. 그런데 **면책 목록에 없는 코드**가 오면
답이 여기서 끝난다 —

> 「면책 조항에는 없습니다. 다만 보장 여부는 '보상하는 사항' 조항이 정하므로
>   이 단계에서 보장된다고 단정할 수 없습니다.」

맞는 말인데 **그 조항을 보여 주지 않았다.** 사람은 어디를 읽어야 할지 모른 채
"확인 불가"만 받는다. 벡터 색인이 바로 그 자리에 쓸 수 있는 물건인데 놀고 있었다.

---

## 2. 어떻게 이었나 — 그리고 **잇지 않은 것**

### 2-1. 판정을 바꾸지 않는다

이 변경의 전부가 이 한 줄이다. **유사도는 근거가 아니다.**

| | `citations` | `related_clauses` |
|---|---|---|
| 무엇 | 질병기호가 **실제로 적힌** 조항 | 의미검색이 「읽어 볼 만하다」고 고른 조항 |
| 어떻게 찾나 | 정규식 범위 대조(결정적) | 벡터 거리(확률적) |
| 판정을 바꾸나 | **예** | **아니오** |
| 급 | `policy_clause` | `retrieved_clause` |

한 목록에 합치면 화면이 둘을 **같은 무게로** 그린다. CLAUDE.md §0 이 금지하는 바로 그것이다.

코드에서도 순서로 못 박았다 — 참고 조항은 판정이 **끝난 뒤** 붙고, 그 함수는
`verdict`·`reason_code`·`per_code`·`all_cites` 를 **읽지도 쓰지도 않는다.**

### 2-2. 포트를 나눴다

```
ClauseSourcePort.load_clauses  → 판정 재료   (여기서 나온 것만 citations 가 된다)
RelatedClausePort.find         → 참고 자료   (related_clauses 로만 나간다)
```

하나로 합치면 조립 지점이 실수로 벡터 검색을 판정 재료로 꽂을 수 있다. **타입으로 막았다.**

### 2-3. 범위를 약관 한 벌로 가둔다

`find(sha256, ...)` — 전역 검색이 없다. 빈 `sha256` 을 주면 `ValueError` 다.
2019년 가입자에게 2024년 조항이 붙으면 **참고라도 틀린 참고**다.

### 2-4. 실패를 빈 목록으로 숨기지 않는다

`related_search` 필드가 세 상태를 가른다 —

| 값 | 뜻 |
|---|---|
| `""` | 스위치가 꺼져 있다 (검색을 안 했다) |
| `"ok"` | 검색했다 (결과가 0건일 수도 있다 = 관련 조항 없음) |
| `"failed: OSError: ..."` | 검색이 **실패**했다 |

셋을 뭉개면 화면이 「관련 조항 없음」이라고 읽는다. 전혀 다른 말이다.
실패 시엔 경고도 함께 나간다 — 「판정 자체는 약관 조항 대조로 이뤄졌으며 영향받지 않았습니다」.

### 2-5. 근거가 이미 있으면 안 붙인다

면책(`excluded`)·예외(`exception`)로 끝난 판정은 근거 조항을 실제로 짚었다.
거기까지 벡터 결과를 얹으면 **근거 있는 답에 근거 아닌 것이 섞인다.** 안 부른다.

### 2-6. 기본은 꺼짐

`PRECHECK_RELATED_SEARCH_ENABLED=false`.
판정 한 건마다 임베딩 1회 + 벡터 조회 1회가 늘고, **이 참고 조항이 실제로 도움이 되는지
아직 실측하지 않았다.** 켤 근거가 생기면 그때 켠다.

## 3. 시험이 무엇을 잰다

`tests/test_precheck_related.py` 9건. 핵심은 **판정 불변** 계약이다 —

```python
def _verdict_shape(o):
    """판정 부분만 뽑는다. 이 값이 바뀌면 참고 조항이 판정에 샌 것이다."""
    return (o.verdict, o.abstained, o.reason_code, o.message,
            tuple(...per_code...), tuple(o.citations))
```

| 시험 | 잰다 |
|---|---|
| 참고조항을_붙여도_판정이_같다 | 켜고/끈 두 판정의 `_verdict_shape` 가 동일 |
| 헛것을_물어와도_판정이_같다 | 상관없는 조항을 줘도 동일 |
| 검색이_터져도_판정이_살고_그_사실이_남는다 | 예외 → 판정 동일 + `failed:` + 경고 |
| 참고조항은_근거와_섞이지_않는다 | 두 목록 `clause_id` 교집합 0 · 급 분리 |
| 자유서술이_있으면_그걸로_묻는다 | 없으면 「보상하는 사항」 고정 질의 |
| 범위를_약관_한벌로_가둔다 | `find` 가 받은 sha256 확인 |
| 근거가_이미_있으면_참고조항을_안_붙인다 | 면책 판정 시 `find` 호출 0회 |
| 기본은_꺼져있다 | `Settings()` 기본값 |
| 어댑터는_범위없는_호출을_전역으로_바꾸지_않는다 | 빈 sha256/질의 → `ValueError` |

## 4. 실제로 열어서 확인했다 (§4)

시험 통과만으로 완료라 하지 않는다. `TestClient` 로 HTTP 응답까지 흘려 봤다.

### 4-1. 스위치 꺼짐 (기본)

```
[customer] 200 verdict=needs_expert related_search='' related=0
[admin]    200 verdict=needs_expert related_search='' related=0
```

### 4-2. 스위치 켬 · 임베더 적재 실패 (로컬 디스크 부족 — 실제 상황)

```
200 verdict=needs_expert reason=no_evidence
related_search="failed: OSError: Can't load the model for 'dragonkue/snowflake-arctic-embed-l-v2.0-ko'…"
경고: 참고 조항 검색에 실패해 관련 조항을 함께 보여 주지 못했습니다.
      판정 자체는 약관 조항 대조로 이뤄졌으며 영향받지 않았습니다.
```

★**의도치 않게 실패 계약이 실물로 검증됐다.** 로컬 디스크가 1.2 GB 뿐이라
임베더(2.2 GB)를 못 받는데, **판정은 정상으로 났고**(`needs_expert`/`no_evidence`)
실패 사실이 응답에 남았다. 조용히 「관련 조항 없음」이 되지 않았다.

### 4-3. 스위치 켬 · 성공 경로 (어댑터 안쪽만 가짜)

```
임베더가 받은 질의: '무릎 반월판 파열로 관절경 수술'
200 verdict=needs_expert reason=no_evidence related_search='ok'
참고 1건 · 근거 0건
  · [retrieved_clause] 제3조 보상하는 사항 p12-13
    인용: 회사는 피보험자가 상해로 병원에 입원하여 치료를 받은 때에는 입원의료비를 …
```

조 전체 본문이 없는 후보 1건은 **빠졌다**(조각만으로는 뜻이 뒤집힌다 — 법률문은 예외가 뒤에 온다).

## 5. 남은 것

- **실측**: 참고 조항이 실제로 도움이 되는지. 이게 있어야 기본값을 켤 근거가 된다.
- **실물 pgvector 종단**: 로컬 디스크가 부족해 임베더를 못 올린다. GPU 호스트에
  역터널로 로컬 PG 를 물려 재확인해야 한다.
- **화면**: `insurance.js` 가 `related_clauses` 를 아직 안 그린다.
  ★그릴 때 **근거와 시각적으로 구분**해야 한다 — 안 그러면 여기서 한 분리가 무의미해진다.

# 준용(準用) 참조 추출기 — 완료보고

- 계기: `core.clause_reference`(준용 참조 그래프 테이블) 앞단이 막혀
  있었다 — CLAUDE.md "그래프 적재" 행. `core` 원장은 다른 세션이 이미
  채웠고(policy_clause 196,039행), 순서상 "준용 추출기 → core 적재 →
  clause_reference"인데 **추출기가 없었다.**
- 상태: **완료(V1).** 코덱스 5.6sol 표본검토 + 직접 재현·수정까지 마쳤다.
  단, **DB 적재 준비 완료는 아니다** — §4 "아직 안 고친 것" 참조.

## 1. 무엇을 했나

`scripts/extract/to_clauses.py` 에 `_extract_references()` 추가. 조 본문에서
"제N조(제목)?를/을 준용" 형태(**번호가 명시된 것만**)를 뽑아 각 조항의
`references` 필드로 싣는다. 법령 원문(`is_statute=True`)에서는 안 부른다.

**의도적으로 안 뽑는 것**(CLAUDE.md §1 "지어내지 않는다"): 장(章) 단위
("제1장의 규정을 준용"), 명칭 참조("주계약을 준용"), 범위 인용("제7조부터
제13조까지"), "…에 따라"류(준용이 아닌 다른 참조), 문서 간 참조("실손
의료보험 제2조를 준용"). `target_clause_id` 로의 실제 해소는 이 단계에서
안 한다 — 문서 컨텍스트를 가진 DB 적재 단계의 몫이다.

## 2. 코덱스 5.6sol 표본검토(실 표본 60건) — 결론 "보류", 결함 재현 4건

1. **나열형 대량 누락** — "제7조 및 제8조를 준용"에서 제8조만 뽑혔다
   (실측 다수: H07·H17·H33·H04). 아이템을 반복 매치하는 시퀀스로 고침.
2. **외부 법령 오탐**(H04) — "「특정강력범죄의 처벌에 관한 특례법」 제13조
   (판결선고)를 준용"이 `is_statute=False`로 새서 약관 자신의 제13조로
   잘못 해소될 뻔했다. 조 제목·매치 직전 인용부호("「…법」") 이중 가드 추가.
3. **가짜 자기참조**(H27) — 조 경계 오류로 "제23조가 제23조를 준용"하는
   것처럼 보이는 경우. 대상 (조번호,가지번호)가 자기 자신과 같으면 안 뽑음.
4. **【】 대괄호 미지원** — 조 머리 파서는 받는데 참조 파서는 안 받아
   판정이 어긋났다. 추가.

## 3. 자체 발견 — 코덱스 지적을 고치다가 새 정규식 버그 하나 더 찾음

외부 법령 가드(2번)를 테스트로 검증하던 중, `[「『][^」』\n]{2,40}(?:법|
법률|…)[」』]` 패턴이 **"상법"·"민법"·"형법" 같이 법령명 전체가 2자뿐인
가장 흔한 경우를 놓친다**는 걸 발견했다(2자 접두 + 별도 "법" 접미를
요구해 최소 3자가 필요해지는데 "상법"은 2자뿐 — §15 "보통약관" 접두공백
흡수 버그와 같은 종류의 실수). `{2,40}` → `{0,38}` 로 낮춰 고쳤다. 이건
코덱스가 지적한 게 아니라 이 기능 자신의 회귀 테스트를 작성하다가 걸렸다
— load-bearing 확인 절차(임시로 가드를 꺼서 테스트가 실패하는지 보는 것)
가 실제로 결함을 잡아낸 사례다.

## 4. 아직 안 고친 것(다음 세션 과제, 코덱스도 같이 지적)

- **제목이 줄바꿈으로 갈리면 그 항목만 놓친다.** 나열형 안에서 특정
  항목의 제목 괄호가 줄을 넘어가면(예: "…신변안전조\n치)") 그 항목은
  안 뽑히고 나머지는 뽑힌다 — 부분 손실이지 전체 실패는 아니다. §15/S1
  원인규명 때부터 있던 같은 종류의(중첩 괄호) 한계와 궤를 같이 한다.
- **`N.(제목)` 번호체계(특별약관) 문서의 참조 대상은 못 받는다.**
  "13.(알릴 의무 위반의 효과)를 준용"처럼 대상이 `제N조`가 아니라
  숫자점 표기인 경우.
- **범위(scope) 접두어는 보존만 하고 해소는 안 한다.** "보통약관 제2조"
  처럼 참조 앞에 다른 부(部)를 가리키는 어휘가 있으면 `target_scope_text`
  로 원문은 남기지만(예: `"보통약관"`), 실제로 그 부의 어느 조를
  가리키는지 확정하는 건 문서 컨텍스트가 있는 DB 적재 단계의 몫이다.
- **문서 간(타 상품) 참조는 아예 손 안 댔다.** "실손의료보험 제2조를
  준용"류.

## 5. 전량 실측(1,362문서, s5L 입력)

| 지표 | 코덱스 검토 전(1차) | 코덱스 지적 반영 후(최종) |
|---|---:|---:|
| `S1_aba_reentry`/`S3_embedded_header`/`S4_annex_absorption`/`gated_clause_count` | 714/1/0/1,391 | **714/1/0/1,391**(동일 — 순수 추가 필드라 원래도 회귀 없음) |
| 참조 총수 | 2,638 | **3,764**(+42.7%, 나열형 지원 효과) |
| 참조 있는 조항 수 | 2,638 | **2,126**(−512, 외부법령·자기참조 가드가 오탐 제거) |
| 제목 누락 | 3 | 3 |

참조 수는 늘고(나열형 회복) 참조-있는-조항 수는 줄었다(오탐 제거) — 둘 다
기대한 방향이다. 회귀 테스트 12개(§`_extract_references`) 신규 작성,
전부 load-bearing 확인(임시 비활성화 → 실패 확인 → 복원 → 재통과).

## 6. DB 적재 전 필요한 것(사람/다른 세션 몫)

이 리포트의 산출물(`clauses[].references`)은 **원재료**다. `core.
clause_reference` 에 실제로 넣으려면:

1. `target_article_no`(+`target_branch_no`, `+target_scope_text`)를
   **같은 문서 안의 실제 `core.policy_clause.id`** 로 해소하는 로더가
   필요하다(이 세션 범위 밖 — "DB는 다른 곳에서 작업 중"이라는 팀 방침).
2. `target_scope_text` 가 있는데(예: "보통약관") 해소 시점에 그 부를
   못 찾으면 `resolution_status='unresolved'`로 두고 `target_clause_id`
   는 `NULL` 로 남겨야 한다 — 지어내면 안 된다.
3. §4 의 한계(줄바꿈 제목·`N.(제목)` 체계·문서간 참조)로 인한 **누락**은
   "0건 확인"이 아니라 "이 V1은 그 형태를 안 본다"는 뜻이다 — 커버리지를
   과신하면 안 된다.

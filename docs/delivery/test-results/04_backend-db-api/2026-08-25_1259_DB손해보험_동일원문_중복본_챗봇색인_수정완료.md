## 1. 결론

확정 원장에는 `36787f5570ba…` 대표본 하나만 유지했다. `2660c88b05cc…`는 삭제하거나
별도 확정 약관으로 추가하지 않고, 같은 `노후실손의료비보험2301` 원문의 재출력본이라는
콘텐츠 별칭으로 기록했다.

챗봇 용어 색인과 S7 모델 데이터셋을 실제로 재생성했으며 두 산출물에서 별칭 SHA는 0건이다.
레이아웃 차이로 달라진 `content_hash`에 기대지 않고 문서 SHA 별칭을 적재 전에 적용한다.

## 4. 남은 운영 항목

- 사용자의 지시에 따라 PostgreSQL 연결·스키마 작업은 수행하지 않았다. 운영 DB에 예전
  `2660…` occurrence가 이미 있다면 코드 반영만으로 즉시 사라지지는 않는다.
- 다음 `build_clause_index` 또는 `load_precomputed` 적재 실행 시 **활성 세대**의 별칭
  occurrence를 먼저 삭제한다. 운영 담당은 실행 후 활성 세대에서 `2660…`이 0건인지 확인해야 한다.
- 과거 비활성 세대의 occurrence와 참조되지 않는 벡터는 검색에 노출되지 않지만 저장 공간에는
  남을 수 있다. 이는 DB 정리 트랙에서 다룬다.
- 전량 검증용 임시 디렉터리 `tmp/alias_verify_s7_20260825`는 도구의 삭제 정책에 막혀 남아 있다.
  Git에는 포함되지 않는 임시 산출물이며 약 374MB다.
- 실제 서비스 프로세스가 이미 실행 중이면 용어 색인 메모리 캐시를 갱신하기 위해 재시작이 필요하다.
  다만 배포본이 이전 용어 색인 파일을 가지고 있어도 새 런타임 로더가 별칭 SHA를 다시 차단한다.

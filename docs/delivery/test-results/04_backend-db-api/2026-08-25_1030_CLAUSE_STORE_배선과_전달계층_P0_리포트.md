## 2. 수행 내용

### 2.1 `CLAUSE_STORE` 배선 (결함 수정)

★**작업 중 발견**: `app/core/config.py` 가 이 세션 도중 바뀌어 있었다(mtime 09:55).
**다른 세션이 `CLAUSE_STORE: Literal["file","pg"] = "file"` 필드를 이미 추가해 둔 상태**였고,
`config/production.env.example` 에도 `CLAUSE_STORE=pg` 를 넣어 두었다.
그러나 **`app/composition.py` 는 여전히 `os.getenv` 로 읽고 있어 그 필드를 아무도 읽지 않았다.**
즉 필드만 있고 배선이 없어, `.env` 설정은 여전히 무시되는 상태였다.

| 파일 | 변경 |
|---|---|
| `app/composition.py:20`~ | `_clause_store_kind()` 가 `Settings().CLAUSE_STORE` 를 읽는다. `get_settings()`(lru_cache)를 쓰지 않는 이유를 주석에 남겼다 — 캐시를 쓰면 "환경을 바꿔도 옛 선택을 붙들고 있는" 옛 문제가 되살아난다 |
| `app/composition.py` | pydantic `ValidationError` → 프로젝트 `ConfigError` 로 변환(오류 계약 유지) |
| `app/core/config.py` | `CLAUSE_STORE`·`DELIVERY_MODE` 에 `mode="before"` 정규화 validator 추가 — 옛 `os.getenv(...).strip().lower()` 의 관용(대소문자·공백)을 **말없이 없애지 않기 위해** |
| `.env.example:47` | `# CLAUSE_STORE=pg` 노출 + 왜 예전엔 안 먹었는지 주석 |
| `config/production.env.example` | ★**중복 제거** — 다른 세션이 추가한 줄과 내가 추가한 줄이 겹쳐 `CLAUSE_STORE=pg` 가 2번 있었다. env 파일은 뒤 값이 조용히 이기므로 이것도 결함이다. 주석 있는 쪽 하나만 남겼다 |

### 2.2 작업 격리 (사용자 요청)

| 위치 | 내용 |
|---|---|
| `delivery/` | 전달 계층·벤치 코드 전용 패키지. 경계 규칙을 `__init__.py` 에 명시 |
| `delivery/bench/router.py` | `GET /_bench/noop`(async) · `/_bench/noop-sync`(sync). **기본 비활성** |
| `delivery/bench/profile.py` | 측정 조건을 **기계가 찍는다.** 부적합하면 `blocking` 에 사유 |
| `delivery/config/delivery.env.example` | 모드 전환 스위치 |
| `delivery/config/bench.env.example` | 벤치 프로필(저장소 전량 PostgreSQL 고정) |
| `tests/delivery/` | 전용 테스트 19개. 마커 `delivery` |
| `pyproject.toml` | `delivery` 마커 등록 |
| `.github/workflows/ci.yml` | 기본 회귀에서 제외 + **별도 스텝**으로 실행 |

기존 앱 코드 접점은 **3곳뿐**이다: `app/core/config.py`(설정 단일 소스),
`app/composition.py`(배선), `app/main.py`(벤치 라우터 **조건부** 마운트).

### 2.3 되돌리기 스위치

```
DELIVERY_MODE=direct        # direct=FastAPI 단독(기본) / django=전달 계층 경유
```

## 4. 미해결 — L0 기준선 측정은 **못 했다**

★**측정하지 않았다. 추정치도 적지 않는다**(`CLAUDE.md` §0).

막힌 이유는 하나다: **이 개발기에 `INSURANCE_PG_DSN` 이 없다.**
PostgreSQL 은 `127.0.0.1:5433` 에 떠 있지만(`netstat` 확인), 애플리케이션이 쓸
`insurance_runtime` 접속 정보가 설정돼 있지 않다. 그 상태로 재면
`AUTH`/`OPS`=SQLite, 코호트=파일, 조항=파일을 재게 되므로 **비교 자료가 되지 않는다.**

측정에 필요한 것:

1. `INSURANCE_PG_DSN` / `INSURANCE_ADMIN_PG_DSN` (운영/개발용 DSN)
2. `delivery/config/bench.env.example` 을 `.env` 에 반영
3. `python -m delivery.bench.profile` 종료코드 **0** 확인
4. 그 다음에야 서버 기동 → L0 측정

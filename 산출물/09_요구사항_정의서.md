## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 올바른 보험비서 — KCD 질병기호 × 실손보험 약관 사전판정 |
| 프로젝트 목적 | 사용자가 가입한 실손보험 상품·가입일과 진료비 내역서의 질병기호(KCD)를 입력하면, 해당 판본의 약관을 검색해 보장·면책 근거와 추가 확인 사항을 **약관 원문 인용과 함께** 안내하는 웹 서비스를 구축한다. 4차에서는 전달 계층을 Django로 분리하고 클라우드에 배포한다 |
| 개발 배경 | 실손보험은 세대(1~5세대)·보험사별로 약관 구조와 보장 조건이 달라 소비자가 스스로 보장 여부를 판단하기 어렵다. 진료비 내역서의 질병기호를 가입 상품의 정확한 약관 판본과 연결하는 과정이 복잡하고, 자기부담금·지급률 같은 핵심 정보는 표·부록에 있어 일반 PDF 추출로는 손실된다 |
| 필요성 | 약관 문서(비정형) + KCD 코드(정형) + 사람 승인 표 정보를 연결해 근거 중심으로 답하되, 근거가 부족하면 임의 답변 대신 "확인 불가"를 반환하는(무폴백) 시스템이 필요하다. 일반 검색·범용 챗봇은 약관 판본을 특정하지 못해 오답의 직접 원인이 된다 |
| 3차 대비 4차 범위 | 3차 보험 기능 전부 유지(3차 초기 코드베이스의 쇼핑몰 기능은 정리되어 범위 외). 추가: ① **Django 전달 계층 분리**(FR-28) ② 프론트 이관 ③ 클라우드 인프라 구축·배포(FR-29) ④ 데이터 이관(DB 4개·벡터 인덱스, FR-30) ⑤ 통합 테스트 |
| 시스템 구성 | 고객 서비스 · 관리자 서비스 · 등록 에이전트 서비스(기본 비활성) 3개 프로세스로 분리 운영. 배포 시 Django 전달 계층이 앞단에 위치 |

## 2. 대상 사용자

| 구분 | 사용자 | 이용 목적 |
|---|---|---|
| 주 사용자 | 실손보험 가입자 | 청구 전에 내 보험으로 이 진료가 보장되는지 약관 근거와 함께 확인, 어려운 약관 용어 질문 |
| 운영자 | 서비스 관리자 | 인덱스·DB 상태, 판정 모드, 증빙 검수, 지식갭·이벤트 조회, 사용자 역할 관리 |
| 기계 사용자 | 등록된 외부 에이전트(REST·MCP) | 동일 판정·용어·코호트 기능을 API 키 기반으로 호출, 실제 청구 결과 보고 |

**사용 환경**

- 클라이언트: 웹 브라우저(Chrome 기준), 별도 설치 없음. 화면은 상담·관리자·마이페이지 3종. 모바일은 열람 가능 수준(전용 반응형 설계는 범위 외)
- 서버: **자체 서버 1대**(도메인 환경)에서 웹과 PostgreSQL을 함께 돌린다(§6 참조). 고객용은 `https://jikimi.duckdns.org/`로 공개하고, **운영용 대시보드는 같은 서버에 붙어 있되 지정 IP만 접속**할 수 있다 — 프로세스·포트 분리에 더해 접근 IP까지 제한한다. AWS EC2에는 모델을 뺀 경량 환경을 따로 둔다
- 네트워크: **인터넷 연결 필수** — 답변 생성은 외부 LLM API(`gpt-4.1-nano`)를 쓴다. 임베딩·리랭커는 자체 서버에서 돈다.
- 데이터: 국내 **12개 보험사** 실손보험 약관 — 확정 원장 **1,355건**(2026-08-14 기계대조 1,246 + 08-25 사람검토 107 + 08-26 2), 승인 릴리스 `r2026-08-04-clause-s7.1-arctic-ko-ocr-approved`

## 3. 핵심 기능

| 영역 | 기능 |
|---|---|
| 회원/로그인 | 아이디·비밀번호 가입/로그인, 얼굴 2차 인증(선택 등록), USER/ADMIN 역할 |
| LLM 질의응답 | ① 보장 사전판정(규칙엔진 + 약관 근거 인용, 4단 판정 — **LLM 미사용**) ② 약관 용어 챗봇(원문 인용, 보장 질문은 판정 양식으로 안내 — 여기서만 LLM 호출) |
| 대화 이력 | 서버 측 처리 이력(`run_events`, trace ID)만 보관하며 관리자 화면에서 조회. 사용자별 이력 화면은 범위 외 |
| 검색/조회 | 지원범위 매니페스트, 상품명 검색, 약관 출현 질병코드 검색, 정의 보유 용어 조회, 조항 근거 검색(운영 전용) |
| 증빙·통계 | 실제/합성 청구 결과 제출, 검증된 코호트 통계 조회(실제 n=0 정직 표시, 합성은 DEMO 표시) |
| 관리자 | 대시보드(준비상태·이벤트·지식갭·에이전트 스트림·검수 대기열·판정 모드·시뮬레이션·사용자·PDF 보고서) |
| 외부 연동 | 등록 에이전트 REST API(scope·요청 한도), MCP 서버(툴 4 + 리소스 2) |
| 부가 | 음성 입력/출력(STT/TTS), 청구 증거 파일 업로드(감사용, 판정 미사용) |
| 4차 신규 | Django 전달 계층 분리, 클라우드 배포, 데이터 이관 |

## 4. 기능 요구사항

| ID | 기능명 | 상세 설명 | 입력 | 출력 | 예외 상황 | 우선 |
|---|---|---|---|---|---|---|
| FR-01 | 회원가입 | 아이디·비밀번호로 계정을 만들고 즉시 로그인 상태가 된다 | 아이디(3~50자), 비밀번호(4~100자) | 액세스 토큰 | 중복 아이디, 길이 위반 → 오류 메시지 | 중 |
| FR-02 | 로그인 | 비밀번호 인증. 얼굴을 등록한 계정은 얼굴 2차 인증까지 통과해야 로그인된다 | 아이디, 비밀번호, (얼굴 이미지) | 액세스 토큰 또는 2차 인증 요청 | 자격 불일치, 얼굴 미일치 시 로그인 거부(우회 경로 없음) | 중 |
| FR-03 | 권한 관리 | USER/ADMIN 역할. 관리자 기능은 관리자만 접근, 강등 즉시 반영. 정의되지 않은 역할은 거부한다 | 토큰 | 허용/거부 | 미인증 401, 권한 없음 403 | 중 |
| FR-04 | 얼굴 등록 관리 | 로그인 사용자가 얼굴을 등록·조회·해제하고, 관리자가 백엔드를 교체·벤치마크한다 | 얼굴 이미지(복수) | 등록 여부, 사용된 샷 수 | 빈 이미지, 장수 초과 | 하 |
| FR-05 | **보장 사전판정** | 보험사·가입일·질병코드로 적용 약관 판본을 찾아 보장 가능성을 4단계(`likely_covered`/`unlikely`/`needs_documents`/`needs_expert`)로 판정하고 근거 조항을 인용한다. 이진 판정은 하지 않으며 **판정에 LLM을 쓰지 않는다** | 보험사, 가입일, 질병코드(1개 이상), 상품명(선택), 사고일 | 판정, 사유 코드, 적용 약관(상품·판매기간·세대), 코드별 판정, 인용 조항(조번호·인용문·쪽·occurrence_id) | 사유 코드 **13종**으로 구분해 반환. 기권은 **HTTP 200 정상 응답**이다. 판정 원장 저장(`PRECHECK_PERSISTENCE`)은 데이터 조건 미충족으로 끈 상태로 배포한다(§7) | 상 |
| FR-06 | 적용 약관 판본 확정 | 가입일·상품·특약으로 판매기간 안의 약관 판본을 결정한다. 현행 약관을 구계약에 대입하지 않으며 확정 원장에 있는 문서만 쓴다 | FR-05와 동일 | 적용 약관 또는 후보 목록 | `no_version_at_date`·`ambiguous_product`·`ambiguous_product_line`·`product_not_matched` → 사유 코드와 후보 반환 | 상 |
| FR-07 | 인용 검증 | 답변의 인용문이 승인 릴리스의 실제 조항 원문에 있는지 `occurrence_id`(`{release_id}:{sha256}:{clause\|annex}:{ordinal}`)로 대조한다 | 판정 결과의 인용 | 검증 통과 인용만 표시 | `citation_unverified`·`ambiguous_citation` → 판정 보류. **occurrence_id가 비면 검증을 건너뛰지 않고 기권**한다 | 상 |
| FR-08 | 지원범위 안내 | 판정에 쓸 수 있는 보험사·판본·세대·판매기간을 데이터로 공개한다. 확정 건수와 분모, 확정 범위(scope)별 내역, 사람 최종승인 대기 건수를 함께 낸다 | 없음 | 보험사별 지원 범위, 확정/수집 건수, 판정 모드 | 못 셌을 때 0으로 보고하지 않고 `error`로 구분. 기계대조 모드일 때 경고 문구 필수 | 상 |
| FR-09 | 상품명 검색 | 보험사·검색어·가입일로 확정 약관의 상품명을 찾는다(입력 도우미) | 보험사, 검색어, 가입일 | 상품 목록(판본 수·판매기간·세대) | 확정 약관 없는 보험사 → 안내 문구 | 중 |
| FR-10 | 질병코드 검색 | 약관에 등장하는 질병코드·범위를 찾는다(입력 도우미). 목록에 없는 코드도 판정은 정상 처리한다 | 검색어, 장(chapter) | 코드 목록 | 인덱스 미준비 → 503 | 중 |
| FR-11 | 약관 용어 설명 | 약관 원문에서 용어 정의를 찾아 그대로 인용한다. 상식으로 메우지 않는다. 근거 코퍼스는 조항 1,621 + 부록 1,029 = **2,650 passage** | 용어, 보험사(선택) | 인용문(보험사·조번호·쪽), 찾음 여부 | 못 찾으면 "정의 없음"(정상 응답) | 중 |
| FR-12 | 용어 챗봇 | 자유 문장에서 의도를 분류해 용어 질문은 원문 인용으로 답하고, 보장 여부 질문은 답하지 않고 판정 양식으로 넘긴다. **이 경로가 이 제품에서 LLM을 호출하는 유일한 고객 기능**이다(`LLM_CHAT_ENABLED`) | 문장(≤500자), 보험사(선택) | 의도, 답변, 다음 행동, 인용, 사용 LLM 정보 | 근거 없음 → 지식갭 큐 기록 후 안내 / 프롬프트 주입 의심 입력 차단 / LLM 출력 오류 502 | 중 |
| FR-13 | 실제 청구 결과 제출 | 외부 에이전트가 실제 지급/부지급 결과를 보고한다. 판정 근거로는 쓰지 않는다(`evidence_tier=external_report`) | 보험사, 코드, 결과(`paid`/`denied`/`partial`/`pending`), 사유, 멱등키 | 접수증(`verification=unverified`) | 중복 제출은 멱등 처리 | 상 |
| FR-13a | 청구 증거 파일 업로드 | 제출에 첨부할 영수증·진단서 스캔본을 저장하고 sha256·저장 참조를 돌려준다. 내용을 파싱하거나 판정 근거로 쓰지 않는다 | 파일(허용 확장자, 크기 상한) | sha256, 저장 참조 | 허용되지 않는 형식·크기 초과 422, 같은 sha256은 재저장 없이 재사용 | 중 |
| FR-14 | 합성 사례 제출 | 시연용 합성 사례를 접수한다. 실제 데이터와 **DB 자체를 분리**한다(`insurance_demo` ↔ `insurance_real`) | FR-13 + 시뮬레이션 식별자 | 접수증 | 승격 전 집계 미반영 | 상 |
| FR-15 | 코호트 통계 조회 | 검증된 실제 사례 집계(현재 n=0, 비어 있음을 명시)와 합성 집계(DEMO 표시)를 **각각 다른 경로**(`/v1/cohorts` ↔ `/v1/demo/cohorts`)로 제공한다. 최소 표본·편향 경고 동반 | 코드, 상품, 연령대 | n, 승인/거절 수, 승인율·신뢰구간, 경고 | 실제·합성 합산 금지(합산 필드 자체가 없다) | 상 |
| **FR-15a** | **자기부담금 계산** | 사람이 승인한 자기부담금 사실(OCR facts)로 실제 부담액을 계산한다. **승인 사실이 정확히 하나로 좁혀질 때만** 계산하고 그 외에는 후보만 돌려준다 | 보험사·상품·판본 축, 대상 의료비(원) | 계산 결과 또는 후보 목록 | 사실이 여럿·0건이면 계산하지 않고 후보 반환(무폴백). | 중 |

| 데이터 제약 | 실제 지급/부지급 사례 공개 자료가 없어 실제 코호트는 n=0. 약관 원문 재배포 금지(인용만). KCD 코드→질병명 사전 미보유. 현대해상 2509 임신출산질환 특약은 공시실 오등록으로 정본 없음(미지원 확정) |
| 공개 저장소 제약 | 약관 PDF·본문 파생 JSON·벡터 DB·모델 가중치·사용자 제출 데이터는 저장소에 포함하지 않는다. 코드만으로는 판정·검색이 동작하지 않으며, 데이터 미연결 시 빈 결과를 꾸며내지 않고 미준비 오류를 낸다 |
| 팀 구성 | AI(임베딩·모델·전처리·문서검증·프롬프트), 프론트(화면 설계·Django UI), 백엔드(전달 계층·배포), 모델 검증(LLM 비교·파인튜닝) |
## 7. 요구사항 우선순위

| 등급 | 기준 | 해당 |
|---|---|---|
| **상 (Must)** | 없으면 제품·4차 요건이 성립하지 않음 | FR-05~08, 13~17, 25, **28~30, 29a** |
| **중 (Should)** | 졸업 릴리스에 필요하나 코어 아님 | FR-01~03, 09~12, 13a, **15a**, 18~21, 24, 27 |
| **하 (Could)** | 3차 기능 유지, 4차에서 개선 없음 | FR-04, 22~23, 26, **29b** |
| 범위 외 (개발 중) | 코드는 있으나 서비스에 연결되지 않음. 완성 시 별도 변경요청으로 편입 | 근거 번들 검색 · 규칙판정+LLM 설명 초안 · 근거 기반 판정 · 장해분류 지급률 조회 |

| 운영 내부 장치 (요구사항 아님) | 사용자 기능이 아니라 운영·측정용 경로. 기본 비활성 | Prometheus 지표 스크랩 `GET /metrics-scrape`(토큰 미설정 시 404) · 전달 계층 오버헤드 벤치 `GET /_bench/noop`(끄면 마운트 없음) |

## 1. 목적

4차에서 추가된 것 — Django 전달 계층, 자체 서버 배포, 데이터 이관, 외부 LLM 제공자 — 이 3차 품질을 깨뜨리지 않았고, 배포 환경에서 프론트·백엔드·LLM·DB가 한 경로로 이어짐을 확인한다.

## 2. 테스트 범위와 합격 기준

| 구분 | 범위 | 합격 기준 |
|---|---|---|
| 회귀 | 3차 기능 전체(판정·용어·증빙·코호트·관리자·에이전트·MCP) | 기본 CI 실패 0 |
| 전달 계층 | Django BFF 경유 시 응답 계약 불변, 도메인 코드 미침투 | 전달 계층 테스트 전부 통과, import 경계 위반 0 |
| 배포 스모크 | 도메인에서 준비상태 API | `ready=true`, 구성요소 전부 정상 |
| 데이터 이관 | 원장·인덱스·모드가 서버에 반영 | 매니페스트 확정 건수 = 로컬 원장 건수, 모드 `machine_match` |
| 성능 | 전달 계층 비용, 임베딩·검색 지연, LLM 응답 | 전달 계층 ≤ +10%, 임베딩·검색 p95 < 0.5초 |
| LLM 제공자 | 인용 원문 일치, 비용, 지연 | 후보 간 상대 비교로 1위 채택 |
| 통합(E2E) | 시연 6컷을 도메인에서 재현 | 각 컷 기대 화면 도달 |

**측정 원칙**: 절대값이 아니라 **구성 간 차이**를 읽는다. 부하 클라이언트가 파이썬이라 절대값은 부풀려지고, 회차가 5회라 신뢰구간을 함께 본다.

## 5. 성능 요약

```
판정 경로 한 요청의 시간 구성(서버, warm 기준 추정)
  질의 임베딩(CPU)   ~0.24 s   T-11
  조항 검색(pgvector) ~0.32 s   T-12
  규칙엔진·인용검증   < 0.05 s
  전달 계층 홉        +0.001~0.002 s   T-07
  ─────────────────────────────
  판정 전체 p50 ≈ 0.6 s  (실측: 서버 실판정 동시 1 p50 147ms · 동시 8 p95 945ms — 목표 p95 1.5초 안)

용어 챗봇 = 위 + LLM 1.9 s(T-13) ≈ 2.5 s  (목표 p95 8초 안)
```

성능 결정 두 가지가 실측으로 확정됐다. ① Django 전달 계층은 판정 비용의 3~9%라 **성능이 채택 근거가 되지 못하고**, 세션·CSRF·보안 헤더·Admin 같은 얻는 것으로 판단한다. ② 성능을 논하려면 전달 계층이 아니라 **커넥션 풀**(23배)을 봐야 한다.
